## 语法概要 {#synopsis}

```sql
[ WITH [ RECURSIVE ] <with_query> [, ...] ]
INSERT INTO <table_name> [ AS <alias> ] [( <column_name> [, ...] )]
   [ OVERRIDING { SYSTEM | USER } VALUE ]
   {DEFAULT VALUES | VALUES ( {<expression> | DEFAULT} [, ...] ) [, ...] | <query>}
   [ ON CONFLICT [ <conflict_target> ] <conflict_action> ]
   [RETURNING * | <output_expression> [ [AS] <output_name> ] [, ...]]

-- where <conflict_target> can be one of:

    ( { <index_column_name> | ( <index_expression> ) } [ COLLATE <collation> ] [ <opclass> ] [, ...] )
    [ WHERE <index_predicate> ]
    ON CONSTRAINT <constraint_name>

-- and <conflict_action> is one of:

    DO NOTHING
    DO UPDATE SET { <column_name> = { <expression> | DEFAULT } |
                    ( <column_name> [, ...] ) = [ ROW ] ( { <expression> | DEFAULT } [, ...] ) |
                    ( <column_name> [, ...] ) = ( sub-SELECT )
                  } [, ...]
              [ WHERE <condition> ]
```

## 说明 {#description}

`INSERT` 向表中插入新行。可以插入由值表达式指定的一行或多行，也可以插入查询结果中的零行或多行。

目标列名可以按任意顺序列出。如果完全没有提供列名列表，则默认按表定义时的顺序使用各列；如果 `VALUES` 子句或查询只提供 *N* 列，则使用前 *N* 个列名。`VALUES` 子句或查询提供的值从左到右与显式或隐式列列表对应。

显式或隐式列列表中未出现的每一列都会填入默认值：如果声明了默认值，就使用该值，否则使用空值。

如果某列的表达式数据类型不正确，Apache Cloudberry 会尝试自动转换类型。

向没有唯一索引的表执行 `INSERT` 不会被并发活动阻塞。对于有唯一索引的表，如果并发会话锁定或修改了与待插入唯一索引值匹配的行，则可能发生阻塞；详情请参阅 PostgreSQL 文档中的[索引唯一性检查](https://www.postgresql.org/docs/12/index-unique-checks.html)。`ON CONFLICT` 可以指定替代操作，以免抛出违反唯一约束或排他约束的错误。（请参阅下文的 [ON CONFLICT 子句](#on-conflict-clause)。）

可选的 `RETURNING` 子句使 `INSERT` 根据每个实际插入的行（如果使用了 `ON CONFLICT DO UPDATE` 子句，也包括更新的行）计算并返回值。这主要用于获取默认值提供的值，例如序列生成的序号，但也允许使用表中列构成的任意表达式。`RETURNING` 列表的语法与 `SELECT` 输出列表相同。只有成功插入或更新的行才会返回。例如，如果某行因不满足 `ON CONFLICT DO UPDATE ... WHERE` 子句的条件而被锁定但未更新，就不会返回该行。

必须对表具有 `INSERT` 权限才能插入数据。如果存在 `ON CONFLICT DO UPDATE`，还需要对表具有 `UPDATE` 权限。

指定列列表时，只需对所列列具有 `INSERT` 权限。同样，指定 `ON CONFLICT DO UPDATE` 时，只需对列出要更新的列具有 `UPDATE` 权限。不过，`ON CONFLICT DO UPDATE` 还要求对其 `ON CONFLICT DO UPDATE` 表达式或条件中读取值的任何列具有 `SELECT` 权限。

使用 `RETURNING` 子句要求对 `RETURNING` 中提到的所有列具有 `SELECT` 权限。如果使用 query 子句插入查询得到的行，则必须对查询引用的任何表或列具有 `SELECT` 权限。

## 参数 {#parameters}

### 插入 {#inserting}

本节介绍仅插入新行时可用的参数。仅用于 `ON CONFLICT` 子句的参数另行说明。

**`with_query`**

`WITH` 子句允许指定一个或多个子查询，并在 `INSERT` 查询中按名称引用它们。

查询（`SELECT` 语句）本身也可以包含 `WITH` 子句。此时，两组 with_query 都可以在 `INSERT` 查询中引用，但第二组嵌套得更深，因此优先。

**`table_name`**

已有表的名称（可用模式限定）。

**`alias`**

table_name 的替代名称。提供别名后，实际表名会被完全隐藏。`ON CONFLICT DO UPDATE` 的目标表名为 `excluded` 时，这尤其有用，否则该名称会被解释为表示待插入行的特殊表名。

**`column_name`**

table_name 所指定表中的列名。必要时可以用子字段名或数组下标限定列名。（仅向复合列的部分字段插入值时，其他字段会设为空值。）通过 `ON CONFLICT DO UPDATE` 引用列时，不要在目标列中包含表名。例如，`INSERT INTO table_name ... ON CONFLICT DO UPDATE SET table_name.col = 1` 是无效的（这遵循 `UPDATE` 的一般行为）。

**`OVERRIDING SYSTEM VALUE`**

没有此子句时，为定义为 `GENERATED ALWAYS` 的标识列指定显式值（`DEFAULT` 除外）会报错。此子句覆盖该限制。

**`OVERRIDING USER VALUE`**

指定此子句时，会忽略为定义为 `GENERATED BY DEFAULT` 的标识列提供的任何值，改用默认的序列生成值。

例如，在表之间复制值时，此子句很有用。`INSERT INTO tbl2 OVERRIDING USER VALUE SELECT * FROM tbl1` 会从 `tbl1` 复制所有在 `tbl2` 中不是标识列的列，而 `tbl2` 中标识列的值由与 `tbl2` 关联的序列生成。

**`DEFAULT VALUES`**

所有列都填入各自的默认值。（此形式不允许使用 `OVERRIDING` 子句。）

**`expression`**

要赋给对应列的表达式或值。

**`DEFAULT`**

对应列将填入其默认值。

**`query`**

提供待插入行的查询（`SELECT` 语句）。语法说明请参阅 [SELECT](/cloudberry/reference/sql-stmts/select/)。

**`output_expression`**

`INSERT` 命令在插入或更新每一行后要计算并返回的表达式。表达式可以使用 table_name 所指定表中的任何列名。使用 `*` 可返回所插入行的所有列。

**`output_name`**

返回列所使用的名称。

要向分区表插入数据，应指定根分区表，即使用 `CREATE TABLE` 命令创建的表。也可以在 `INSERT` 命令中指定叶子分区。如果数据不符合指定叶子分区的要求，就会报错。不支持在 `INSERT` 命令中指定不是叶子分区的子表。也不支持对分区表的任何子表执行 `UPDATE`、`DELETE` 等其他 DML 命令；这些命令必须对根分区表，即使用 `CREATE TABLE` 命令创建的表执行。

对于分区表，未启用全局死锁检测器时（默认情况），`INSERT` 操作会锁定所有子表。启用全局死锁检测器后，只会锁定部分叶子分区。

## ON CONFLICT 子句 {#on-conflict-clause}

可选的 `ON CONFLICT` 子句指定替代操作，以免抛出违反唯一约束或排他约束的错误。对于每个待插入行，要么正常插入，要么在违反 conflict_target 指定的仲裁约束或索引时，执行替代的 conflict_action。`ON CONFLICT DO NOTHING` 的替代操作就是不插入该行。`ON CONFLICT DO UPDATE` 的替代操作则是更新与待插入行冲突的现有行。

conflict_target 可以执行唯一索引推断。执行推断时，它由一个或多个 index_column_name 列和/或 index_expression 表达式，以及可选的 index_predicate 组成。table_name 上所有恰好包含 conflict_target 所指定列/表达式（不考虑顺序）的唯一索引，都会被推断（选中）为仲裁索引。如果指定了 index_predicate，它还必须满足仲裁索引的要求，才能完成推断。注意，这意味着如果存在满足其他所有条件的非部分唯一索引（没有谓词的唯一索引），该索引也会被推断出来（从而被 `ON CONFLICT` 使用）。如果推断失败，Apache Cloudberry 会报错。

`ON CONFLICT DO UPDATE` 保证得到原子的 `INSERT` 或 `UPDATE` 结果；只要没有其他独立错误，即使在高并发情况下，也保证出现这两种结果之一。这也称为 *UPSERT*，即 `UPDATE` 或 `INSERT`。

**`conflict_target`**

通过选择仲裁索引，指定 `ON CONFLICT` 对哪些冲突采取替代操作。可以执行唯一索引推断，也可以显式指定约束名。对于 `ON CONFLICT DO NOTHING`，conflict_target 是可选的；省略时，会处理与所有可用约束（及唯一索引）的冲突。对于 `ON CONFLICT DO UPDATE`，必须提供 conflict_target。

**`conflict_action`**

conflict_action 指定 `ON CONFLICT` 的替代操作。它可以是 `DO NOTHING`，或是指定冲突时具体 `UPDATE` 操作的 `DO UPDATE` 子句。`ON CONFLICT DO UPDATE` 中的 `SET` 和 `WHERE` 子句可通过表名（或别名）访问现有行，通过特殊的 excluded 表访问待插入行。读取 excluded 中的列时，需要对目标表中的对应列具有 `SELECT` 权限。

注意，所有行级 `BEFORE INSERT` 触发器的影响都会反映在 excluded 值中，因为这些影响可能正是该行无法插入的原因之一。

**`index_column_name`**

table_name 中的列名，用于推断仲裁索引。遵循 `CREATE INDEX` 格式。需要对 index_column_name 具有 `SELECT` 权限。

**`index_expression`**

类似于 index_column_name，但用于推断索引定义中基于 table_name 列的表达式，而非简单列。遵循 `CREATE INDEX` 格式。需要对 index_expression 中出现的任何列具有 `SELECT` 权限。

**`collation`**

指定后，要求对应的 index_column_name 或 index_expression 使用特定排序规则，才能在推断时匹配。通常省略此项，因为排序规则一般不影响是否发生约束违反。遵循 `CREATE INDEX` 格式。

**`opclass`**

指定后，要求对应的 index_column_name 或 index_expression 使用特定操作符类，才能在推断时匹配。通常省略此项，因为同一类型各操作符类的相等语义往往相同，或者只需信任已定义的唯一索引采用了适当的相等定义即可。遵循 `CREATE INDEX` 格式。

**`index_predicate`**

用于支持部分唯一索引的推断。任何满足该谓词的索引都可以被推断出来（它们实际上不一定是部分索引）。遵循 `CREATE INDEX` 格式。需要对 index_predicate 中出现的任何列具有 `SELECT` 权限。

**`constraint_name`**

按名称显式指定仲裁约束，而非推断约束或索引。

**`condition`**

返回 `boolean` 类型值的表达式。只有该表达式返回 `true` 的行才会被更新，但执行 `ON CONFLICT DO UPDATE` 操作时，所有相关行都会被锁定。注意，condition 最后才求值，即在已识别冲突并将其确定为更新候选之后求值。

注意，`ON CONFLICT DO UPDATE` 不支持将排他约束用作仲裁条件。在所有情况下，只支持以 `NOT DEFERRABLE` 约束和唯一索引作为仲裁条件。

带 `ON CONFLICT DO UPDATE` 子句的 `INSERT` 是“确定性”语句。这意味着不允许命令多次影响同一个现有行；发生这种情况时，会抛出基数违反错误。对于仲裁索引或约束所限制的属性，各待插入行不应相互重复。

注意，对分区表执行 `INSERT` 时，目前不支持其 `ON CONFLICT DO UPDATE` 子句更新冲突行的分区键并因此需要将该行移到新分区。

**提示：** 通常更适合使用唯一索引推断，而不是通过 `ON CONFLICT ON CONSTRAINT constraint_name` 直接指定约束名。当底层索引以新旧短暂并存的方式被另一个基本等价的索引替换时，推断仍能正常工作，例如先使用 `CREATE UNIQUE INDEX ... CONCURRENTLY`，再删除被替换的索引。

## 输出 {#outputs}

成功完成后，`INSERT` 命令返回以下形式的命令标签：

```sql
INSERT <oid> <count>
```

count 是插入或更新的行数。oid 始终为 `0`（过去，当 count 恰为 1 且目标表声明了 `WITH OIDS` 时，它是分配给插入行的 OID，否则为 0；但现在已不再支持创建带 `WITH OIDS` 的表）。

如果 `INSERT` 命令包含 `RETURNING` 子句，其结果类似于 `SELECT` 语句，包含 `RETURNING` 列表定义的列和值，并针对命令插入或更新的各行计算。

## 注意事项 {#notes}

如果指定表是分区表，Apache Cloudberry 会将每行路由到适当分区并插入。如果指定表是某个分区，而任一输入行违反该分区的约束，就会报错。

对于分区表，未启用全局死锁检测器时（默认情况），`INSERT` 操作会锁定所有子表。启用全局死锁检测器后，只会锁定部分叶子子表。

Apache Cloudberry 最多支持 127 个事务并发向同一个 AO 表执行 `INSERT`。

## 示例 {#examples}

向表 `films` 插入一行：

```sql
INSERT INTO films VALUES
    ('UA502', 'Bananas', 105, '1971-07-13', 'Comedy', '82 minutes');
```

此例省略了 `len` 列，因此该列使用默认值：

```sql
INSERT INTO films (code, title, did, date_prod, kind)
    VALUES ('T_601', 'Yojimbo', 106, '1961-06-16', 'Drama');
```

此例为 `date_prod` 列使用 `DEFAULT` 子句，而非指定值：

```sql
INSERT INTO films VALUES
    ('UA502', 'Bananas', 105, DEFAULT, 'Comedy', '82 minutes');
INSERT INTO films (code, title, did, date_prod, kind)
    VALUES ('T_601', 'Yojimbo', 106, DEFAULT, 'Drama');
```

插入完全由默认值组成的一行：

```sql
INSERT INTO films DEFAULT VALUES;
```

使用多行 `VALUES` 语法插入多行：

```sql
INSERT INTO films (code, title, did, date_prod, kind) VALUES
    ('B6717', 'Tampopo', 110, '1985-02-10', 'Comedy'),
    ('HG120', 'The Dinner Game', 140, DEFAULT, 'Comedy');
```

此例从列布局与 `films` 相同的表 `tmp_films` 中取出一些行，插入表 `films`：

```sql
INSERT INTO films SELECT * FROM tmp_films WHERE date_prod < 
'2004-05-07';
```

此例向数组列插入值：

```sql
-- Create an empty 3x3 gameboard for noughts-and-crosses
INSERT INTO tictactoe (game, board[1:3][1:3])
    VALUES (1, '{{" "," "," "},{" "," "," "},{" "," "," "}}');
-- The subscripts in the above example aren't really needed
INSERT INTO tictactoe (game, board)
    VALUES (2, '{{X," "," "},{" ",O," "},{" ",X," "}}');
```

向表 distributors 插入一行，并返回 DEFAULT 子句生成的序号：

```sql
INSERT INTO distributors (did, dname) VALUES (DEFAULT, 'XYZ Widgets')
   RETURNING did;
```

增加负责 Acme Corporation 账户的销售人员的销售计数，并将更新后的整行及当前时间记录到日志表中：

```sql
WITH upd AS (
  UPDATE employees SET sales_count = sales_count + 1 WHERE id =
    (SELECT sales_person FROM accounts WHERE name = 'Acme Corporation')
    RETURNING *
)
INSERT INTO employees_log SELECT *, current_timestamp FROM upd;
```

根据情况插入或更新新的经销商。假定已定义唯一索引来约束 `did` 列中的值。注意，特殊的 `excluded` 表用于引用原本打算插入的值：

```sql
INSERT INTO distributors (did, dname)
    VALUES (5, 'Gizmo Transglobal'), (6, 'Associated Computing, Inc')
    ON CONFLICT (did) DO UPDATE SET dname = EXCLUDED.dname;
```

插入经销商；如果存在导致待插入行被排除的现有行（即行插入前触发器执行后，受约束列与之匹配的行），则不执行操作。此例假定已定义唯一索引来约束 `did` 列中的值：

```sql
INSERT INTO distributors (did, dname) VALUES (7, 'Redline GmbH')
    ON CONFLICT (did) DO NOTHING;
```

根据情况插入或更新新的经销商。此例假定已定义唯一索引来约束 `did` 列中的值。`WHERE` 子句限制实际更新的行（不过，未更新的现有行仍会被锁定）：

```sql
-- Don't update existing distributors based in a certain ZIP code
INSERT INTO distributors AS d (did, dname) VALUES (8, 'Anvil Distribution')
    ON CONFLICT (did) DO UPDATE
    SET dname = EXCLUDED.dname || ' (formerly ' || d.dname || ')'
    WHERE d.zipcode <> '21201';

-- Name a constraint directly in the statement (uses associated
-- index to arbitrate taking the DO NOTHING action)
INSERT INTO distributors (did, dname) VALUES (9, 'Antwerp Design')
    ON CONFLICT ON CONSTRAINT distributors_pkey DO NOTHING;
```

尽可能插入新经销商，否则执行 `DO NOTHING`。此例假定已定义唯一索引，对布尔列 `is_active` 求值为 `true` 的行子集约束 `did` 列中的值：

```sql
-- This statement could infer a partial unique index on "did"
-- with a predicate of "WHERE is_active", but it could also
-- just use a regular unique constraint on "did"
INSERT INTO distributors (did, dname) VALUES (10, 'Conrad International')
    ON CONFLICT (did) WHERE is_active DO NOTHING;
```

## 兼容性 {#compatibility}

`INSERT` 符合 SQL 标准，但 `RETURNING` 子句是 Apache Cloudberry 的扩展，在 `INSERT` 中使用 `WITH` 的能力，以及通过 `ON CONFLICT` 指定替代操作的能力也是扩展。此外，标准不允许省略列名列表却只用 `VALUES` 子句或查询填充部分列的情况。

SQL 标准规定，只有存在定义为始终生成的标识列时，才能指定 `OVERRIDING SYSTEM VALUE`。Apache Cloudberry 在任何情况下都允许该子句，不适用时将其忽略。

query 子句可能存在的限制记录在 [SELECT](/cloudberry/reference/sql-stmts/select/) 中。
