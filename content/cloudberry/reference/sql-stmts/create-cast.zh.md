## 概要 {#synopsis}

```sql
CREATE CAST (<sourcetype> AS <targettype>) 
       WITH FUNCTION <funcname> (<argtype> [, ...]) 
       [AS ASSIGNMENT | AS IMPLICIT]

CREATE CAST (<sourcetype> AS <targettype>)
       WITHOUT FUNCTION 
       [AS ASSIGNMENT | AS IMPLICIT]

CREATE CAST (<sourcetype> AS <targettype>)
       WITH INOUT 
       [AS ASSIGNMENT | AS IMPLICIT]
```

## 描述 {#description}

`CREATE CAST` 定义一个新的类型转换。类型转换指定如何在两种数据类型之间执行转换。例如，

```sql
SELECT CAST(42 AS float8);
```

通过调用先前指定的函数（此例中为 `float8(int4)`）将整数常量 `42` 转换为类型 `float8`。如果没有定义合适的类型转换，转换就会失败。

两种类型可以是二进制可强制转换的，这意味着这两种类型无需调用任何函数就可以相互转换。这要求对应的值使用相同的内部表示。例如，类型 `text` 和 `varchar` 在两个方向上都是二进制可强制转换的。二进制可强制转换性不一定是对称关系。例如，在当前实现中，从 `xml` 到 `text` 的转换可以免费完成，但反方向则需要一个至少执行语法检查的函数。（两个方向上都二进制可强制转换的两种类型也称为二进制兼容。）

可以使用 `WITH INOUT` 语法将类型转换定义为 *I/O 转换式类型转换*。I/O 转换式类型转换通过调用源数据类型的输出函数，并将得到的字符串传给目标数据类型的输入函数来执行。在许多常见情形下，这一功能避免了为转换另写一个单独的转换函数。I/O 转换式类型转换的行为与基于常规函数的类型转换相同；只是实现方式不同。

默认情况下，类型转换只能通过显式的转换请求来调用，即显式的 `CAST(x AS` typename`)` 或 `x:: typename` 构造。

如果类型转换被标记为 `AS ASSIGNMENT`，则在向目标数据类型的列赋值时可以隐式调用它。例如，假设 `foo.f1` 是类型为 `text` 的列，则：

```sql
INSERT INTO foo (f1) VALUES (42);
```

在从类型 `integer` 到类型 `text` 的转换被标记为 `AS ASSIGNMENT` 时才会被允许，否则不允许。术语*赋值转换*通常用来描述这类转换。

如果类型转换被标记为 `AS IMPLICIT`，则在任何上下文中都可以隐式调用它，无论是赋值还是表达式内部。术语*隐式转换*通常用来描述这类转换。例如，考虑下面的查询：

```sql
SELECT 2 + 4.0;
```

解析器最初将这两个常量分别标记为类型 `integer` 和 `numeric`。系统目录中没有 `integer + numeric` 操作符，但有 `numeric + numeric` 操作符。如果存在从 `integer` 到 `numeric` 的类型转换（确实存在）并且被标记为 `AS IMPLICIT`（事实上确实如此），则此查询会成功。解析器只应用该隐式转换，并按照下面这样写的方式来解析该查询：

```sql
SELECT CAST ( 2 AS numeric ) + 4.0;
```

系统目录还提供了从 `numeric` 到 `integer` 的类型转换。如果该转换被标记为 `AS IMPLICIT`（实际并没有），则解析器将面临选择：是采用上述解释，还是将 `numeric` 常量转换为 `integer` 并应用 `integer + integer` 操作符。由于不知道该偏向哪个选择，解析器会放弃并宣布该查询有歧义。两种转换中只有一个是隐式的，这正是我们教会解析器优先把 `numeric` 与 `integer` 混合的表达式解析为 `numeric` 的方式；解析器本身没有关于这一点的内置知识。

在将类型转换标记为隐式时，保守一些是明智的。过多的隐式转换路径可能导致 Apache Cloudberry 对命令选择出人意料的解释，或者由于存在多种可能的解释而完全无法解析命令。一个好的通用规则是：仅对同一一般类型类别中类型之间保持信息的转换，才使其可隐式调用。例如，从 `int2` 到 `int4` 的转换可以合理地设为隐式，但从 `float8` 到 `int4` 的转换可能应该仅限赋值。跨类型类别的转换，例如 `text` 到 `int4`，最好设为仅限显式。

> **注意** 有时出于可用性或标准兼容性的原因，需要在一组类型之间提供多个隐式转换，从而造成上述做法无法避免的歧义。在这种情况下，解析器使用基于类型类别和首选类型的回退启发式规则，来帮助提供期望的行为。更多信息参见 [CREATE TYPE](/cloudberry/reference/sql-stmts/create-type/)。

要能够创建类型转换，必须拥有源数据类型或目标数据类型，并且对另一个类型具有 `USAGE` 权限。要创建二进制可强制转换的类型转换，必须是超级用户。（之所以有此限制，是因为错误的二进制可强制转换很容易使服务器崩溃。）

## 参数 {#parameters}

**`sourcetype`**

类型转换的源数据类型的名称。

**`targettype`**

类型转换的目标数据类型的名称。

**`funcname(argtype [, ...])`**

用于执行类型转换的函数。函数名可以带模式限定。如果不带模式限定，Apache Cloudberry 会在模式搜索路径中查找该函数。函数的结果数据类型必须与类型转换的目标类型相匹配。

类型转换实现函数可以有一到三个参数。第一个参数的类型必须与类型转换的源类型相同，或可从其进行二进制强制转换。第二个参数（如果有）必须是 `integer` 类型；它接收与目标类型相关联的类型修饰符，如果没有则为 `-1`。第三个参数（如果有）必须是 `boolean` 类型；如果该转换是显式转换，它接收 `true`，否则接收 `false`。SQL 规范在某些情况下要求显式转换和隐式转换具有不同的行为。提供此参数是为了供必须实现这类转换的函数使用。不建议以这种方式设计自己的数据类型。

类型转换函数的返回类型必须与类型转换的目标类型相同，或可向其进行二进制强制转换。

通常，类型转换的源数据类型和目标数据类型必须不同。但是，如果类型转换有一个接受多个参数的转换实现函数，则允许声明源类型与目标类型相同的类型转换。系统目录中用它来表示特定类型的长度强制转换函数。所指定的函数用于将该类型的值强制转换为由其第二个参数给定的类型修饰符值。

当类型转换的源类型与目标类型不同，并且有一个接受多个参数的函数时，该转换在一个步骤中既完成从一种类型到另一种类型的转换，又应用长度强制转换。当没有这样的条目可用时，向使用类型修饰符的类型进行强制转换需要两个步骤：一步在数据类型之间转换，另一步应用修饰符。

目前，向域类型或从域类型进行的类型转换没有效果。向域或从域进行转换时，使用的是与其底层类型相关联的类型转换。

**`WITHOUT FUNCTION`**

表示源类型可二进制强制转换为目标类型，因此执行该转换不需要函数。

**`WITH INOUT`**

表示该类型转换是 I/O 转换式类型转换，通过调用源数据类型的输出函数，并将得到的字符串传给目标数据类型的输入函数来执行。

**`AS ASSIGNMENT`**

表示该类型转换可以在赋值上下文中隐式调用。

**`AS IMPLICIT`**

表示该类型转换可以在任何上下文中隐式调用。

## 注解 {#notes}

注意，在本版本的 Apache Cloudberry 中，用户定义类型转换所使用的用户定义函数必须定义为 `IMMUTABLE`。自定义函数的任何已编译代码（共享库文件）必须放在 Apache Cloudberry 阵列（Coordinator 和所有 Segment）中每台主机上的同一位置。该位置还必须在 `LD_LIBRARY_PATH` 中，以便服务器能够找到这些文件。

请记住，如果希望能够双向转换类型，则需要显式声明两个方向的类型转换。

通常没有必要在用户定义类型与标准字符串类型（`text`、`varchar` 和 `char(*n*)`，以及被定义为属于字符串类别的用户定义类型）之间创建类型转换。Apache Cloudberry 为这些类型提供了自动的 I/O 转换式类型转换。到字符串类型的自动转换被视为赋值转换，而从字符串类型的自动转换则仅限显式。可以通过声明自己的类型转换来替换自动转换，从而覆盖这一行为，但通常这样做的唯一原因是希望该转换比标准的仅限赋值或仅限显式的设置更容易被调用。另一个可能的原因是希望该转换的行为与该类型的 I/O 函数不同——这样做之前请三思。（少数内置类型的转换行为确实不同，这主要是因为 SQL 标准的要求。）

建议遵循以目标数据类型命名类型转换实现函数的约定，就像内置的类型转换实现函数的命名方式那样。许多用户习惯于使用函数式写法来转换数据类型，即 `typename(x)`。

有两种情况下，函数调用构造会在未匹配到实际函数的情况下被视为类型转换请求。如果函数调用 `*name(x)*` 与任何现有函数都不完全匹配，但 `*name*` 是某个数据类型的名称，并且 `pg_cast` 提供了从 `*x*` 的类型到该类型的二进制可强制转换，则该调用会被解释为二进制可强制转换。Apache Cloudberry 做此例外，是为了使二进制可强制转换即使没有任何函数，也能使用函数语法调用。同样，如果没有 `pg_cast` 条目，但转换涉及字符串类型（转到或来自字符串类型），则该调用会被解释为 I/O 转换式类型转换。这一例外使 I/O 转换式类型转换可以使用函数语法调用。

上述例外还有一个例外：从复合类型到字符串类型的 I/O 转换式类型转换不能使用函数语法调用，而必须写成显式转换语法（`CAST` 或 :: 记法）。之所以有这一例外，是因为在引入自动提供的 I/O 转换式类型转换之后，发现当本意是函数或列引用时，很容易意外调用这类转换。

## 示例 {#examples}

使用函数 `int4(bigint)` 创建从类型 `bigint` 到类型 `int4` 的赋值转换（该转换已在系统中预定义）：

```sql
CREATE CAST (bigint AS int4) WITH FUNCTION int4(bigint) AS ASSIGNMENT;
```

## 兼容性 {#compatibility}

`CREATE CAST` 命令符合 SQL 标准，只是 SQL 没有为二进制可强制转换的类型或实现函数的额外参数作出规定。`AS IMPLICIT` 也是 Apache Cloudberry 的扩展。
