## 概要 {#synopsis}

```shell
psql [<option> ...] [<dbname> [<username>]]
```

## 说明 {#description}

`psql` 是 Apache Cloudberry 的终端前端。它允许你交互式输入查询，将查询发送给 Apache Cloudberry，并查看查询结果。也可以从文件读取输入。此外，它提供许多元命令和各种类似 shell 的功能，便于编写脚本并自动执行各种任务。

## 选项 {#options}

**`-a | --echo-all`**

读取输入时，将所有非空输入行输出到标准输出。（这不适用于交互式读取的行。）这等同于将变量 ECHO 设为 `all`。

**`-A | --no-align`**

切换到不对齐输出模式。（默认输出模式为对齐。）

**`-c 'command' | --command='command'`**

指定 `psql` 运行给定的命令字符串，然后退出。这对 shell 脚本很有用。command 必须是服务器可以完整解析的命令字符串，或单个反斜杠命令。因此，使用此选项时不能混合 SQL 和 `psql` 元命令。要实现这一点，可以将字符串通过管道传给 `psql`，例如：

```shell
echo '\x \\ SELECT * FROM foo;' | psql
```

（`\` 是分隔符元命令。）

如果命令字符串包含多个 SQL 命令，除非字符串中包含明确的 `BEGIN/COMMIT` 命令将其分成多个事务，否则这些命令将在单个事务中处理。这与将同一字符串提供给 `psql` 标准输入时的行为不同。此外，只返回最后一个 SQL 命令的结果。

**`-d dbname | --dbname=dbname`**

指定要连接的数据库名称。这等同于在命令行中将 dbname 作为第一个非选项参数指定。

如果此参数包含 `=` 号，或以有效 URI 前缀（`postgresql://` 或 `postgres://`）开头，则将其视为 `conninfo` 字符串。更多信息请参阅 PostgreSQL 文档中的[连接字符串](https://www.postgresql.org/docs/12/libpq-connect.html#LIBPQ-CONNSTRING)。

**`-e | --echo-queries`**

同时将发送给服务器的所有 SQL 命令复制到标准输出。

**`-E | --echo-hidden`**

回显 `\d` 和其他反斜杠命令生成的实际查询。可以用它研究 `psql` 的内部操作。这等同于将变量 ECHO_HIDDEN 设为 `on`。

**`-f filename | --file=filename`**

使用文件 filename 作为命令源，而不是交互式读取命令。处理完文件后，`psql` 终止。这在很多方面等同于元命令 `\i`。

如果 filename 为 `-`（连字符），则读取标准输入，直到遇到 EOF 标志或 `\q` 元命令。但请注意，此时不使用 Readline（很像指定了 `-n`）。

使用此选项与写 `psql < <filename>` 略有不同。一般来说，两者都会按预期工作，但使用 `-f` 可以启用一些便利功能，例如带行号的错误消息。此外，使用此选项可能略微降低启动开销。另一方面，使用 shell 输入重定向的变体（理论上）保证产生的输出与手动输入全部内容时完全相同。

**`-F separator | --field-separator=separator`**

使用指定分隔符作为不对齐输出的字段分隔符。

**`-H | --html`**

启用 HTML 表格输出。

**`-l | --list`**

列出所有可用数据库，然后退出。其他非连接选项都会被忽略。

**`-L filename | --log-file=filename`**

除正常输出目标外，将所有查询输出写入指定日志文件。

**`-n | --no-readline`**

不使用 Readline 进行行编辑，也不使用命令历史记录。在剪切和粘贴时，这有助于关闭制表符扩展。

**`-o filename | --output=filename`**

将所有查询输出写入指定文件。

**`-P assignment | --pset=assignment`**

允许在命令行中按 `\pset` 的风格指定打印选项。注意，此处必须用等号而不是空格分隔名称和值。因此，要将输出格式设为 `LaTeX`，可以写成 `-P format=latex`。

**`-q | --quiet`**

指定 `psql` 安静地执行工作。默认情况下，它会打印欢迎消息和各种信息性输出。使用此选项后，这些输出都不会产生。此选项与 `-c` 选项一起使用很有用。这等同于将变量 QUIET 设为 `on`。

**`-R separator | --record-separator=separator`**

使用 separator 作为不对齐输出的记录分隔符。

**`-s | --single-step`**

以单步模式运行。这意味着每个命令发送到服务器前都会提示用户，也可以取消执行。用此选项调试脚本。

**`-S | --single-line`**

以单行模式运行，此时换行符终止 SQL 命令，就像分号一样。

**`-t | --tuples-only`**

关闭列名、结果行数页脚等内容的打印。此命令等同于 `\pset tuples_only`，仅为方便而提供。

**`-T table_options | --table-attr= table_options`**

允许指定要放入 HTML table 标签中的选项。详情参阅 `\pset`。

**`-v assignment | --set=assignment | --variable= assignment`**

执行变量赋值，类似于 `\set` 元命令。注意，在命令行中必须用等号分隔名称和值（如果有）。要取消设置变量，省略等号。要将变量设为空值，使用等号但省略值。这些赋值在启动的很早阶段执行，因此保留给内部用途的变量之后可能被覆盖。

**`-V | --version`**

打印 `psql` 版本并退出。

**`-x | --expanded`**

启用扩展表格式模式。

**`-X | --no-psqlrc`**

不读取启动文件（系统范围的 `psqlrc` 文件和用户的 `~/.psqlrc` 文件都不读取）。

**`-z | --field-separator-zero`**

将不对齐输出的字段分隔符设为零字节。

**`-0 | --record-separator-zero`**

将不对齐输出的记录分隔符设为零字节。这对于与 `xargs -0` 等工具交互很有用。

**`-1 | --single-transaction`**

`psql` 运行脚本时，添加此选项会在脚本外包裹 `BEGIN`/`COMMIT`，使脚本作为单个事务运行。这确保所有命令要么全部成功完成，要么不应用任何更改。

如果脚本本身使用 `BEGIN`、`COMMIT` 或 `ROLLBACK`，此选项不会产生预期效果。此外，如果脚本包含不能在事务块中运行的命令，指定此选项会使该命令（从而使整个事务）失败。

**`-? | --help`**

显示 `psql` 命令行参数的帮助并退出。

### 连接选项 {#connection-options}

**`-h host | --host=host`**

运行 Cloudberry Coordinator 数据库服务器的主机名。如果未指定，将读取环境变量 `PGHOST` 的值，否则默认为 localhost。

在 Coordinator 主机上启动 `psql` 时，如果主机值以斜杠开头，则将其用作 UNIX 域套接字的目录。

**`-p port | --port=port`**

Cloudberry Coordinator 数据库服务器监听连接的 TCP 端口。如果未指定，将读取环境变量 `PGPORT` 的值，否则默认为 `5432`。

**`-U username | --username=username`**

连接时使用的数据库角色名。如果未指定，将读取环境变量 `PGUSER` 的值，否则默认为当前系统角色名。

**`-W | --password`**

强制提示输入密码。服务器请求密码认证时，`psql` 应自动提示输入密码。但是，目前密码请求检测并不完全可靠，因此提供此选项强制提示。如果没有发出密码提示，而服务器又要求密码认证，连接尝试将失败。

**`-w --no-password`**

从不提示输入密码。如果服务器要求密码认证，而又无法通过 .pgpass 文件等其他方式获取密码，连接尝试将失败。此选项适用于无人输入密码的批处理作业和脚本。

> **注意** 此选项在整个会话期间保持设置，因此也会影响元命令 `\connect` 的使用以及初始连接尝试。

## 退出状态 {#exit-status}

如果正常结束，`psql` 向 shell 返回 0；如果发生自身的致命错误（内存不足、找不到文件），返回 1；如果与服务器的连接异常且会话不是交互式，返回 2；如果脚本发生错误且变量 `ON_ERROR_STOP` 已设置，返回 3。

## 用法 {#usage}

### 连接数据库 {#connect-to-a-database}

`psql` 是 Apache Cloudberry 的客户端应用程序。要连接数据库，需要知道目标数据库名称、Cloudberry Coordinator 服务器的主机名和端口号，以及要使用的数据库用户名。可以分别通过 `-d`、`-h`、`-p` 和 `-U` 命令行选项将这些参数告知 `psql`。如果发现某个参数不属于任何选项，则将其解释为数据库名（如果已给出数据库名，则解释为用户名）。这些选项不必全部提供，因为有可用的默认值。如果省略主机名，`psql` 会通过 UNIX 域套接字连接本地主机上的 Coordinator 服务器；在没有 UNIX 域套接字的机器上，则通过 TCP/IP 连接 `localhost`。默认 Coordinator 端口号为 5432。如果使用其他 Coordinator 端口，必须指定端口。默认数据库用户名是操作系统用户名，默认数据库名也是如此。注意，不能使用任意用户名连接任意数据库。数据库管理员应已告知你拥有的访问权限。

默认值不合适时，可以将环境变量 `PGAPPNAME`、`PGDATABASE`、`PGHOST`、`PGPORT` 和 `PGUSER` 中的任意一个或全部设为适当值，减少输入。

还可以使用 `~/.pgpass` 文件，避免经常输入密码。该文件应位于主目录中，并包含以下格式的行：

```shell
<hostname>:<port>:<database>:<username>:<password>
```

`.pgpass` 的权限必须禁止其他用户或组访问（例如：`chmod 0600 ~/.pgpass`）。如果权限不够严格，将忽略该文件。（不过，Microsoft Windows 客户端目前不检查文件权限。）

另一种指定连接参数的方法是使用 `conninfo` 字符串或 URI，代替数据库名。此机制可以非常细致地控制连接。例如：

```shell
$ psql "service=myservice sslmode=require"
$ psql postgresql://gpcoordinator:5433/mydb?sslmode=require
```

这样也可以使用 LDAP 查找连接参数，具体说明请参阅 PostgreSQL 文档中的 [LDAP 查找连接参数](https://www.postgresql.org/docs/12/libpq-ldap.html)。所有可用连接选项的更多信息，请参阅 PostgreSQL 文档中的[参数关键字](https://www.postgresql.org/docs/12/libpq-connect.html#LIBPQ-PARAMKEYWORDS)。

如果因任何原因无法建立连接（权限不足、服务器未运行等），`psql` 将返回错误并终止。

如果标准输入或标准输出至少有一个是终端，则 `psql` 会将客户端编码设为 `auto`，根据区域设置（Unix 系统上的 `LC_CTYPE` 环境变量）检测适当的客户端编码。如果结果不符合预期，可以使用 `PGCLIENTENCODING` 环境变量覆盖客户端编码。

### 输入 SQL 命令 {#enter-sql-commands}

正常运行时，`psql` 提示符包含 `psql` 当前连接的数据库名称，后面是普通用户使用的 **=>**，或超级用户使用的 **=\#**。例如：

```shell
testdb=>
testdb=#
```

在提示符下，用户可以输入 SQL 命令。通常，输入行遇到终止命令的分号时才发送到服务器。行尾不会终止命令，因此可以将命令分成多行以提高可读性。如果命令已发送且运行无误，命令结果会显示在屏幕上。

如果不受信任用户可以访问尚未采用[模式的安全使用方式](https://www.postgresql.org/docs/12/ddl-schemas.html#DDL-SCHEMAS-PATTERNS)的数据库，请在会话开始时从 search_path 中移除可公开写入的模式。可以将 `options=-csearch_path=` 添加到连接字符串，或在其他 SQL 命令前执行 `SELECT pg_catalog.set_config('search_path', '', false)`。此注意事项并非 `psql` 特有，适用于运行任意 SQL 命令的所有接口。

## 元命令 {#meta-commands}

在 `psql` 中输入的内容，只要以未加引号的反斜杠开头，就是由 `psql` 自身处理的 `psql` 元命令。这些命令使 `psql` 更便于管理和编写脚本。元命令通常也称为斜杠命令或反斜杠命令。

`psql` 命令的格式为反斜杠后紧跟命令动词，再接参数。参数与命令动词之间、各参数之间以任意数量的空白字符分隔。

若要在参数中包含空白字符，可用单引号将其括起。若要在这样的参数中包含单引号，请在单引号文本内连续写两个单引号。此外，单引号内的内容还会进行类似 C 语言的替换：`\n`（换行）、`\t`（制表符）、`\b`（退格）、`\r`（回车）、`\f`（换页）、`\digits`（八进制）和 `\xdigits`（十六进制）。在单引号文本中，反斜杠若位于其他任何字符之前，就会转义该字符。

参数中用反引号（```）括起的文本会被视为命令行并传递给 shell。命令的输出（去掉末尾的换行符）会替换这段反引号文本。

如果参数中出现未加引号的冒号（`:`），后面紧跟 `psql` 变量名，则会将其替换为该变量的值，详见 [SQL 插值](#sql-interpolation)。

某些命令接受 SQL 标识符（如表名）作为参数。这类参数遵循 SQL 的语法规则：未加引号的字母会强制转为小写，而双引号（`"`）可防止字母进行大小写转换，并允许标识符中包含空白字符。在双引号内，成对的双引号在最终名称中会合并为一个双引号。例如，`FOO"BAR"BAZ` 被解释为 `fooBARbaz`，而 `"A weird"" name"` 则变为 `A weird" name`。

遇到另一个未加引号的反斜杠时，参数解析就会停止，并将其视为新元命令的开始。特殊序列 `\`（两个反斜杠）标记参数结束，并继续解析后续的 SQL 命令（如果有）。因此，一行内可以自由混用 SQL 和 `psql` 命令。但无论如何，元命令的参数都不能跨越行尾。

定义了以下元命令：

**`\a`**

如果当前表格输出格式为不对齐，则切换为对齐；否则切换为不对齐。保留此命令是为了向后兼容。更通用的设置方式见 `\pset`。

**`\c | \connect [dbname [username] [host] [port]] | conninfo`**

建立新的 Apache Cloudberry 连接。连接参数既可按位置语法指定，也可使用 `conninfo` 连接字符串，详见 [libpq 连接字符串](https://www.postgresql.org/docs/12/libpq-connect.html#LIBPQ-CONNSTRING)。

如果命令省略了数据库名、用户、主机或端口，新连接可以复用上次连接的值。默认情况下，除了处理 `conninfo` 字符串时，都会复用上次连接的值。将第一个参数设为 `-reuse-previous=on` 或 `-reuse-previous=off` 可覆盖该默认行为。如果某个参数既未指定也未复用，则使用 `libpq` 的默认值。将 dbname、username、host 或 port 指定为 `-`，等同于省略该参数。

如果新连接建立成功，就会关闭原连接。如果连接尝试失败，只有在 `psql` 处于交互模式时才会保留原连接。运行非交互脚本时，处理会立即停止并报错。这样区分是为了方便用户纠正输入错误，同时防止脚本意外操作错误的数据库。

示例：

```shell
=> \c mydb myuser host.dom 6432
=> \c service=foo
=> \c "host=localhost port=5432 dbname=mydb connect_timeout=10 sslmode=disable"
=> \c postgresql://tom@localhost/mydb?application_name=myapp
```

**`\C [title]`**

设置查询结果中所打印表格的标题，或取消已有标题。此命令等同于 `\pset title`。

**`\cd [directory]`**

更改当前工作目录。不带参数时，切换到当前用户的主目录。要显示当前工作目录，请使用 `\!pwd`。

**`\conninfo`**

显示当前连接的信息，包括数据库名、用户名、连接类型（UNIX 域套接字、`TCP/IP` 等）、主机和端口。

**`\copy {table [(column_list)] | (query)} {from | to} {'filename' | program 'command' | stdin | stdout | pstdin | pstdout} [with] (option [, ...])`**

执行前端（客户端）复制。此操作会运行 SQL [`COPY`](/cloudberry/reference/sql-stmts/copy/) 命令，但指定文件由 `psql` 读写，而非由服务器读写；数据经由它在服务器和本地文件系统之间传送。因此，文件的可访问性和权限取决于本地用户，而非服务器，且不需要 SQL 超级用户权限。

指定 `program` 时，command 由 `psql` 运行，来自 command 或发往 command 的数据在服务器与客户端之间传送。因此，执行权限取决于本地用户，而非服务器，且不需要 SQL 超级用户权限。

`\copy ... from stdin | to stdout` 分别通过命令输入和输出进行读写。所有行都从发出命令的同一来源读取，直到读到 `\.` 或数据流到达 `EOF`。输出发送到命令输出所在的位置。若要读写 `psql` 的标准输入或标准输出，请使用 `pstdin` 或 `pstdout`。此选项适合直接在 SQL 脚本文件中填充表数据。

此命令的语法与 SQL [`COPY`](/cloudberry/reference/sql-stmts/copy/) 命令类似，option 必须指定 SQL `COPY` 命令的某个选项。正因如此，`\copy` 命令采用特殊的解析规则。具体而言，变量替换规则和反斜杠转义不适用。

此操作的效率低于 SQL `COPY` 命令，因为所有数据都必须经过客户端与服务器之间的连接。

**`\copyright`**

显示 Apache Cloudberry 所基于的 PostgreSQL 的版权和分发条款。

**`\d [relation_pattern]  | \d+ [relation_pattern] | \dS [relation_pattern]`**

对于每个与 relation 模式匹配的关系（表、外部表、视图、物化视图、索引、序列或外表）或复合类型，显示全部列、列类型、表空间（如果不是默认表空间），以及 `NOT NULL` 或默认值等特殊属性。还会显示相关索引、约束、规则和触发器。对于外表，还会显示关联的外部服务器。

- 对于某些关系类型，`\d` 会显示各列的附加信息：序列的列值、索引的索引表达式，以及外表的外部数据包装器选项。
- `\d+` 命令的作用相同，但显示更多信息：包括表中各列的注释、表是否含有 OID，以及关系为视图时的视图定义。

    对于分区表，使用 `\d` 或 `\d+` 命令指定根分区表或子表时，会显示该表的信息，包括分区表当前层级的分区键。`\d+` 命令还会显示表的直接子分区，以及分区是外部表还是普通表。

    对于 AO 表和列存表，`\d+` 会显示表的存储选项。AO 表按表显示这些选项，列存表则按列显示存储选项。

- 默认仅显示用户创建的对象；提供模式或 `S` 修饰符即可包含系统对象。

    > **注意** 如果使用 `\d` 时未提供模式参数，则等同于 `\dtvmsE`，会列出所有可见的表、视图、物化视图、序列和外表。

**`\da[S] [aggregate_pattern]`**

列出聚合函数及其操作的数据类型。如果指定了模式，则仅显示名称与该模式匹配的聚合函数。默认仅显示用户创建的对象；提供模式或 `S` 修饰符即可包含系统对象。

**`\db[+] [tablespace_pattern]`**

**`\dF[+] [pattern]`**

**`\dFt[+] [pattern]`**

**`\dg[+] [role_pattern]`**

**`\dl`**

> **注意** Apache Cloudberry 不支持 PostgreSQL 的[大对象机制](https://www.postgresql.org/docs/12/largeobjects.html)，无法以流式方式处理存储在大对象结构中的用户数据。

**`\do[S] [operator_pattern]`**

列出可用运算符及其操作数类型和返回类型。如果指定了模式，则仅列出名称与该模式匹配的运算符。默认仅显示用户创建的对象；提供模式或 `S` 修饰符即可包含系统对象。

**`\dO[S+] [pattern]`**

**`\dp [relation_pattern_to_show_privileges]`**

列出表、视图和序列及其相关访问权限。如果指定了模式，则仅列出名称与该模式匹配的表、视图和序列。[GRANT](/cloudberry/reference/sql-stmts/grant/) 和 [REVOKE](/cloudberry/reference/sql-stmts/revoke/) 命令用于设置访问权限。权限显示内容的含义见 [GRANT](/cloudberry/reference/sql-stmts/grant/)。

**`\drds [role-pattern [database-pattern]]`**

列出已定义的配置设置。这些设置可以针对角色、数据库，或同时针对二者。role-pattern 和 database-pattern 分别用于选择要列出的特定角色和数据库。省略相应参数或指定 `*` 时，会列出所有设置，包括不针对特定角色或特定数据库的设置。

[`ALTER ROLE`](/cloudberry/reference/sql-stmts/alter-role/) 和 [`ALTER DATABASE`](/cloudberry/reference/sql-stmts/alter-database/) 命令用于定义各角色和各数据库的角色配置设置。

**`\dT[S+] [datatype_pattern]`**

列出数据类型。如果指定了模式，则仅列出名称与该模式匹配的类型。如果在命令名后附加 `+`，还会列出各类型的内部名称、大小、枚举类型（`enum`）的允许值，以及相关权限。默认仅显示用户创建的对象；提供模式或 `S` 修饰符即可包含系统对象。

**`\du[+] [role_pattern]`**

列出数据库角色。（“用户”和“组”的概念已统一为“角色”，因此此命令现在等同于 `\dg`。）如果指定了模式，则仅列出名称与该模式匹配的角色。如果使用 `\du+` 形式，则显示各角色的附加信息；目前会增加各角色的注释。

**`\dx[+] [extension_pattern]`**

列出已安装的扩展。如果指定了模式，则仅列出名称与该模式匹配的扩展。如果使用 `\dx+` 形式，则列出属于每个匹配扩展的全部对象。

**`\dy[+] [pattern]`**

列出事件触发器。如果指定了模式，则仅列出名称与该模式匹配的触发器。如果在命令名后附加 `+`，还会列出每个对象的相关描述。

**`\dy[+] [pattern]`**

列出事件触发器。如果指定了模式，则仅列出名称与该模式匹配的触发器。如果在命令名后附加 `+`，还会列出每个对象的相关描述。

> **注意** Apache Cloudberry 不支持用户定义的触发器。

**`\e | \edit [filename] [line_number]`**

如果指定了 filename，就编辑该文件；退出编辑器后，其内容会复制回查询缓冲区。如果未指定 filename，则将当前查询缓冲区复制到临时文件，再以同样方式编辑。

随后按照 `psql` 的常规规则重新解析新的查询缓冲区，将整个缓冲区视为一行。（因此无法用这种方式编写脚本，编写脚本请使用 `\i`。）这也意味着，如果查询以分号结尾（更确切地说，只要包含分号），就会立即执行。否则，它只会留在查询缓冲区中等待；输入分号或 `\g` 可发送查询，输入 `\r` 可取消。

如果指定了行号，`psql` 会将光标定位到文件或查询缓冲区的相应行。注意，如果只提供一个全为数字的参数，`psql` 会将其视为行号，而非文件名。

有关配置和定制编辑器的信息，见[环境](#environment)。

**`\echo text [ ... ]`**

将参数打印到标准输出，以单个空格分隔，并在末尾加上换行符。这可用于在脚本输出中穿插提示信息。如果第一个参数为未加引号的 `-n`，则不输出末尾的换行符。

> **注意** 如果使用 `\o` 命令重定向查询输出，可能应使用 `\qecho` 代替此命令。

**`\ef [function_description [line_number]]`**

此命令以 `CREATE OR REPLACE FUNCTION` 命令的形式获取并编辑指定函数的定义。编辑方式与 `\edit` 相同。退出编辑器后，更新后的命令会留在查询缓冲区中等待；输入分号或 `\g` 可发送命令，输入 `\r` 可取消。

目标函数可以仅用名称指定，也可以用名称和参数指定，例如 `foo(integer, text)`。如果存在多个同名函数，则必须提供参数类型。

如果未指定函数，则会提供空白的 `CREATE FUNCTION` 模板供编辑。

如果指定了行号，`psql` 会将光标定位到函数体的相应行。（注意，函数体通常并非从文件的第一行开始。）

有关配置和定制编辑器的信息，见[环境](#environment)。

**`\encoding [encoding]`**

设置客户端字符集编码。不带参数时，此命令显示当前编码。

**`\f [field_separator_string]`**

设置不对齐查询输出的字段分隔符。默认值为竖线（`|`）。另见 `\pset`，它提供通用的输出选项设置方式。

**`\g [filename]`**<br />
**`\g [ `|` command ]`**

将当前查询输入缓冲区发送到服务器，并可选择将查询输出存入 filename，或通过管道将输出传给 shell 命令 command。仅当查询成功返回零个或多个元组时，才会写入文件或命令；查询失败或 SQL 命令不返回数据时，不会写入。

单独使用 `\g` 基本等同于分号。带参数的 `\g` 则相当于仅生效一次的 `\o` 命令。

**`\gset [prefix]`**

将当前查询输入缓冲区发送到服务器，并将查询输出存入 `psql` 变量。要执行的查询必须恰好返回一行。该行的每一列都会存入一个独立变量，变量名与列名相同。例如：

```sql
=> SELECT 'hello' AS var1, 10 AS var2;
-> \gset
=> \echo :var1 :var2
hello 10
```

如果指定了 prefix，则会将该字符串加在查询列名前，形成要使用的变量名：

```sql
=> SELECT 'hello' AS var1, 10 AS var2;
-> \gset result_
=> \echo :result_var1 :result_var2
hello 10
```

如果某列结果为 NULL，则取消设置相应变量，而不是为其赋值。

如果查询失败或返回结果不是一行，则不会更改任何变量。

**`\h | \help [sql_command]`**

提供指定 SQL 命令的语法帮助。如果未指定命令，`psql` 会列出所有可提供语法帮助的命令。如果 command 为星号（`*`），则显示所有 SQL 命令的语法帮助。为便于输入，由多个单词组成的命令无需加引号。

**`\H | \html`**

启用 HTML 查询输出格式。如果已启用 HTML 格式，则切换回默认的对齐文本格式。此命令是为兼容性和使用便利而提供的；有关其他输出选项的设置，见 `\pset`。

**`\i | \include filename`**

从文件 filename 读取输入，并按键盘输入的方式执行。

如果 filename 为 `-`（连字符），则读取标准输入，直到遇到 EOF 标记或 `\q` 元命令。这可用于交替使用交互输入和文件输入。注意，只有最外层启用了 Readline 时，才会使用其行为。

若要在读取各行时将其显示在屏幕上，必须将变量 `ECHO` 设为 `all`。

**`\ir | \include_relative filename`**

`\ir` 命令与 `\i` 类似，但解析相对文件名的方式不同。交互模式下，两者行为相同。不过，从脚本调用时，`\ir` 会相对于脚本所在目录解释文件名，而非相对于当前工作目录。

**`\l[+] | \list[+] [pattern]`**

列出服务器中的数据库，显示其名称、所有者、字符集编码和访问权限。如果指定了模式，则仅列出名称与该模式匹配的数据库。如果在命令名后附加 `+`，还会显示数据库大小、默认表空间和描述。（大小信息仅适用于当前用户能够连接的数据库。）

**`\lo_export loid filename`**

从数据库读取 OID 为 loid 的大对象，并将其写入 filename。注意，这与服务器函数 `lo_export` 略有不同，后者使用运行数据库服务器的用户权限，并操作服务器的文件系统。使用 `\lo_list` 可查找大对象的 OID。

> **注意** Apache Cloudberry 不支持 PostgreSQL 的[大对象机制](https://www.postgresql.org/docs/12/largeobjects.html)，无法以流式方式处理存储在大对象结构中的用户数据。

**`\lo_import large_object_filename [comment]`**

将文件存储到大对象中。也可将指定注释与该对象关联。例如：

```shell
mydb=> \lo_import '/home/gpadmin/pictures/photo.xcf' 'a 
picture of me'
lo_import 152801
```

响应表明该大对象获分配的对象 ID 为 152801；如果今后还要访问它，就应记住这个 ID。因此，建议始终为每个对象添加便于人阅读的注释，之后可用 `\lo_list` 命令查看。注意，此命令与服务器端的 `lo_import` 略有不同：它以本地用户身份操作本地文件系统，而不是使用服务器的用户和文件系统。

> **注意** Apache Cloudberry 不支持 PostgreSQL 的[大对象机制](https://www.postgresql.org/docs/12/largeobjects.html)，无法以流式方式处理存储在大对象结构中的用户数据。

**`\lo_list`**

列出当前存储在数据库中的所有大对象及其注释（如果有）。

> **注意** Apache Cloudberry 不支持 PostgreSQL 的[大对象机制](https://www.postgresql.org/docs/12/largeobjects.html)，无法以流式方式处理存储在大对象结构中的用户数据。

**`\lo_unlink largeobject_oid`**

从数据库中删除指定 OID 的大对象。使用 `\lo_list` 可查找大对象的 OID。

> **注意** Apache Cloudberry 不支持 PostgreSQL 的[大对象机制](https://www.postgresql.org/docs/12/largeobjects.html)，无法以流式方式处理存储在大对象结构中的用户数据。

**`\o | \out [ filename ]`**<br />
**`\o | \out [ `|` command ]`**

将后续查询结果保存到文件 filename，或通过管道传给 shell 命令 command。如果未指定参数，则将查询输出恢复为标准输出。查询结果包括从数据库服务器获得的所有表格、命令响应和通知，以及查询数据库的各种反斜杠命令（如 `\d`）的输出，但不包括错误消息。要在查询结果之间穿插文本输出，请使用 `\qecho`。

**`\p`**

将当前查询缓冲区打印到标准输出。

**`\password [username]`**

更改指定用户（默认为当前用户）的密码。此命令提示输入新密码，将其加密后以 `ALTER ROLE` 命令发送到服务器。这可确保新密码不会以明文出现在命令历史、服务器日志或其他位置。

**`\prompt [ text ] name`**

提示用户输入文本，并将其赋给变量 name。可用 text 指定提示字符串。（提示包含多个单词时，请用单引号将文本括起。）

默认情况下，`\prompt` 使用终端进行输入和输出。不过，如果使用了命令行开关 `-f`，`\prompt` 就会使用标准输入和标准输出。

**`\pset [print_option [value]]`**

此命令设置影响查询结果表输出的选项。print_option 指定要设置的选项，value 的含义取决于所选选项。对于某些选项，省略 value 会切换或取消该选项，详见各选项的说明。如果未说明这种行为，那么省略 value 只会显示当前设置。

不带任何参数的 `\pset` 会显示所有打印选项的当前状态。

可调整的打印选项包括：

- **`border`** – 值必须是数字。通常，数字越大，表格的边框和分隔线越多，但具体取决于格式。在 HTML 格式中，它直接对应 `border=...` 属性；其他格式中，只有 `0`（无边框）、`1`（内部分隔线）和 `2`（表格外框）有意义。`latex` 和 `latex-longtable` 还支持将 `border` 设为 3，以在各行之间添加分隔线。
- **`columns`** – 设置 `wrapped` 格式的目标宽度，以及判断输出是否过宽、需要使用分页器或在扩展自动模式下改为纵向显示的宽度阈值。默认值为零。值为零时，目标宽度由环境变量 `COLUMNS` 控制；若未设置 `COLUMNS`，则使用检测到的屏幕宽度。此外，如果 `columns` 为零，折行格式仅影响屏幕输出。如果 columns 非零，则文件和管道输出也会按该宽度折行。

    设置目标宽度后，使用 `\pset format wrapped` 命令启用折行格式。

- **`expanded`** | **`x`** – 如果指定 value，其值必须为 `on`、`off` 或 `auto`，分别表示启用扩展模式、禁用扩展模式或自动选择。省略 value 时，命令会在 `on` 和 `off` 之间切换。启用扩展模式时，查询结果以两列显示，左侧为列名，右侧为数据。如果普通的“横向”模式无法在屏幕上容纳数据，此模式会很有用。设为 `auto` 时，只要查询输出宽于屏幕，就使用扩展模式，否则使用常规模式。`auto` 设置仅对对齐和折行格式有效。在其他格式下，其行为始终与扩展模式设为 `off` 相同。
- **`fieldsep`** – 指定不对齐输出模式使用的字段分隔符。例如，可以生成以制表符或逗号分隔的输出，以适应其他程序的需要。要将制表符设为字段分隔符，请输入 `\pset fieldsep '\t'`。默认字段分隔符为 `'|'`（竖线）。
- **`fieldsep_zero`** - 将不对齐输出格式使用的字段分隔符设为零字节。
- **`footer`** – 如果指定 value，其值必须为 `on` 或 `off`，分别启用或禁用表格页脚（行数统计 (n rows)）的显示。省略 value 时，命令会切换页脚的显示状态。
- **`format`** – 将输出格式设为 `unaligned`、`aligned`、`html`、`latex`（使用 `tabular`）、`latex-longtable`、`troff-ms` 或 `wrapped` 之一。允许使用不产生歧义的缩写。

    **`unaligned`** 格式将一行中的所有列写在同一行上，以当前生效的字段分隔符分隔。这适合生成供其他程序读取的输出（例如制表符分隔或逗号分隔格式）。

    **`aligned`** 格式是标准的、便于阅读且排版整齐的文本输出格式；这是默认格式。

    **`html`**、**`latex`**、**`latex-longtable`** 和 **`troff-ms`** 格式输出的表格可嵌入使用相应标记语言的文档。它们并非完整文档！（对 HTML 来说，这可能影响不大，但 LaTeX 必须有完整的文档外层结构。`latex-longtable` 还要求使用 LaTeX 的 `longtable` 和 `booktabs` 宏包。）

    **`wrapped`** 格式类似于 `aligned`，但会将较宽的数据值折行，使输出适合目标列宽。目标宽度按 `columns` 选项中的说明确定。注意，`psql` 不会尝试折行显示列标题；如果列标题所需的总宽度超出目标宽度，`wrapped` 格式的行为就与 `aligned` 相同。

- **`linestyle`** [**`unicode`** | **`ascii`** | **`old-ascii`**] – 将边框线条样式设为 unicode、ascii 或 old-ascii。三种样式都允许使用不产生歧义的缩写，包括单字母缩写。默认设置为 `ascii`。此选项仅影响 `aligned` 和 `wrapped` 输出格式。

    **`ascii`** – 使用普通 ASCII 字符。数据中的换行符会以右侧边缘的 `+` 符号表示。当折行格式在没有换行符的情况下将数据从一行折到下一行时，会在前一行的右侧边缘和后一行的左侧边缘各显示一个点（`.`）。

    **`old-ascii`** – 使用普通 ASCII 字符，采用 PostgreSQL 8.4 及更早版本的格式样式。数据中的换行符会以 `:` 符号表示，替代左侧列分隔符。当数据在没有换行符的情况下从一行折到下一行时，会用 `;` 符号替代左侧列分隔符。

    **`unicode`** – 使用 Unicode 制表字符。数据中的换行符会以右侧边缘的回车符号表示。当数据在没有换行符的情况下从一行折到下一行时，会在前一行的右侧边缘和后一行的左侧边缘各显示一个省略号。

    当 `border` 设置大于零时，此选项还决定绘制边框线使用的字符。普通 ASCII 字符适用于所有环境，而 Unicode 字符在支持它们的显示器上更美观。

- **`null 'string'`** – 第二个参数指定列值为 null 时要打印的字符串。默认不打印任何内容，这很容易与空字符串混淆。例如，可以使用 `\pset null '(null)'`。
- **`numericlocale`** – 如果指定 value，其值必须为 `on` 或 `off`，分别启用或禁用使用区域设置特定字符来分隔小数点左侧数字组的显示方式。省略 value 时，命令会在常规数字输出和区域设置特定的数字输出之间切换。
- **`pager`** – 控制是否对查询和 `psql` 帮助输出使用分页器。如果设置了环境变量 `PAGER`，输出就会通过管道传给指定程序。否则，使用平台默认程序（如 `more`）。设为 `off` 时，不使用分页器。设为 `on` 时，仅在适当情况下使用分页器，即输出目标为终端且无法在屏幕上完整显示时。还可将 pager 设为 `always`，使所有终端输出都使用分页器，无论能否在屏幕上完整显示。不带值的 `\pset pager` 会切换分页器的启用状态。
- **`recordsep`** – 指定不对齐输出模式使用的记录（行）分隔符。默认值为换行符。
- **`recordsep_zero`** - 将不对齐输出格式使用的记录分隔符设为零字节。
- **`tableattr`** | **`T`** [text] – 在 HTML 格式中，指定要放入 HTML `table` 标签内的属性，例如 `cellpadding` 或 `bgcolor`。注意，通常不应在此指定 `border`，因为它已由 `\pset border` 处理。如果未提供值，则取消表格属性设置。

    在 `latex-longtable` 格式中，此选项控制包含左对齐数据类型的各列的宽度比例。其值为以空白分隔的数值列表，例如 `'0.2 0.2 0.6'`。未指定的输出列使用最后一个指定值。

- **`title`** [text] – 设置后续打印的所有表格的标题，可用于为输出添加描述性标签。如果未提供值，则取消标题。
- **`tuples_only`** | **`t`** [novalue | on | off] – 如果指定 value，其值必须为 `on` 或 `off`，分别启用或禁用仅元组模式。省略 value 时，命令会在常规输出和仅元组输出之间切换。常规输出包括列标题、表格标题和各种页脚等附加信息。仅元组模式只显示实际表数据。`\t` 命令等同于 `\pset``tuples_only`，提供该命令是为了使用方便。

**提示：**

`\pset` 有多种快捷命令。见 `\a`、`\C`、`\f`、`\H`、`\t`、`\T` 和 `\x`。

**`\q | \quit`**

退出 `psql` 程序。在脚本文件中，此命令仅终止该脚本的执行。

**`\qecho text [ ... ]`**

此命令与 `\echo` 相同，但输出会写入由 `\o` 设置的查询输出通道。

**`\r | \reset`**

重置（清空）查询缓冲区。

**`\s [filename]`**

将 `psql` 的命令行历史打印到 `filename`。如果省略 `filename`，则将历史写入标准输出（适当时使用分页器）。如果构建 `psql` 时未启用 `Readline` 支持，则无法使用此命令。

**`\set [name [value [ ... ]]]`**

将 `psql` 变量 name 设为 value；如果提供了多个值，则将它们连接后赋值。如果只提供一个参数，则仅将变量设为空值。要取消变量设置，请使用 `\unset` 命令。

不带任何参数的 `\set` 会显示当前所有已设置的 `psql` 变量及其值。

有效变量名可以包含字母、数字和下划线。见[高级功能](#advanced-features)中的“变量”。变量名区分大小写。

虽然可以将任意变量设为任意值，但 `psql` 会对某些变量作特殊处理。这些变量在变量主题中说明。

此命令与 SQL 命令 [SET](/cloudberry/reference/sql-stmts/set/) 无关。

**`\setenv name [ value ]`**

将环境变量 name 设为 value；如果未提供值，则取消该环境变量的设置。例如：

```shell
testdb=> \setenv PAGER less
testdb=> \setenv LESS -imx4F
```

**`\sf[+] function_description`**

此命令以 `CREATE OR REPLACE FUNCTION` 命令的形式获取并显示指定函数的定义。定义会打印到由 `\o` 设置的当前查询输出通道。

目标函数可以仅用名称指定，也可以用名称和参数指定，例如 `foo(integer, text)`。如果存在多个同名函数，则必须提供参数类型。

如果在命令名后附加 `+`，则会为输出行编号，函数体的第一行为第 1 行。

**`\t [novalue | on | off]`**

单独使用 `\t` 命令会切换输出列标题和行数页脚的显示状态。值 `on` 和 `off` 可直接设置元组显示方式，不受当前设置影响。此命令等同于 `\pset tuples_only`，提供它是为了使用方便。

**`\T table_options`**

指定 HTML 输出格式中要放入 `table` 标签的属性。此命令等同于 `\pset tableattr table_options`。

**`\timing [novalue | on | off]`**

不带参数时，切换是否显示每条 SQL 语句的耗时，单位为毫秒。值 `on` 和 `off` 可直接设置耗时显示状态，不受当前设置影响。

**`\unset name`**

取消设置（删除）`psql` 变量 name。

**`\w | \write filename`**<br />
**`\w | \write `|` command`**

将当前查询缓冲区输出到文件 filename，或通过管道传给 shell 命令 command。

**`\watch [seconds]`**

反复执行当前查询缓冲区（类似于 `\g`），直到被中断或查询失败。每次执行之间等待指定的秒数（默认为 2 秒）。

**`\x [ on | off | auto ]`**

设置或切换表格的扩展格式模式，等同于 `\pset expanded`。

**`\z [pattern]`**

列出表、视图和序列及其相关访问权限。如果指定了模式，则仅列出名称与该模式匹配的表、视图和序列。这是 `\dp` 的别名。

**`\! [command]`**

转入独立的 shell，或执行 shell 命令 command。不会进一步解释参数；shell 会收到原样参数。具体而言，变量替换规则和反斜杠转义不适用。

**`\?`**

显示 `psql` 反斜杠命令的帮助信息。

## 模式匹配 {#patterns}

各种 `\d` 命令都接受 pattern 参数，用于指定要显示的对象名称。最简单的情况下，模式就是对象的确切名称。模式中的字符通常会转换为小写，与 SQL 名称一样；例如，`\dt FOO` 会显示名为 `foo` 的表。同样，将模式用双引号括起可阻止转换为小写。若需在模式中包含实际的双引号字符，请在双引号序列内写两个连续的双引号；这也符合 SQL 带引号标识符的规则。例如，`\dt "FOO""BAR"` 会显示名为 `FOO"BAR` 的表（而非 `foo"bar`）。与 SQL 名称的常规规则不同，可以只将模式的一部分用双引号括起，例如 `\dt FOO"FOO"BAR` 会显示名为 `fooFOObar` 的表。

在模式中，`*` 匹配任意字符序列（包括空序列），`?` 匹配任意单个字符。（这种表示法类似于 UNIX shell 的文件名模式。）例如，`\dt int*` 显示名称以 `int` 开头的所有表。但在双引号内，`*` 和 `?` 不再具有这些特殊含义，只按字面匹配。

包含点号（`.`）的模式被解释为模式名的匹配模式，后接对象名的匹配模式。例如，`\dt foo*.bar*` 显示表名以 `bar` 开头、所在模式名以 `foo` 开头的所有表。如果没有点号，则只匹配当前模式搜索路径中可见的对象。同样，双引号内的点号会失去特殊含义，只按字面匹配。

高级用户可以使用正则表达式表示法。所有正则表达式特殊字符的行为均遵循 [PostgreSQL 正则表达式文档](https://www.postgresql.org/docs/12/functions-matching.html#FUNCTIONS-POSIX-REGEXP)，但以下字符除外：`.` 按上述规则作为分隔符，`*` 转换为正则表达式 `.*`，`?` 转换为 `..`。如有需要，可以用 `?` 代替 `.,``(R+|)` 代替 `R*`，或用 `(R|)` 代替 `R?`，以模拟这些模式字符。请记住，与正则表达式的常规解释不同，模式必须匹配整个名称；如果不希望模式固定在名称边界，请在开头和／或末尾写上 `*`。注意，在双引号内，所有正则表达式特殊字符都会失去特殊含义，只按字面匹配。此外，在运算符名称模式（如 `\do` 的参数）中，正则表达式特殊字符也按字面匹配。

完全省略 pattern 参数时，`\d` 命令会显示当前模式搜索路径中可见的所有对象，等同于使用模式 `*.`。要查看数据库中的所有对象，请使用模式 `*.*.`。

## 高级功能 {#advanced-features}

### 变量 {#variables}

`psql` 提供类似于常见 UNIX 命令 shell 的变量替换功能。变量只是名称／值对，其中值可以是任意长度的任意字符串。名称必须由字母（包括非拉丁字母）、数字和下划线组成。

要设置变量，请使用 psql 元命令 `\set`。例如，

```shell
testdb=> \set foo bar
```

将变量 `foo` 设为值 `bar`。要获取变量内容，请在名称前加上冒号，例如：

```shell
testdb=> \echo :foo
bar
```

这既适用于普通 SQL 命令，也适用于元命令；详见 [SQL 插值](#sql-interpolation)。

调用 `\set` 时若不带第二个参数，就会将变量设为空字符串。要取消设置（即删除）变量，请使用 `\unset` 命令。要显示所有变量的值，请调用不带参数的 `\set`。

> **注意** `\set` 的参数遵循与其他命令相同的替换规则。因此，可以构造 `\set :foo 'something'` 这样的引用，得到 Perl 或 PHP 中分别称为“软链接”或“变量变量”的结构。遗憾的是，这些结构无法发挥实际用途。不过，`\set bar :foo` 是完全有效的变量复制方式。

`psql` 会对其中一些变量作特殊处理。它们表示某些选项设置，可在运行时通过修改变量值来更改；有时也表示 `psql` 的可变状态。虽然可以将这些变量用于其他用途，但不建议这样做，否则程序行为可能很快变得十分异常。按照惯例，所有特殊处理的变量名都由大写 ASCII 字母（可能还有数字和下划线）组成。为尽可能保证今后的兼容性，请避免为自己的用途使用此类变量名。下文列出所有受到特殊处理的变量。

**`AUTOCOMMIT`**

设为 on（默认值）时，每条 SQL 命令成功完成后都会自动提交。若要在此模式下延迟提交，必须输入 SQL 命令 `BEGIN` 或 `START TRANSACTION`。设为 off 或未设置时，SQL 命令直到显式发出 `COMMIT` 或 `END` 才会提交。autocommit-on 模式的工作方式是在执行符合条件的命令之前，隐式发出 `BEGIN`：该命令尚未处于事务块内，本身不是 `BEGIN` 或其他事务控制命令，也不是不能在事务块内执行的命令（如 `VACUUM`）。

在 autocommit-off 模式下，必须输入 `ABORT` 或 `ROLLBACK` 来显式放弃失败的事务。还应记住，如果退出会话时没有提交，所做的工作会丢失。

autocommit-on 模式是 PostgreSQL 的传统行为，但 autocommit-off 更接近 SQL 规范。如果倾向于使用 autocommit-off，可以在 `~/.psqlrc` 文件中设置。

**`COMP_KEYWORD_CASE`**

决定补全 SQL 关键字时使用的大小写。设为 `lower` 或 `upper` 时，补全的单词分别采用小写或大写。设为 `preserve-lower` 或 `preserve-upper`（默认值）时，补全的单词沿用已输入部分的大小写；但如果尚未输入任何字符，则补全的单词分别采用小写或大写。

**`DBNAME`**

当前连接的数据库名。每次连接数据库时（包括程序启动时）都会设置此变量，但可以取消设置。

**`ECHO`**

设为 `all` 时，所有非空输入行都会在读取时打印到标准输出。（不适用于交互读取的行。）要在程序启动时选择此行为，请使用开关 `-a`。设为 queries 时，`psql` 会在将各查询发送到服务器时将其打印到标准输出，对应开关为 `-e`。

**`ECHO_HIDDEN`**

当此变量设为 `on` 且反斜杠命令查询数据库时，会先显示该查询。此功能有助于学习 Apache Cloudberry 的内部机制，并在自己的程序中提供类似功能。（要在程序启动时选择此行为，请使用开关 `-E`。）若将变量设为 `noexec`，则只显示查询，不会实际发送到服务器并执行。

**`ENCODING`**

当前客户端字符集编码。

**`FETCH_COUNT`**

如果将此变量设为大于 0 的整数，`SELECT` 查询的结果就会按该行数分组获取和显示，而不是采用默认行为，收集整个结果集后再显示。因此，无论结果集多大，都只使用有限的内存。启用此功能时，通常设为 100 到 1000。请注意，使用此功能时，查询可能在已显示部分行之后失败。

虽然此功能可以配合任何输出格式使用，但默认的对齐格式通常显示效果不佳，因为每组 `FETCH_COUNT` 行都会单独格式化，导致各组的列宽不同。其他输出格式效果更好。

**`HISTCONTROL`**

如果将此变量设为 `ignorespace`，则以空格开头的行不会记入历史列表。设为 `ignoredups` 时，与上一条历史记录相同的行不会记入。值 `ignoreboth` 结合了这两个选项。未设置时，或设为上述值之外的其他值时，交互模式下读取的所有行都会保存到历史列表。

**`HISTFILE`**

用于存储历史列表的文件名。默认值为 `~/.psql_history`。例如，将

```shell
\set HISTFILE ~/.psql_history- :DBNAME
```

放入 `~/.psqlrc`，会使 `psql` 为每个数据库分别维护历史记录。

**`HISTSIZE`**

命令历史中保存的命令数。默认值为 500。

**`HOST`**

当前连接的数据库服务器主机。每次连接数据库时（包括程序启动时）都会设置此变量，但可以取消设置。

**`IGNOREEOF`**

未设置时，向 `psql` 的交互会话发送 `EOF` 字符（通常为 `CTRL+D`）会终止应用程序。如果设为数值，则在终止应用程序之前忽略相应数量的 `EOF` 字符。如果设置了该变量但其值不是数值，则默认值为 `10`。

**`LASTOID`**

最后受影响的 OID 值，由 `INSERT` 或 `lo_import` 命令返回。此变量只保证在下一条 SQL 命令的结果显示之前有效。

**`ON_ERROR_ROLLBACK`**

设为 `on` 时，如果事务块中的语句产生错误，会忽略该错误并继续事务。设为 `interactive` 时，仅在交互会话中忽略此类错误，读取脚本文件时不会忽略。未设置或设为 `off` 时，事务块中产生错误的语句会取消整个事务。错误回滚模式的工作方式是在事务块中的每条命令之前，隐式发出 `SAVEPOINT`，并在出错时回滚到该保存点。

**`ON_ERROR_STOP`**

默认情况下，发生错误后仍会继续处理命令。将此变量设为 `on` 后，处理会立即停止。在交互模式下，`psql` 会返回命令提示符；否则，`psql` 会退出并返回错误码 3，以区别于使用错误码 1 报告的致命错误。无论哪种情况，当前正在运行的所有脚本（顶层脚本，如果有，以及它调用的其他脚本）都会立即终止。如果顶层命令字符串包含多条 SQL 命令，则处理会停在当前命令处。

**`PORT`**

当前连接的数据库服务器端口。每次连接数据库时（包括程序启动时）都会设置此变量，但可以取消设置。

**`PROMPT1`**<br />
**`PROMPT2`**<br />
**`PROMPT3`**

这些变量指定 `psql` 提示符的样式。见“提示符”。

**`QUIET`**

将此变量设为 `on` 等同于命令行选项 `-q`。它在交互模式下用途不大。

**`SINGLELINE`**

此变量等同于命令行选项 `-S`。

**`SINGLESTEP`**

将此变量设为 `on` 等同于命令行选项 `-s`。

**`USER`**

当前连接使用的数据库用户。每次连接数据库时（包括程序启动时）都会设置此变量，但可以取消设置。

**`VERBOSITY`**

此变量可设为 `default`、`verbose` 或 `terse`，用于控制错误报告的详细程度。

### SQL 插值 {#sql-interpolation}

`psql` 变量的一项关键功能是可以将其替换（“插值”）到普通 SQL 语句和元命令参数中。此外，`psql` 还提供机制，确保作为 SQL 字面量和标识符使用的变量值得到正确的引号处理。不加引号插入值的语法是在变量名前加冒号（`:`）。例如，

```sql
testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :foo;
```

会查询表 `my_table`。注意，这可能不安全：变量值会按字面复制，因此可能含有不配对的引号，甚至反斜杠命令。必须确保它在插入位置具有合理含义。

当值用作 SQL 字面量或标识符时，最安全的做法是为其加引号。要将变量值作为 SQL 字面量加引号，请在冒号后写上用单引号括起的变量名。要将值作为 SQL 标识符加引号，请在冒号后写上用双引号括起的变量名。这些写法会正确处理变量值内的引号和其他特殊字符。前面的示例更安全的写法如下：

```sql
testdb=> \set foo 'my_table'
testdb=> SELECT * FROM :"foo";
```

变量插值不会在带引号的 SQL 字面量和标识符内进行。因此，`':foo'` 这样的写法无法将变量值转换为带引号的字面量（即便有效也不安全，因为它无法正确处理值内的引号）。

此机制的一种用法是将文件内容复制到表的一列中。先将文件载入变量，再将变量值作为带引号字符串插入：

```sql
testdb=> \set content `cat my_file.txt`
testdb=> INSERT INTO my_table VALUES (:'content');
```

（注意，如果 `my_file.txt` 包含 `NUL` 字节，这种方式仍然无效。`psql` 不支持变量值内嵌 `NUL` 字节。）

由于冒号可以合法地出现在 SQL 命令中，只有指定变量当前已设置时，才会替换看似插值的内容（即 `:name`、`:'name'` 或 `:"name"`）。无论如何，都可以用反斜杠转义冒号，以防止替换。

变量的冒号语法是 ECPG 等嵌入式查询语言所使用的标准 SQL 语法。数组切片和类型转换的冒号语法是 Apache Cloudberry 扩展，有时会与标准用法冲突。使用冒号和引号将变量值转义为 SQL 字面量或标识符的语法，则是 `psql` 扩展。

### 提示符 {#prompting}

可以按个人偏好定制 `psql` 的提示符。`PROMPT1`、`PROMPT2` 和 `PROMPT3` 这三个变量包含字符串和特殊转义序列，用于描述提示符的样式。提示符 1 是常规提示符，在 `psql` 请求新命令时显示。提示符 2 在输入命令过程中仍需更多输入时显示，例如命令未以分号结束，或引号未闭合。提示符 3 则在运行 SQL 命令 `COPY FROM STDIN`、需要在终端输入一行值时显示。

所选提示符变量的值会按字面打印，但遇到百分号（`%`）时除外。此时会根据其后的字符替换为特定文本。定义的替换如下：

**`%M`**

数据库服务器的完整主机名（包括域名）；如果通过 UNIX 域套接字连接，则为 `[local]`；如果 UNIX 域套接字不在编译时指定的默认位置，则为 `[local:/dir/name]`。

**`%m`**

数据库服务器的主机名，在第一个点号处截断；如果通过 UNIX 域套接字连接，则为 `[local]`。

**`%>`**

数据库服务器监听的端口号。

**`%n`**

数据库会话用户名。（在数据库会话中，执行 `SET SESSION AUTHORIZATION` 命令可能改变此值的展开结果。）

**`%/`**

当前数据库的名称。

**`%~`**

类似于 `%/`，但如果该数据库是默认数据库，则输出 `~`（波浪号）。

**`%#`**

如果会话用户是数据库超级用户，则为 **\#**，否则为 **>**。（在数据库会话中，执行 `SET SESSION AUTHORIZATION` 命令可能改变此值的展开结果。）

**`%R`**

在提示符 1 中通常为 `=`，但单行模式下为 `^`，会话与数据库断开连接时则为 `!`（`\connect` 失败时可能发生）。在提示符 2 中，`%R` 替换成的字符取决于 `psql` 仍需更多输入的原因：命令尚未结束时为 `-`，存在未结束的注释时为 `*`（即 `/* ... */` 注释），存在未结束的带引号字符串时为单引号，存在未结束的带引号标识符时为双引号，存在未结束的美元引号字符串时为美元符号，存在未配对的左括号时为 `(`。在提示符 3 中，`%R` 不产生任何内容。

**`%x`**

事务状态：不在事务块内时为空字符串；在事务块内时为 **\***；在失败的事务块内时为 **!**；事务状态不确定时（例如没有连接）为 **?**。

**`%digits`**

替换为指定八进制编码对应的字符。

**`%:name:`**

`psql` 变量 name 的值。详见[高级功能](#advanced-features)中的“变量”。

**``` %`command` ```**

command 的输出，类似于普通的反引号替换。

**`%[ ... %]`**

提示符可包含终端控制字符，例如用于改变提示符文本的颜色、背景或样式，或更改终端窗口标题。为使行编辑正常工作，必须用 `%[` 和 `%]` 将这些不可打印的控制字符括起，标记为不可见。提示符内可以出现多对这样的标记。例如，

```sql
testdb=> \set PROMPT1 '%[%033[1;33;40m%]%n@%/%R%[%033[0m%]%#'
```

在兼容 VT100 且支持颜色的终端上，会产生粗体（`1;`）黑底黄字（`33;40`）的提示符。要在提示符中插入百分号，请写成 `%%`。提示符 1 和 2 的默认值为 `'%/%R%# '`，提示符 3 的默认值为 `'>> '`。

### 命令行编辑 {#command-line-editing}

`psql` 使用 `readline` 库来方便地编辑和检索命令行。`psql` 退出时会自动保存命令历史，`psql` 启动时重新载入。还支持 Tab 补全，但其补全逻辑并不是 SQL 解析器。Tab 补全生成的查询也可能干扰其他 SQL 命令，例如 `SET TRANSACTION ISOLATION LEVEL`。如果由于某种原因不希望使用 Tab 补全，可以将以下内容放入主目录下名为 `.inputrc` 的文件，以关闭该功能：

```shell
$if psql
set disable-completion on
$endif
```

## 环境变量 {#environment}

**`COLUMNS`**

如果 `\pset columns` 为零，则控制折行格式的宽度，以及用于判断宽输出是否需要分页器、或是否应在扩展自动模式下切换为纵向格式的宽度。

**`PAGER`**

如果查询结果无法在屏幕上完整显示，则通过管道传给此命令。典型值为 `more` 或 `less`。默认值取决于平台。可将 PAGER 设为空值，或使用 `\pset` 命令的分页器相关选项来禁用分页器。

**`PGDATABASE`**<br />
**`PGHOST`**<br />
**`PGPORT`**<br />
**`PGUSER`**

默认连接参数。

**`PSQL_EDITOR`**<br />
**`EDITOR`**<br />
**`VISUAL`**

`\e` 和 `\ef` 命令使用的编辑器。按所列顺序检查这些变量，使用第一个已设置的变量。

内置默认编辑器在 Unix 系统上为 `vi`，在 Windows 系统上为 `notepad.exe`。

**`PSQL_EDITOR_LINENUMBER_ARG`**

使用带行号参数的 `\e` 或 `\ef` 时，此变量指定用于向用户编辑器传递起始行号的命令行参数。对于 Emacs 或 `vi` 等编辑器，该参数为加号。如果选项名与行号之间需要空格，请在变量值的末尾加上空格。例如：

```shell
PSQL_EDITOR_LINENUMBER_ARG='+'
PSQL_EDITOR_LINENUMBER_ARG='--line '
```

Unix 系统上的默认值为 `+`（对应默认编辑器 `vi`，也适用于许多其他常见编辑器）；Windows 系统上则没有默认值。

**`PSQL_HISTORY`**

命令历史文件的替代位置。会执行波浪号（`~`）展开。

**`PSQLRC`**

用户 `.psqlrc` 文件的替代位置。会执行波浪号（`~`）展开。

**`SHELL`**

`\!` 命令运行的命令。

**`TMPDIR`**

存储临时文件的目录。默认值为 `/tmp`。

## 文件 {#files}

**`psqlrc and ~/.psqlrc`**

除非传入 `-X` 或 `-c` 选项，否则 `psql` 会在连接数据库之后、接受普通命令之前，先尝试读取并执行系统级启动文件（`psqlrc`）中的命令，再执行用户个人启动文件（`~/.psqlrc`）中的命令。可通过这些文件按需配置客户端和／或服务器，通常使用 `\set` 和 `SET` 命令。

系统级启动文件名为 `psqlrc`，在安装的“系统配置”目录中查找；运行 `pg_config --sysconfdir` 是确定该目录最可靠的方式。默认情况下，此目录相对于 Apache Cloudberry 可执行文件所在目录为 `../etc/`。可通过环境变量 `PGSYSCONFDIR` 显式设置此目录名。

用户个人启动文件名为 `.psqlrc`，在调用用户的主目录中查找。在没有这一概念的 Windows 上，个人启动文件名为 `%APPDATA%\postgresql\psqlrc.conf`。可通过环境变量 `PSQLRC` 显式设置用户启动文件的位置。

系统级启动文件和用户个人启动文件都可以在文件名后附加连字符及底层 PostgreSQL 的主版本号或次版本号，使其专用于某个 psql 版本，例如 `~/.psqlrc-9.4`。会优先读取版本匹配最具体的文件，而不是不区分版本的文件。

**`.psql_history`**

命令行历史存储在 `~/.psql_history` 文件中；Windows 上则为 `%APPDATA%\postgresql\psql_history`。

可通过环境变量 `PSQL_HISTORY` 显式设置历史文件的位置。

## 注意事项 {#notes}

`psql` 与相同或较旧主版本的服务器配合使用时效果最好。如果服务器版本比 `psql` 本身更新，反斜杠命令尤其容易失败。不过，`\d` 系列反斜杠命令应能用于较旧版本的服务器，但不一定适用于比 `psql` 更新的服务器。执行 SQL 命令和显示查询结果等常规功能也应能用于较新主版本的服务器，但无法保证所有情况都有效。

如果要用 `psql` 连接多个不同主版本的服务器，建议使用最新版本的 `psql`。也可以保留各主版本的 `psql`，并确保使用与相应服务器匹配的版本。不过，实践中通常没有必要增加这层复杂性。

## Windows 用户注意事项 {#notes-for-windows-users}

`psql` 是控制台应用程序。由于 Windows 控制台窗口使用的编码与系统其他部分不同，在 `psql` 中使用 8 位字符时必须格外小心。如果 `psql` 检测到有问题的控制台代码页，会在启动时发出警告。要更改控制台代码页，需要完成两项操作：

输入以下命令设置代码页：

```shell
cmd.exe /c chcp 1252
```

`1252` 是拉丁字母的一种字符编码，Microsoft Windows 将其用于英语和其他一些西方语言。如果使用 Cygwin，可以将此命令放入 `/etc/profile`。

将控制台字体设为 Lucida Console，因为点阵字体无法用于 ANSI 代码页。

## 示例 {#examples}

以交互模式启动 `psql`：

```shell
psql -p 54321 -U sally mydatabase
```

在 `psql` 交互模式下，将一个命令分成多行输入。注意提示符的变化：

```sql
testdb=> CREATE TABLE my_table (
testdb(>  first integer not null default 0,
testdb(>  second text)
testdb-> ;
CREATE TABLE
```

查看表定义：

```sql
testdb=> \d my_table
             Table "public.my_table"
 Column    |  Type   |      Modifiers
-----------+---------+--------------------
 first     | integer | not null default 0
 second    | text    |
Distributed by: (first)
```

传入包含 SQL 命令的文件，以非交互模式运行 `psql`：

```shell
psql -f /home/gpadmin/test/myscript.sql
```
