## Физические машины {#physical-machines}

Тип машины GCE n1-highcpu-2

- 1x выделенный локальный SSD, используемый как каталог данных etcd
- 1x выделенный медленный диск для ОС
- 1.8 GB памяти
- 2x CPU

## Кластер etcd {#etcd-cluster}

3 участника etcd 2.2.0, каждый работает на отдельной машине.

Точные версии:

```
etcd Version: 2.2.0
Git SHA: e4561dd
Go Version: go1.5
Go OS/Arch: linux/amd64
```

## Тестирование {#testing}

Запустите ещё одну машину вне кластера etcd и примените [инструмент HTTP-тестирования `hey`](https://github.com/rakyll/hey) с патчем повторного использования соединений для отправки запросов каждому участнику кластера etcd. Патч и шаги для воспроизведения процедуры приведены в [инструкции по тестированию](https://github.com/etcd-io/etcd/tree/v2.3.8/hack/benchmark).

Производительность вычислена по результатам 100 раундов тестирования.

## Изменения производительности {#performance-changes}

- Поскольку etcd теперь записывает метрики для каждого вызова API, в большинстве сценариев QPS чтения немного снизился. Это минимальное влияние на производительность признано разумной платой за широкий набор данных для мониторинга и отладки.

- QPS записи на лидерах кластера немного увеличился. Основной цикл и циклы применения записей были разделены в логике Raft etcd, что устранило несколько блокировок между ними.

- QPS записи на всех участниках значительно увеличился, поскольку последователи теперь раньше получают последний зафиксированный индекс и быстрее фиксируют предложения.
