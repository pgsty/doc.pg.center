Ces entrées conservent l’intégralité de l'historique des modifications upstream pour pgBadger 10.x, du plus récent au plus ancien.

## v10.3 · 2019-02-14 {#v10-3}

Cette version de pgBadger est une mise à jour de maintenance qui corrige certains problèmes de détection automatique du format de journalisation, ainsi qu’un autre problème de lecture des journaux de pgBouncer signalé par les utilisateurs. Une nouvelle fonctionnalité est également disponible :

    The -o | --outfile option can now be used multiple time to dump
    output in several format in a single command. For example:
        pgbadger -o out.html -o out.json /log/pgsql-11.log
    will create two reports in html and json format saved in the
    two corresponding files.

Il existe également quelques corrections de bogues et améliorations de fonctionnalités.

  - Corriger les rapports statistiques lorsque l'on applique un filtre sur la base de données, l'utilisateur, le client ou l'application. Certaines requêtes n'étaient pas rapportées.
  - Corriger la détection automatique du préfixe de ligne de journal par défaut pour pg>=10.
  - Corriger la détection automatique du fichier journal lorsqu'il utilise un préfixe de ligne de journal « non standard ». Si --prefix %t, %m, %n ou %p ou %c est spécifié, définir le format sur stderr. Merci à Alex Danvy pour le signalement.
  - Supprimer l'espace supplémentaire en fin de ligne.
  - Ajouter un test minimal pour le parseur syslog.
  - Corriger un appel à autodetect_format().
  - Tronquer l'instruction lorsque maxlength est utilisé. Merci à Thibaud Madelaine pour le correctif.
  - Ajouter un test pour plusieurs formats de sortie.
  - L'option -o | --outfile peut désormais être utilisée plusieurs fois pour générer plusieurs formats de sortie dans une même commande. Par exemple :
  pgBadger -o out.txt -o out.html -o - -x json /log/pgsql-11.log
  Dans ce cas, pgBadger créera deux rapports au format texte et HTML, sauvegardés dans les fichiers correspondants. Il produira également un rapport au format json sur la sortie standard. Merci à Nikolay pour la demande de fonctionnalité.
  - Déplacer la détection du format de sortie et la définition du nom de fichier de sortie vers une fonction dédiée set_output_extension().
  - Corriger un autre problème de parsing des journaux pgBouncer. Merci à Douglas J. Hunley pour le signalement.

## v10.2 · 2018-12-27 {#v10-2}

Cette version de pgBadger est une mise à jour de maintenance qui corrige les problèmes signalés par les utilisateurs au cours des trois derniers mois. Elle inclut également quelques nouvelles fonctionnalités :

  * Ajouter la prise en charge du format de journal des statistiques pgbouncer 1.8.
  * Ajuster automatiquement l’heure de fuseau horaire des graphiques JavaScript.

Une nouvelle option de ligne de commande est disponible :

  * Ajouter l'option --exclude-db pour générer un rapport sur tout sauf la base de données spécifiée.
  * Ajouter le support du téléchargement distant de fichiers journaux PostgreSQL via http ou ftp.
      Le fichier journal est analysé pendant le téléchargement à l'aide de la commande curl
      et n'est jamais sauvegardé sur le disque. En cas d'analyse distante via ssh, vous pouvez utiliser
      l'URI en tant qu'argument de ligne de commande pour préciser le fichier journal PostgreSQL.
            ssh://localhost/postgresql-10-main.log
            http://localhost/postgresql-10-main.log.gz
            ftp://localhost/postgresql-10-main.log
    
    with http and ftp protocol you need to specify the log file format
    at end of the uri:
    
            http://localhost/postgresql-10-main.log:stderr
    
    You can specify multiple uri for log files to be parsed. This is
    useful when you have pgbouncer log file on a remote host and
    PostgreSQL logs in the local host.

    With ssh protocol you can use wild card too like with remote
    mode, ex: ssh://localhost/postgresql-10-main.log*
    
    Old syntax to parse remote log file using -r option is still
    working but is obsolete and might be removed in future versions.


Il existe également quelques corrections de bogues et améliorations de fonctionnalités.

  - Ajuster la fin de la barre de progression pour les fichiers dont la taille estimée est connue (fichiers compressés bz2 et fichiers distants compressés).
  - Mettre à jour l'année dans le copyright.
  - Ajouter des informations sur la notation URI pour analyser les fichiers journaux distants.
  - Forcer la progression à atteindre 100 % à la fin de l'analyse d'un fichier distant compressé.
  - Extraire les informations sur les appels de fonctions PL/pgSQL présents dans les requêtes des rapports de fichiers temporaires. Ces informations sont ajoutées au bloc d'affichage détaillé.
  - Corriger la barre de progression pour les fichiers CSV.
  - Corriger la lecture d'un fichier binaire comme fichier d'entrée au lieu du fichier journal.
  - Encoder la sortie HTML des requêtes en UTF8 afin d'éviter le message « Wide character in print ». Merci à Colin 't Hart pour le signalement.
  - Ajouter la clé/valeur « distance des points de contrôle » pour la distance maximale.
  - Corriger l'analyse des logs de pgbouncer et les rapports de débit de requêtes. Merci à Levente Birta pour le signalement.
  - Corriger l'utilisation de csvlog au lieu de csv pour le format d'entrée.
  - Ajouter la prise en charge du format de journal pgbouncer 1.8. Merci à Levente Birta pour le signalement.
  - Ajouter un avertissement concernant le traitement parallèle désactivé avec csvlog. Merci à cstdenis pour le signalement.
  - Ajouter des informations dans la sortie d'aide sur le forçage du processus unique avec le format csvlog via les options -j et -J. Merci à cstdenis pour le signalement.
  - Corriger l'erreur « format de ligne inconnu » pour les journaux multilignes lors d'une analyse incrémentale via SSH. Merci à Wooyoung Cho pour le signalement.
  - Ajouter l'option -k (--insecure) à la commande curl afin de pouvoir télécharger des journaux depuis un serveur utilisant un certificat auto-signé.
  - Ajuster automatiquement le fuseau horaire des graphiques JavaScript. Merci à Massimino Sala pour la demande de fonctionnalité.
  - Ajouter la prise en charge du téléchargement des journaux HTTP par pgBadger, par exemple :
        /usr/bin/pgbadger http://www.mydom.com/postgresql-10.log
  - Analyser le fichier pendant son téléchargement à l'aide de la commande curl.
  - Corriger la documentation. Merci à 0xflotus pour le correctif.
  - Reappliquer la correction relative au remplacement des paramètres liés après un nettoyage de code supplémentaire. Merci à Bernhard J. M. Grun pour le signalement.
  - Ajouter l'option --exclude-db pour générer un rapport sur tout sauf la base de données spécifiée. Cette option peut être utilisée plusieurs fois.

## v10.0 · 2018-09-09 {#v10-0}

Cette version de pgBadger est une version majeure qui introduit de nouvelles fonctionnalités et corrige tous les problèmes signalés par les utilisateurs depuis la dernière version.

  * Ajouter le support du format de fichier journal syslog de pgbouncer.
  * Ajouter le support de tous les formats auto_explain (texte, XML, JSON et YAML).
  * Ajouter le support du placeholder %q dans log_line_prefix.
  * Ajouter le format jsonlog de l'extension de Michael Paquier, avec -f jsonlog
    pgBadger pourra parser le fichier journal.
  * Remplacer le formateur SQL/embellisseur par la version 3.0 de pgFormatter.

Une nouvelle option de ligne de commande est disponible :

  - Ajouter l'option en ligne de commande --prettify-json pour formater de manière lisible la sortie JSON.
  - Ajouter l'option en ligne de commande --log-timezone + /-XX pour définir le nombre d'heures par rapport à GMT de la zone horaire à utiliser afin d'ajuster les dates/heure lues dans le fichier journal avant leur analyse. Notez que vous pourriez toutefois devoir ajuster la zone horaire du graphique en utilisant -Z lorsque le client n'utilise pas la même zone horaire.
  - Ajouter l'option --include-time pour permettre de choisir les périodes que vous souhaitez afficher, plutôt que d'exclure toutes les périodes que vous ne souhaitez pas voir (--exclude-time).

Le projet pgBadger et ses droits d'auteur ont été transférés de Dalibo à l'auteur et au mainteneur officiel du projet. Veuillez mettre à jour vos liens :

  - Site web : http://pgbadger.darold.net/
