pgBadger развивается как открытый проект. Сообщения об ошибках, предложения функций, исправления документации и патчи принимаются через репозиторий исходного проекта на GitHub.

## Ошибки и запросы функций {#bugs-and-features}

1. Обновитесь до самой новой выпущенной версии и убедитесь, что проблема сохраняется.
2. Поищите готовый ответ среди [открытых задач](https://github.com/darold/pgbadger/issues) и [закрытых задач](https://github.com/darold/pgbadger/issues?q=is%3Aissue+is%3Aclosed).
3. Сведите проблему к минимальному безопасному фрагменту журнала и командной строке, на которых она всё ещё воспроизводится.
4. Удалите учётные данные, конфиденциальный SQL, значения параметров, имена узлов, адреса и деловые данные.
5. Создайте [новую задачу](https://github.com/darold/pgbadger/issues/new), указав версию pgBadger, операционную систему, формат ввода, точные параметры, наблюдаемый и ожидаемый результаты.

При аварийном завершении или ошибке синтаксического анализатора приложите только минимальный очищенный набор строк журнала, необходимый для воспроизведения условий ошибки. Полный производственный журнал или сгенерированный отчёт почти никогда не следует публиковать в общедоступной задаче.

## Отправка патча {#contribute-a-patch}

Проект содержит файл `.editorconfig`, обеспечивающий единообразные отступы. Если изменение влияет на видимое пользователю поведение, синхронно обновляйте справку команд, POD и сгенерированную документацию Markdown.

В исходном проекте документация обновляется так:

```console
$ perl Makefile.PL
$ make README
```

`doc/pgBadger.pod` — основной развёрнутый источник. Команда `pgbadger --help` формирует краткую справку, а файлы README являются сгенерированными представлениями. Перед отправкой запроса на слияние запустите соответствующие тесты.

- [Репозиторий исходного кода](https://github.com/darold/pgbadger)
- [Запросы на слияние](https://github.com/darold/pgbadger/pulls)
- [Руководство для участников](https://github.com/darold/pgbadger/blob/master/CONTRIBUTING.md)
- [Заметки для разработчиков](https://github.com/darold/pgbadger/blob/master/HACKING.md)

## Коммерческая поддержка {#commercial-support}

Лицензия проекта pgBadger не предусматривает обязательств по сопровождению или поддержке. Для платной помощи с журналированием PostgreSQL, анализом производительности или автоматизацией отчётов обратитесь к [каталогу профессиональных услуг PostgreSQL](https://www.postgresql.org/support/professional_support/).
