يستطيع HAProxy إرسال طلبات HTTP إلى تطبيقات FastCGI من نوع Responder. أُضيفت هذه الميزة في
HAProxy 2.1. للقيام بذلك، يجب إعداد الخوادم لاستخدام بروتوكول FastCGI (باستخدام الكلمة
المفتاحية "proto fcgi" في سطر الخادم)، ويجب إعداد تطبيق FastCGI واستخدامه من قبل الـ backend
الذي يدير هذه الخوادم (باستخدام الكلمة المفتاحية "use-fcgi-app" في قسم الـ proxy). يمكن
تعريف عدة تطبيقات FastCGI، لكن يمكن لـ backend استخدام أحدها فقط في كل مرة.

ينفِّذ HAProxy جميع ميزات مواصفة FastCGI لتطبيقات Responder. وعلى وجه الخصوص فهو قادر على
الإرسال المتعدد لعدة طلبات على اتصال واحد بسيط.

## 10.1. الإعداد {#section-10-1}



### 10.1.1. قسم Fcgi-app {#section-10-1-1}

<a id="entry-10-1-1-fcgi-app"></a>

**`fcgi-app <name>`**

```haproxy
fcgi-app <name>
```

يعلن عن تطبيق FastCGI باسم `<name>`. ليكون صالحًا، يجب تعريف جذر المستندات (document root)
على الأقل.

<a id="entry-10-1-1-acl"></a>

**`acl <aclname> <criterion> [flags] [operator] <value> ...`**

```haproxy
acl <aclname> <criterion> [flags] [operator] <value> ...
```

يعلن عن قائمة وصول أو يكملها.

راجع الكلمة المفتاحية "acl" في [القسم 4.2](/ar/haproxy/proxies/#section-4-2) و[القسم 7](/ar/haproxy/acls-and-samples/)
حول استخدام ACL لمزيد من التفاصيل. قوائم ACL المعرَّفة لتطبيق FastCGI خاصة. لا يمكن
استخدامها من قبل أي تطبيق آخر أو أي proxy. وبالطريقة نفسها، قوائم ACL المعرَّفة في أي قسم
آخر غير قابلة للاستخدام من قبل تطبيق FastCGI. ومع ذلك، تتوفر قوائم ACL معرَّفة مسبقًا.

<a id="entry-10-1-1-docroot"></a>

**`docroot <path>`**

```haproxy
docroot <path>
```

تعرِّف جذر المستندات على المضيف البعيد. سيُستخدم `<path>` لبناء القيمة الافتراضية لمعاملي
FastCGI وهما SCRIPT_FILENAME وPATH_TRANSLATED. إنه إعداد إلزامي.

<a id="entry-10-1-1-index"></a>

**`index <script-name>`**

```haproxy
index <script-name>
```

تعرِّف اسم السكربت الذي سيُلحَق بعد URI ينتهي بشرطة مائلة ("/") لضبط القيمة الافتراضية
لمعامل FastCGI وهو SCRIPT_NAME. إنه إعداد اختياري.

مثال:

```text
index index.php
```

<a id="entry-10-1-1-log-stderr-global"></a>

**`log-stderr global`**

```haproxy
log-stderr global
log-stderr <target> [len <length>] [format <format>]
    [sample <ranges>:<sample_size>] <facility> [<level> [<minlevel>]]
```

يُمكِّن تسجيل رسائل STDERR التي يبلغ عنها تطبيق FastCGI.

راجع الكلمة المفتاحية "log" في [القسم 4.2](/ar/haproxy/proxies/#section-4-2) لمزيد من التفاصيل. إنه إعداد
اختياري. افتراضيًا تُتجاهل رسائل STDERR.

<a id="entry-10-1-1-pass-header"></a>

**`pass-header <name> [ { if | unless } <condition> ]`**

```haproxy
pass-header <name> [ { if | unless } <condition> ]
```

تحدد اسم ترويسة طلب ستُمرَّر إلى تطبيق FastCGI. ويمكن اختياريًا أن تتبعها حالة قائمة على
ACL، وفي هذه الحالة لن تُقيَّم إلا إذا كانت الحالة صحيحة.

معظم ترويسات الطلب متاحة بالفعل لتطبيق FastCGI، مسبوقة بالبادئة "HTTP\_". وعليه، لا يُطلب
هذا التوجيه إلا لتمرير الترويسات المحذوفة عمدًا. حاليًا، ترويسات "Authorization" و
"Proxy-Authorization" والترويسات hop-by-hop هي المحذوفة.

لاحظ أن الترويستين "Content-type" و"Content-length" لا تُمرَّران أبدًا إلى تطبيق FastCGI
لأنهما محوَّلتان بالفعل إلى معاملات.

<a id="entry-10-1-1-path-info"></a>

**`path-info <regex>`**

```haproxy
path-info <regex>
```

تعرِّف تعبيرًا نمطيًا لاستخراج اسم السكربت ومعلومات المسار (path-info) من المسار بعد فك
ترميز URL. وبذلك يمكن لـ `<regex>` أن يحتوي التقاطين: الأول لالتقاط اسم السكربت والثاني
لالتقاط معلومات المسار. الأول إلزامي والثاني اختياري. بهذه الطريقة، من الممكن استخراج اسم
السكربت من المسار مع تجاهل معلومات المسار. إنه إعداد اختياري. وإذا لم يُعرَّف، فلن تُنفَّذ
أي مطابقة على المسار، ولن يُملأ معاملا FastCGI وهما PATH_INFO وPATH_TRANSLATED.

لأسباب أمنية، عندما يُعرَّف هذا التعبير النمطي، يُحظر محرف السطر الجديد والمحرف الفارغ
(null) في المسار بعد فك ترميز URL. وسبب هذا القيد هو أن المطابقة ستفشل دائمًا في غير ذلك
(بسبب قيد في طريقة تنفيذ التعبيرات النمطية في HAProxy). فإذا وُجد أحد هذين المحرفين في
المسار بعد فك ترميز URL، أُعيد خطأ إلى العميل. يُطبَّق هنا مبدأ أقل قدر من الدهشة.

مثال:

```text
path-info ^(/.+\.php)(/.*)?$ # both script-name and path-info may be set
path-info ^(/.+\.php)        # the path-info is ignored
```

<a id="entry-10-1-1-option-get-values"></a>

**`option get-values`**

```haproxy
option get-values
no option get-values
```

يُمكِّن استرجاع المتغيرات المتعلقة بإدارة الاتصال أو يعطّله.

يستطيع HAProxy إرسال السجل FCGI_GET_VALUES عند إنشاء الاتصال لاسترجاع قيمة المتغيرات
التالية:

    * FCGI_MAX_REQS     العدد الأقصى من الطلبات المتزامنة التي سيقبلها هذا
                        التطبيق.

    * FCGI_MPXS_CONNS   "0" إذا كان هذا التطبيق لا يدعم الإرسال المتعدد للاتصالات،
                        "1" فيما عدا ذلك.

بعض تطبيقات FastCGI لا تدعم هذه الميزة. وبعضها الآخر يغلق الاتصال فور إرسال استجابته. لذا،
هذا الخيار معطَّل افتراضيًا.

لاحظ أن العدد الأقصى للطلبات المتزامنة التي يقبلها تطبيق FastCGI هو متغير على مستوى
الاتصال. وهو يحد فقط من عدد التيارات لكل اتصال. إذا كان يجب تحديد الحمل الشامل على
التطبيق، فيجب ضبط معاملي الخادم "maxconn" و"pool-max-conn". بالإضافة إلى ذلك، إذا كان
تطبيق لا يدعم الإرسال المتعدد للاتصالات، يُضبط العدد الأقصى للطلبات المتزامنة تلقائيًا
على 1.

<a id="entry-10-1-1-option-keep-conn"></a>

**`option keep-conn`**

```haproxy
option keep-conn
no option keep-conn
```

يوجِّه تطبيق FastCGI إلى إبقاء الاتصال مفتوحًا أو عدم إبقائه مفتوحًا بعد إرسال استجابة.

إذا عُطِّل، يغلق تطبيق FastCGI الاتصال بعد الاستجابة لهذا الطلب. افتراضيًا، هذا الخيار
ممكَّن.

<a id="entry-10-1-1-option-max-reqs"></a>

**`option max-reqs <reqs>`**

```haproxy
option max-reqs <reqs>
```

تعرِّف العدد الأقصى للطلبات المتزامنة التي سيقبلها هذا التطبيق.

قد تُستبدل قيمة هذا الخيار إذا استُرجع المتغير FCGI_MAX_REQS أثناء إنشاء الاتصال. علاوة
على ذلك، إذا كان التطبيق لا يدعم الإرسال المتعدد للاتصالات، فسيُتجاهل هذا الخيار. تُضبط
افتراضيًا على 1.

<a id="entry-10-1-1-option-mpxs-conns"></a>

**`option mpxs-conns`**

```haproxy
option mpxs-conns
no option mpxs-conns
```

يُمكِّن دعم الإرسال المتعدد للاتصالات أو يعطّله.

قد تُستبدل قيمته إذا استُرجع المتغير FCGI_MPXS_CONNS أثناء إنشاء الاتصال. وهو معطَّل
افتراضيًا.

<a id="entry-10-1-1-set-param"></a>

**`set-param <name> <fmt> [ { if | unless } <condition> ]`**

```haproxy
set-param <name> <fmt> [ { if | unless } <condition> ]
```

يضبط معامل FastCGI ينبغي تمريره إلى هذا التطبيق. يجب أن تتبع قيمته، المعرَّفة بـ `<fmt>`،
قواعد تنسيق السجل المخصص (راجع [القسم 8.2.6](/ar/haproxy/configuration-logging/#section-8-2-6) "تنسيق السجل المخصص"). ويمكن
اختياريًا أن تتبعها حالة قائمة على ACL، وفي هذه الحالة لن تُقيَّم إلا إذا كانت الحالة
صحيحة.

بهذا التوجيه، من الممكن الكتابة فوق قيمة معاملات FastCGI الافتراضية. إذا قُيِّمت القيمة
إلى سلسلة فارغة، تُتجاهل القاعدة. تُقيَّم هذه التوجيهات بترتيب تعريفها.

مثال:

```shell
# PHP only, required if PHP was built with --enable-force-cgi-redirect
set-param REDIRECT_STATUS 200

set-param PHP_AUTH_DIGEST %[req.hdr(Authorization)]
```

### 10.1.2. قسم الـ proxy {#section-10-1-2}

use-fcgi-app `<name>` يعرِّف تطبيق FastCGI المراد استخدامه للـ backend.

الوسائط:

```text
<name>    هو اسم تطبيق FastCGI المراد استخدامه.
```

هذه الكلمة المفتاحية متاحة فقط للـ proxies HTTP ذات قدرة الـ backend وذات خادم FastCGI واحد
على الأقل. ومع ذلك، يمكن خلط خوادم FastCGI بخوادم HTTP. لكن ما لم يكن هناك سبب وجيه لذلك،
فهو غير موصى به (راجع [القسم 10.3](/ar/haproxy/fastcgi/#section-10-3) حول القيود لمزيد من التفاصيل). يمكن
تعريف تطبيق واحد فقط في كل مرة لكل backend.

لاحظ أنه، بمجرد الإشارة إلى تطبيق FastCGI من أجل backend ما، وبحسب الإعداد، قد تُنفَّذ بعض
المعالجة حتى لو لم يُرسَل الطلب إلى خادم FastCGI. فتُقيَّم قواعد ضبط المعاملات أو تمرير
الترويسات إلى تطبيق ما.

### 10.1.3. مثال {#section-10-1-3}

```haproxy
frontend front-http
    mode http
    bind *:80

    use_backend back-dynamic if { path_reg ^/.+\.php(/.*)?$ }
    default_backend back-static

backend back-static
    mode http
    server www A.B.C.D:80

backend back-dynamic
    mode http
    use-fcgi-app php-fpm
    server php-fpm A.B.C.D:9000 proto fcgi

fcgi-app php-fpm
    log-stderr global
    option keep-conn

    docroot /var/www/my-app
    index index.php
    path-info ^(/.+\.php)(/.*)?$
```

## 10.2. المعاملات الافتراضية {#section-10-2}

لتطبيق FastCGI من نوع Responder الغرض نفسه الذي لبرنامج CGI/1.1. في مواصفة CGI/1.1
(RFC3875)، يجب تمرير عدة متغيرات إلى السكربت. لذا يضبطها HAProxy هي وبعض غيرها الشائع
استخدامها في تطبيقات FastCGI. يمكن الكتابة فوق جميع هذه المتغيرات، مع الحذر رغم ذلك.

```text
  +-------------------+-----------------------------------------------------+
  | AUTH_TYPE         | يحدد الآلية التي يستخدمها HAProxy، إن وُجدت،         |
  |                   | لمصادقة المستخدم. عمليًا، لا تُدعم سوى                |
  |                   | آلية المصادقة BASIC.                                |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | CONTENT_LENGTH    | يحتوي على حجم جسم الرسالة المرفق بالطلب.            |
  |                   | ويعني ذلك أن الطلبات ذات الحجم المعروف فقط          |
  |                   | تُعتبر صالحة وتُرسل إلى التطبيق.                      |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | CONTENT_TYPE      | يحتوي على نوع جسم الرسالة المرفق بالطلب.            |
  |                   | قد لا يكون مضبوطًا.                                  |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | DOCUMENT_ROOT     | يحتوي على جذر المستندات على المضيف البعيد الذي      |
  |                   | ينبغي تنفيذ السكربت تحته، كما هو معرف في            |
  |                   | تهيئة التطبيق.                                      |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | GATEWAY_INTERFACE | يحتوي على لهجة CGI التي يستخدمها HAProxy            |
  |                   | للتواصل مع تطبيق FastCGI.                           |
  |                   | عمليًا، يُضبط على "CGI/1.1".                          |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | PATH_INFO         | يحتوي على الجزء من هرمية مسار URI التالي            |
  |                   | للجزء الذي يحدد السكربت نفسه.                       |
  |                   | ليُضبط، يجب تعريف التوجيه "path-info".               |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | PATH_TRANSLATED   | إذا ضُبط PATH_INFO، فهذه نسخته المترجمة،             |
  |                   | وهي ناتج وصل DOCUMENT_ROOT بـ                       |
  |                   | PATH_INFO. إذا لم يضبط PATH_INFO، فهذا المعامل      |
  |                   | لا يضبط كذلك.                                       |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | QUERY_STRING      | يحتوي على سلسلة الاستعلام الخاصة بالطلب. قد لا      |
  |                   | يكون مضبوطًا.                                        |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | REMOTE_ADDR       | يحتوي على عنوان الشبكة للعميل المرسل                |
  |                   | للطلب.                                              |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | REMOTE_USER       | يحتوي على سلسلة تعريف المستخدم التي يقدمها          |
  |                   | العميل ضمن مصادقة المستخدم.                         |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | REQUEST_METHOD    | يحتوي على الطريقة التي ينبغي أن يستخدمها            |
  |                   | السكربت لمعالجة الطلب.                              |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | REQUEST_URI       | يحتوي على URI الخاص بالطلب.                         |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SCRIPT_FILENAME   | يحتوي على المسار المطلق للسكربت، وهو ناتج وصل       |
  |                   | DOCUMENT_ROOT بـ SCRIPT_NAME.                       |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SCRIPT_NAME       | يحتوي على اسم السكربت. إذا عُرِّف التوجيه              |
  |                   | "path-info"، فهو الجزء الأول من هرمية مسار          |
  |                   | URI، المنتهي باسم السكربت. وإلا فهو مسار            |
  |                   | URI بأكمله.                                         |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SERVER_NAME       | يحتوي على اسم مضيف الخادم الموجَّه إليه طلب           |
  |                   | العميل. وهو قيمة الترويسة "Host" إن كانت            |
  |                   | معرفة، وإلا فهو عنوان الوجهة للاتصال في             |
  |                   | جانب العميل.                                        |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SERVER_PORT       | يحتوي على منفذ TCP الوجهة للاتصال في جانب           |
  |                   | العميل، وهو المنفذ الذي اتصل به العميل.             |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SERVER_PROTOCOL   | يحتوي على بروتوكول الطلب.                           |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | SERVER_SOFTWARE   | يحتوي على السلسلة "HAProxy" متبوعة بإصدار           |
  |                   | HAProxy الحالي.                                     |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
  | HTTPS             | يُضبط على قيمة غير فارغة ("on") إذا جرى الاستعلام    |
  |                   | عن السكربت عبر بروتوكول HTTPS.                      |
  |                   |                                                     |
  +-------------------+-----------------------------------------------------+
```

## 10.3. القيود {#section-10-3}

للتنفيذ الحالي بعض القيود. أولها يتعلق بالطريقة التي تُخفى بها بعض ترويسات الطلب عن تطبيقات
FastCGI. يحدث هذا أثناء تحليل الترويسات، في جانب الـ backend، قبل إنشاء الاتصال. في هذه
المرحلة، يعرف HAProxy أن الـ backend يستخدم تطبيق FastCGI لكنه لا يعرف ما إذا كان الطلب
سيُوجَّه إلى خادم FastCGI أم لا. لكنه لإخفاء ترويسات الطلب، يكتفي بإزالتها من رسالة HTX.
فإذا وُجِّه الطلب في النهاية إلى خادم HTTP، فلن يرى هذه الترويسات أبدًا. لهذا السبب، لا
يُوصى بخلط خوادم FastCGI وخوادم HTTP تحت الـ backend نفسه.

وبالمثل، تُقيَّم القاعدتان "set-param" و"pass-header" أثناء تحليل ترويسات الطلب. لذا يُنفَّذ
التقييم دائمًا، حتى لو أُعيد توجيه الطلب في النهاية إلى خادم HTTP.

بخصوص قواعد "set-param"، عند تطبيق قاعدة ما، تُضاف ترويسة زائفة (pseudo header) إلى رسالة
HTX. لذا، وبالطريقة نفسها كما في إعادة كتابة ترويسات HTTP، قد يفشل ذلك إذا كان المخزن
المؤقت ممتلئًا. وستتنافس قواعد "set-param" مع قواعد "http-request".

أخيرًا، تُرسَل جميع معاملات FastCGI وترويسات HTTP في سجل فريد هو FCGI_PARAM. يجب أن يتم
ترميز هذا السجل في تمريرة واحدة، وإلا أُعيد خطأ معالجة. ويعني ذلك أن السجل FCGI_PARAM، بعد
ترميزه، يجب ألا يتجاوز حجم مخزن مؤقت. ومع ذلك، لا توجد مساحة احتياطية يجب مراعاتها هنا.
