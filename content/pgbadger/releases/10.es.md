## v10.3 · 2019-02-14 {#v10-3}

Esta versión de pgBadger es una versión de mantenimiento que corrige algunos
problemas de autodetección del formato de registro y otro problema de análisis del registro
de pgBouncer reportados por los usuarios. También hay una funcionalidad nueva:

    La opción -o | --outfile ahora se puede usar varias veces para volcar la
    salida en varios formatos en un solo comando. Por ejemplo:
        pgbadger -o out.html -o out.json /log/pgsql-11.log
    creará dos informes en formato html y json guardados en los
    dos archivos correspondientes.

También hay algunas correcciones de errores y mejoras de funcionalidades.

  - Corregir los informes de estadísticas cuando se solicita un filtro por base de datos, usuario,
    cliente o aplicación. Algunas consultas no se
    reportaban.
  - Corregir la autodetección del prefijo de línea de registro predeterminado de pg>=10.
  - Corregir la autodetección del archivo de registro con un prefijo de línea de registro «no estándar».
    Si --prefix especifica %t, %m, %n y %p o %c, establecer el formato en stderr.
    Gracias a Alex Danvy por el informe.
  - Eliminar el espacio extra al final de la línea.
  - Añadir una prueba mínima al analizador syslog.
  - Corregir una llamada a autodetect_format().
  - Truncar la sentencia cuando se usa maxlength. Gracias a Thibaud
    Madelaine por el parche.
  - Añadir una prueba para múltiples formatos de salida.
  - La opción -o | --outfile ahora se puede usar varias veces para volcar la
    salida en varios formatos en un solo comando. Por ejemplo:
      pgbadger -o out.txt -o out.html -o - -x json /log/pgsql-11.log
    Aquí pgbadger creará dos informes en formato texto y html
    guardados en los dos archivos correspondientes. También emitirá un informe
    json en la salida estándar. Gracias a Nikolay por la solicitud
    de funcionalidad.
  - Mover la detección del formato de salida y el establecimiento del nombre del archivo de salida a
    una función dedicada set_output_extension().
  - Corregir otro problema de análisis del registro de pgBouncer. Gracias a Douglas J.
    Hunley por el informe.

## v10.2 · 2018-12-27 {#v10-2}

Esta versión de pgBadger es una versión de mantenimiento que corrige problemas
reportados por los usuarios durante los últimos tres meses. También hay algunas
funcionalidades nuevas:

  * Añadir compatibilidad con el formato de registro de estadísticas de pgbouncer 1.8.
  * Ajustar automáticamente la zona horaria de los gráficos javascript.

Hay una opción nueva de línea de comandos:

  * Añadir la opción --exclude-db para calcular un informe sobre todo excepto
    la base de datos especificada.
  * Añadir compatibilidad con la descarga remota de archivos de registro de PostgreSQL por http o ftp.
    El archivo de registro se analiza durante la descarga usando el comando curl
    y nunca se guarda en el disco. Con el análisis remoto de registros por ssh puedes usar
    un uri como argumento de línea de comandos para especificar el archivo de registro de PostgreSQL.

            ssh://localhost/postgresql-10-main.log
            http://localhost/postgresql-10-main.log.gz
            ftp://localhost/postgresql-10-main.log

    con los protocolos http y ftp debes especificar el formato del archivo de registro
    al final del uri:

            http://localhost/postgresql-10-main.log:stderr

    Puedes especificar múltiples uri para los archivos de registro que se van a analizar. Esto es
    útil cuando tienes el archivo de registro de pgbouncer en un host remoto y
    los registros de PostgreSQL en el host local.

    Con el protocolo ssh también puedes usar comodines como en el modo
    remoto, p. ej.: ssh://localhost/postgresql-10-main.log*

    La sintaxis antigua para analizar archivos de registro remotos usando la opción -r sigue
    funcionando, pero está obsoleta y podría eliminarse en versiones futuras.


También hay algunas correcciones de errores y mejoras de funcionalidades.

  - Ajustar el final de la barra de progreso con archivos de tamaño estimado (archivos
    comprimidos bz2 y archivos remotos comprimidos.

  - Añadir información sobre la notación URI para analizar archivos de registro remotos.
  - Forzar que el progreso alcance el 100% al final del análisis de un archivo
    remoto comprimido.
  - Extraer información sobre llamadas a funciones PL/pgSQL en las consultas de
    los informes de archivos temporales. La información se añade al bloque
    de visualización de detalles.
  - Corregir la barra de progreso con archivos csv.
  - Corregir la lectura de un archivo binario como archivo de entrada en lugar de un archivo de registro.
  - Codificar la salida html de las consultas en UTF8 para evitar el mensaje "Wide
    character in print". Gracias a Colin 't Hart por el informe.
  - Añadir la clave/valor de distancia de checkpoints para el pico de distancia.
  - Corregir el análisis de pgbouncer y los informes de rendimiento de solicitudes. Gracias
    a Levente Birta por el informe.
  - Corregir el uso de csvlog en lugar de csv como formato de entrada.
  - Añadir compatibilidad con el formato de registro de estadísticas de pgbouncer 1.8. Gracias a Levente
    Birta por el informe.
  - Añadir una advertencia sobre el procesamiento en paralelo desactivado con csvlog. Gracias
    a cstdenis por el informe.
  - Añadir información en la salida de uso sobre el forzado de un solo proceso con el
    formato csvlog en las opciones -j y -J. Gracias a cstdenis por el
    informe.
  - Corregir el error de formato de línea desconocido para registros multilínea durante el análisis
    incremental por ssh. Gracias a Wooyoung Cho por el informe.
  - Añadir la opción -k (--insecure) al comando curl para poder descargar
    registros de un servidor que usa un certificado autofirmado.
  - Ajustar automáticamente la zona horaria de los gráficos javascript. Gracias a Massimino Sala
    por la solicitud de funcionalidad.
  - Añadir compatibilidad con la descarga de archivos de registro por HTTP en pgBadger, por ejemplo:
        /usr/bin/pgbadger http://www.mydom.com/postgresql-10.log
  - Analizará el archivo durante la descarga usando el comando curl.
  - Corregir la documentación. Gracias a 0xflotus por el parche.
  - Reaplicar la corrección del reemplazo faltante de los parámetros de enlace tras una

  - Añadir la opción --exclude-db para calcular un informe sobre todo excepto
    la base de datos especificada. La opción se puede usar varias veces.

## v10.0 · 2018-09-09 {#v10-0}

Esta versión de pgBadger es una versión mayor que añade algunas funcionalidades
nuevas y corrige todos los problemas reportados por los usuarios desde la última versión.

  * Añadir compatibilidad con el formato de archivo de registro syslog de pgbouncer.
  * Añadir compatibilidad con todos los formatos de auto_explain (text, xml, json y yaml).
  * Añadir compatibilidad con el marcador %q en log_line_prefix.
  * Añadir el formato jsonlog de la extensión de Michael Paquier; con -f jsonlog
    pgbadger podrá analizar el registro.
  * Reemplazar el formateador/embellecedor SQL por la versión 3.0 de pgFormatter.

Hay algunas opciones nuevas de línea de comandos:

  - Añadir la opción de línea de comandos --prettify-json para embellecer la salida JSON.
  - Añadir la opción de línea de comandos --log-timezone  +/-XX  para establecer el número
    de horas respecto a GMT de la zona horaria que debe usarse para ajustar
    la fecha/hora leída del archivo de registro antes de analizarla. Ten en cuenta que
    podrías seguir necesitando ajustar la zona horaria de los gráficos con -Z cuando el
    cliente no tenga la misma zona horaria.
  - Añadir la opción --include-time para poder elegir los horarios que
    quieres ver, en lugar de excluir todos los que no
    quieres ver (--exclude-time).
