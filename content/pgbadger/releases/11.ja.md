## v11.8 · 2022-04-08 {#v11-8}

pgBadger のこのリリースでは、過去 3 か月以降にユーザーから報告されたいくつかの問題が修正され、特に増分モードでの新しいログ エントリの検出に関する 2 つの修正が行われています。

  * log_line_prefix でミリ秒 (%m) またはエポック (%n) が使用された場合のタイムスタンプ付きの新しいログ エントリの検出を修正します。
  * マルチプロセスが使用されていない場合のローカル ファイル内の新しいログ エントリの検出を修正しました。

変更と謝辞の完全な一覧は次のとおりです。

  - 準備されたクエリの名前に「:」文字が含まれている場合の解析の問題を修正します。 aleszeleny さん、レポートありがとうございます。
  - ミリ秒 (%m) またはエポック (%n) のタイムスタンプを持つ新しいログ エントリの検出を修正します。 aleszeleny さん、レポートありがとうございます。
  - マルチプロセスが使用されていない場合のローカル ファイル内の新しいログ エントリの検出を修正しました。 aleszeleny さん、レポートありがとうございます。
  - SSH を介したリモート ファイル内の新しいログ エントリの検出を修正します。ルカ・フェラーリのレポートに感謝します
  - 「ユーザーごとの接続数」レポートのユーザー名の文字化けを修正しました。 caseyandgina さん、レポートありがとうございます。
  - URI を使用するときに ssh オプションが欠落していた ssh コマンドを修正しました。ルカ・フェラーリさん、レポートありがとうございます。
  - Handle クエリ ID %Q プレースホルダー。パッチを提供してくれた Adrien Nayrat に感謝します。
  - エラー文のタイプミスを修正しました。パッチを提供してくれた Luca Ferrari に感謝します
  - レポート メッセージ: イベント レポートの「サーバー プロセスはシグナルによって終了しました」。レポートを提供してくれた Avi Vallarapu に感謝します。

  - t/04_advanced.t: syslog テストを修正しました。パッチを提供してくれた Christoph Berg に感謝します。

## v11.7 · 2022-01-23 {#v11-7}

pgBadger のこのリリースでは、過去 5 か月以降にユーザーから報告されたいくつかの問題が修正され、いくつかの改善が行われています。

* 新しいオプション --no-progressbar オプションを追加して、表示せずに他の出力を保持します。
* 指定した日の HTML レポートを再構築するために使用できる新しいオプション --day-report を追加します。オプション --month-report と似ていますが、1 日のみです。これには、増分出力ディレクトリと、必要なすべてのバイナリ データ ファイルが存在することが必要です。値は、YYYY-MM-DD 形式の日付です。
* Heraku logplex および Cloudsql json ログの解析を改善します。

変更と謝辞の完全な一覧は次のとおりです。

- コントリビューション ガイドラインと Makefile.PL を更新して、一貫性、明確さ、依存関係を改善します。パッチを提供してくれた拡散者に感謝します。
- バイナリ モードでの最後の解析ファイル (--last-parsed) の使用を修正しました。報告してくれたwibrtさんに感謝します。
- --last-parsed 使用の回帰テストを追加し、一時ファイルのみのレポートの回帰テストを修正しました。
- ホストごとのセッションのグラフのタイトルを修正しました。 Norbert Bede さんのレポートに感謝します。
- --iso-week-number および --incremental オプションが有効になっている場合に週レポートを計算するときの週番号を修正します。 hansgv さん、レポートありがとうございます。
- --no-progressbar オプションを追加して、これを表示せずに他の出力を保持します。機能リクエストをくださったseidlmicさんに感謝します。
- 複数行の jsonlog のデバッグ モードで不明な形式の行が大量に出力されるのを防ぎます。
- 単一行のcloudsql jsonログの解析を修正しました。レポートを提供してくれた Thomas Leclare に感謝します。
- log_temp_files のみを使用して一時ファイルの概要を修正します。
- -q または --quiet が使用されている場合でも、-v を使用してデバッグ メッセージを出力します。
- jsonlog ファイルの自動検出を修正しました。
- cloudsql ログ ファイルの解析を修正しました。 Luc Lamarle さんのレポートに感謝します。
- parse_json_input での PID 抽出を修正します。パッチを提供してくれた Francois Scala に感謝します。
- 新しいオプション --day-report を追加し、値を YYYY-MM-DD 形式の日付として指定します。これは、指定した日の HTML レポートを再構築するために使用できます。機能リクエストをくださった Thomas Leclaire に感謝します。
- 進行状況バーのクエリカウンターを修正しました。レポートを提供してくれた Guillaume Lelarge に感謝します。
- トップバインド用に保存された不完全なクエリを修正し、レポートを準備します。
- オブジェクト識別子の正規化を修正しました。数値が ? に置き換えられる場合がありました。
- 先頭にコメントがある場合の、フォーマットされていない正規化されたクエリを修正します。
- --dbname を使用する場合の標準エラー出力形式の複数行を修正しました。レポートを提供してくれた Guillaume Lelarge に感謝します。
- --dbname の使用時に増分モードでレポートが生成されない問題を修正しました。レポートを提供してくれた Dudley Perkins に感謝します。
- バイナリ ファイルに互換性がない場合でも、もう死ぬことはなく、次のファイルに切り替えます。提案してくれた Thomas Leclare に感謝します。
- pgbadger パーサーにおける Heroku logplex 形式の変更を修正しました。レポートを提供してくれた François Pietka に感謝します。

## v11.6 · 2021-09-04 {#v11-6}

pgBadger のこのリリースでは、過去 7 か月以降にユーザーから報告されたいくつかの問題が修正され、いくつかの改善が加えられています。

  * PG14 の新しい log_line_prefix にクエリ ID の検出を追加します。 Florent Jardin さん、レポートありがとうございます。
  * データベースの除外と分解機能を備えた高度な回帰テストを追加します。パッチを提供してくれた MigOps Inc に感謝します。
  * --explode を使用する場合、レポート生成にマルチプロセスを適用します。パッチについては MigOps Inc、機能リクエストについては Thomas Leclaire に感謝します。
  * 増分モードで --iso-week-number を追加します。カレンダーの週は月曜日から始まり、ISO 8601 の週番号が考慮されます。範囲は 01 から 53 までです。ここで、1 週は、新年の少なくとも 4 日がある最初の週です。機能リクエストをくださった Alex Muntada に感謝します。
  * コマンド ライン オプション --keep-comments を追加して、正規化されたクエリからコメントを削除しないようにします。同じ正規化されたクエリを区別したい場合に便利です。機能リクエストをくださった Stefan Corneliu Petrea に感謝します。
  * サードパーティ ソフトウェアによって PostgreSQL ログ ファイルに導入された INFO 行をスキップします。レポートを提供してくれた David Piscitelli に感謝します。
  * ステートメント期間に続く行数とバイト単位のサイズを含む PostgresPro ログ ファイルとの互換性を追加します。 panatamann さん、レポートありがとうございます。
  * T を使用して時間を解析し、journalctl からのタイムスタンプを使用できるようにします。パッチを提供してくれた Graham Christensen に感謝します。
  * Windows ポートを改善します。パッチを提供してくれた Bertrand Bourgier に感謝します。

重要な注意事項:

  * 次のメジャー リリースでは --iso-week-number がデフォルトになり、週は常に月曜日から始まるため、--start-monday オプションが削除されることが予想されます。コードを簡素化するために、週レポートを日曜日から開始する可能性は削除されます。

## v11.5 · 2021-02-18 {#v11-5}

pgBadger のこのリリースでは、過去 3 か月以降にユーザーから報告されたいくつかの問題が修正され、いくつかの改善が加えられています。

  * セッションのアイドル時間のレポートを追加しました。次の式で計算します。
        "total sessions time - total queries time / number of sessions
    正確な値を得るには、log_connectionとログの切断記録を有効にし、log_min_duration_statement = 0としてすべてのクエリーを記録する必要があります。これにより、アイドル時間の損失量や、プーラーのトランザクションモードが有効かどうかを判断できます。このレポートは「Global Stats」の「Sessions」タブと、「General Activity」レポートの「Sessions」タブ（時間帯別）で利用できます。
  * 数値の匿名化を追加し、4 乱数に置き換えます。
  * pgFormatter 5.0 に基づいて SQL ビューティファイアーを更新します。

変更と謝辞の完全な一覧は次のとおりです。

  - cloudsql の複数行ステートメントの解析を修正しました。ジョンヨンさん、レポートありがとうございます。
  - 匿名化のための回帰テストを追加します。
  - maxlength truncate によって壊れた匿名化を修正しました。 artlさん、レポートありがとうございます。
  - 時間のかかるレポートの作成とバインドにパラメータの匿名化を追加します。報告してくれたarltさんに感謝します。
  - logplex ログ行プレフィックスにマイクロ秒のサポートを追加します。レポートを提供してくれた Ross Gardiner に感謝します。
  - セッションのアイドル時間に関するレポートを追加します。機能リクエストをくださった Guillaume Lelarge に感謝します。
  - jsonlog 形式の複数行をサポートするための完全なパッチ。

## v11.4 · 2020-11-24 {#v11-4}

pgBadger のこのリリースでは、過去 4 か月以降にユーザーから報告されたいくつかの問題が修正されています。 PostgreSQL 13 ログ情報のサポートを改善し、いくつかの新機能を追加します。

  * 「テーブルごとのバキューム」レポートに、バッファ使用量 (ヒット、ミス、ダーティ)、ピンによるスキップ、凍結スキップ、および WAL 使用量 (レコード、フル ページ イメージ、バイト) に関する完全な自動バキューム情報を追加します。 「テーブルごとに削除されたタプル」レポートでは、追加の自動バキューム情報として、残っているタプル、まだ削除されていないタプル、および残っているページが表示されます。これらの情報は、「テーブル」タブでのみ利用できます。
  * チェックポイント開始原因に関する新しい再パーティション レポートを追加します。
  * 接続許可トレースからアプリケーション名の検出を追加します。

変更と謝辞の完全な一覧は次のとおりです。

  - エラー メッセージのタイプミスを修正しました。パッチを提供してくれた Vidar Tyldum に感謝します。
  - Windows移植版で「can not load incompatible binary data」エラーが発生する問題を修正しました。報告してくださったEric Brawnerに感謝します。
  - pgbadger の使用法とドキュメントのオプション --html-outdir のタイプミスを修正します。パッチを提供してくれた Vidar Tyldum に感謝します。
  - jsonlog/cloudsql 形式の自動検出を修正しました。ジョンヨンさん、レポートありがとうございます。
  - PG v13 による CSV ログ解析を修正しました。レポートについては Kanwei Li 氏、パッチについては Kaarel Moppel に感謝します。
  - ほとんどの一時ファイル レポートを生成するクエリの種類を修正しました。レポートを提供してくれた Sebastien Lardiere に感謝します。
  - デバッグ モードで pgbadger バージョン トレースを追加します。

## v11.3 · 2020-07-26 {#v11-3}

pgBadger のこのリリースでは、過去 4 か月以降にユーザーから報告されたいくつかの問題が修正されています。また、いくつかの新機能と新しいコマンド ライン オプションも追加されます。

  * グラフにタイムゾーンが適用されないように、UTC タイムスタンプの自動検出を追加します。
  * GCP CloudSQL json ログ形式へのサポートを追加します。
  * 新しいオプション --dump-all-queries を追加して、pgBadger を使用してすべてのクエリをテキスト ファイルにダンプします。レポートは生成されず、PostgreSQL ログで見つかったステートメントの完全なリストのみが生成されます。バインド パラメータはクエリのそれぞれの位置に挿入されます。
  * 新しいオプションを追加 -Q | --query-numbering は、オプション --dump-all-queries または --normalized-only. を使用するときに出力にクエリの番号を追加するために使用されます。
  * 新しいコマンド ライン オプション --tempdir を追加して、一時ファイルが書き込まれるディレクトリを設定します。 /tmp. への書き込みが許可されていないシステムで役立つ可能性があります
  * デフォルトの22以外のSSHポートを設定する--ssh-portコマンドラインオプションを追加しました。URI表記でも、次の形式でSSHポートを指定できます。
        ssh://192.168.1.100:2222//var/log/postgresql-11.log

変更と謝辞の完全な一覧は次のとおりです。

  - jsonlog/cloudsql ログ形式の増分レポートを修正しました。レポートを提供してくれた Ryan DeShone に感謝します
  - UTC タイムスタンプの自動検出を追加して、自動検出されたタイムゾーンがグラフに適用されないようにします。 UTC 時間を使用すると、JavaScript はローカル タイムゾーンを適用します。レポートを提供してくれた Brett Stauner に感謝します。
  - journalctl ログの増分解析が 2 回目の実行以降機能しない問題を修正しました。パッチを提供してくれた Paweł Koziol に感謝します。
  - -X および -E を使用する場合のリソース ファイルへのパスを修正します。レポートを提供してくれた Ryan DeShone に感謝します。
  - 読み取り/書き込みクエリに関する一般アクティビティ レポートを修正しました。 alexandre-sk5 さん、レポートありがとうございます。
  - パラレル モードが使用されていない場合のデバッグ メッセージを追加します。
  - ファイル サイズ検出の elsif ロジックと、--since オプションが追加されたときにjournalctl コマンドに導入される追加スペースを修正します。パッチを提供してくれた Pawel Koziol に感謝します。
  - 「not a valid file descriptor」エラーを修正しました。報告してくださったPawel Koziolに感謝します。
  - RDS ファイルによるインクリメンタル モードを修正します。レポートを提供してくれた Ildefonso Camargo、nodje、John Walsh に感謝します。
  - 新しいオプションを追加 -Q | --query-numbering は、オプション --dump-all-queries または --normalized-only. を使用するときに出力にクエリの番号を追加するために使用されます。これは、外部スクリプトから出力ファイル内の複数行のクエリを抽出するのに役立ちます。機能リクエストをいただいた Shantanu Oak に感謝します。

        pgbadger -I -O "/out-dir/data" --noreport /var/log/postgresql*.log
    
「/out-dir/data」にデータ バイナリ ファイルを作成するだけで、たとえば、別のディレクトリ `/out-dir/reports` に翌日のレポートを毎晩作成できます。
        pgbadger -I -l "/out-dir/data/LAST_PARSED" -H "/out-dir/reports" /out-dir/data/2020/02/19/*.bin
    
    これには、最後に解析された情報へのパス、HTML レポートが書き込まれるパス、およびその日のバイナリ データ ファイルを設定する必要があります。

新しいコマンド ライン オプションもあります。

  * グラフィカル Explain ツールの URL をオーバーライドするために使用される新しいコマンド ライン オプション --explain-url を追加します。デフォルトの URL は次のとおりです。
        http://explain.depesz.com/?is_public=0&is_anon=0&plan=
    
    PgExplain または他のツールのローカル インストールを使用する場合。 pgBadger は、URL の最後にエスケープされたテキスト形式でプランを追加します。

  * 新しいオプション --no-week を追加して、増分モードで週次レポートを作成しないように pgbadger に指示します。時間とリソースがかかりすぎる場合に役立ちます。

  * 新しいコマンド ライン オプション --command を追加して、pgBadger が標準入力のログ エントリを取得するために実行するコマンドを設定できるようにします。 pgBadger はコマンドへのパイプを開き、コマンドによって生成されたログ エントリを解析します。たとえば:
      pgbadger -f stderr --command 'cat /var/log/postgresql.log'
    
    これは、ログ ファイルを引数として直接指定して pgbadger を実行するのと同じです。このオプションの利点は、ログ ファイルをオンザフライで変更する必要がある場合、またはログ エントリがプログラムから抽出されるかデータベースから生成される場合に明らかです。例えば：

      pgbadger -f csv --command 'psql dbname -c "COPY jrn_log TO STDOUT (FORMAT CSV)"'
    
  * 新しいコマンド ライン オプション --noexplain を追加して、pgBadger が auto_explain 拡張機能によってログに書き込まれた Explain プランを解析して報告しないようにします。これは、PostgreSQL バージョン < 9.0 で、ログに説明プランがあるときに pgBadger が壊れたレポートを生成する場合に便利です。

下位互換性:

  - デフォルトでは、pgBadger はクエリを 100000 文字まで切り捨てます。この任意の値は、オプション --maxlength. を使用して調整できます。以前の動作ではクエリが切り捨てられませんでしたが、これにより過剰なリソースが使用される可能性がありました。デフォルトのサイズを制限する方が安全であり、サイズ制限により、ほとんどの場合、切り捨てが許可されない可能性があります。ただし、クエリが 25000 文字を超える場合、クエリは整形されません。
