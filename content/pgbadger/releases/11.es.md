## v11.8 · 2022-04-08 {#v11-8}

Esta versión de pgBadger corrige algunos problemas reportados por los usuarios durante los
últimos tres meses y, en especial, dos correcciones en la detección de nuevas entradas
de registro en modo incremental.

    epoch (%n) en log_line_prefix.

## v11.5 · 2021-02-18 {#v11-5}

últimos tres meses, así como algunas mejoras:

        "(total sessions time - total queries time) / number of sessions"
    Esto requiere que log_connections y log_disconnections hayan estado

    y en la pestaña "Sessions" de los informes "General Activity" (por hora).
  * Añadir el anonimizado de los valores numéricos, reemplazados por 4 dígitos aleatorios.
  * Actualizar el embellecedor SQL basado en pgFormatter 5.0.

## v11.2 · 2020-03-11 {#v11-2}

Esta versión de pgBadger corrige varios problemas reportados por los usuarios durante los
últimos seis meses. También añade algunas funcionalidades nuevas:

  * Añadir compatibilidad y autodetección del formato de registro de AWS redshift.
  * Añadir compatibilidad con el nuevo formato de registro de pgbouncer 1.11.
  * Manejar los formatos de compresión zstd y lz4
  * Permitir separar por completo la construcción de estadísticas y la construcción del informe HTML en
    modo incremental sin tener que leer un archivo de registro. Por ejemplo,
    es posible ejecutar pgbadger cada hora de la siguiente manera:

        pgbadger -I -O "/out-dir/data" --noreport /var/log/postgresql*.log

    Esto solo crea los archivos binarios de datos en "/out-dir/data" y luego,
   por ejemplo, puedes generar los informes cada noche para el día siguiente en
   un directorio separado `/out-dir/reports`:

        pgbadger -I -l "/out-dir/data/LAST_PARSED" -H "/out-dir/reports" /out-dir/data/2020/02/19/*.bin

    Esto requiere establecer la ruta a la información del último análisis, la
    ruta donde se escribirán los informes HTML y el archivo de datos binarios
    del día.

También hay nuevas opciones de línea de comandos:

  * Añadir la nueva opción de línea de comandos --explain-url, que se usa para sobrescribir la url
    de la herramienta de explain gráfico. La URL predeterminada es:

        http://explain.depesz.com/?is_public=0&is_anon=0&plan=

    Si quieres usar una instalación local de PgExplain u otra herramienta.
    pgBadger añadirá el plan en formato de texto escapado al final de
    la URL.

  * Añadir la nueva opción --no-week para indicar a pgbadger que no construya informes
    semanales en modo incremental. Útil si lleva demasiado tiempo y
    recursos.

  * Añadir la nueva opción de línea de comandos --command para poder establecer un comando
    que pgBadger ejecutará para recuperar entradas de registro por stdin.
    pgBadger abrirá una tubería hacia el comando y analizará las entradas de registro
    generadas por el comando. Por ejemplo:

      pgbadger -f stderr --command 'cat /var/log/postgresql.log'

    que es lo mismo que ejecutar pgbadger con el archivo de registro directamente
    como argumento. El interés de esta opción es obvio si tienes que
    modificar el archivo de registro al vuelo o si las entradas de registro se extraen
    de un programa o se generan desde una base de datos. Por ejemplo:

      pgbadger -f csv --command 'psql dbname -c "COPY jrn_log TO STDOUT (FORMAT CSV)"'

  * Añadir la nueva opción de línea de comandos --noexplain para impedir que pgBadger
    analice y reporte los planes de explain escritos en el registro por la extensión
    auto_explain. Esto es útil si tienes una versión de PostgreSQL < 9.0
    en la que pgBadger genera informes rotos cuando hay un plan de explain
    en el registro.

Compatibilidad con versiones anteriores:

  - Por defecto pgBadger truncará las consultas hasta 100000 caracteres.
    Este valor arbitrario se puede ajustar con la opción --maxlength.
    El comportamiento anterior era no truncar las consultas, pero esto podía
    llevar a un uso excesivo de recursos. Limitar el tamaño por defecto es más seguro
    y el límite de tamaño podría permitir no truncar en la mayoría de los casos. Sin embargo,
    las consultas no se embellecerán si superan los 25000 caracteres.

## v11.0 · 2019-06-25 {#v11-0}

Esta versión de pgBadger añade algunas funciones nuevas importantes y corrige algunos
problemas reportados por los usuarios durante los últimos cuatro meses. Funcionalidades nuevas:

  - Reagrupar las consultas relacionadas con cursores (DECLARE,CLOSE,FETCH,MOVE) en el nuevo
    tipo de consulta CURSOR.
  - Añadir las consultas de enlace top que generan más archivos temporales.
    Requiere que log_connections y log_disconnections estén activados.
  - Añadir la opción de línea de comandos --exclude-client para poder excluir las entradas
    de registro de la ip del cliente especificada. Se puede usar varias veces.
  - Permitir usar solo la hora en los filtros --begin y --end.
  - Añadir la opción -H, --html-dir para poder establecer una ruta diferente donde
    deba escribirse el informe HTML en modo incremental. Los archivos binarios permanecen
    en el directorio definido con la opción -O, --outdir.
  - Añadir la opción -E | --explode para dividir el informe principal en un
    informe por base de datos. La información global no relacionada con una base de datos
    se añade al informe de la base de datos postgres.
  - Añadir el informe por base de datos al modo incremental. En este modo habrá
    un subdirectorio por base de datos con informes incrementales
    dedicados.
  - Añadir compatibilidad con el formato logplex de PostgreSQL de Heroku. El registro se puede
    analizar con:

      heroku logs -p postgres | pgbadger -f logplex -o heroku.html -

  - Cuando una consulta supera los 10Kb, primero se limita el tamaño de todos los parámetros de cadena
    constantes a 30 caracteres y luego la consulta se trunca a 10Kb.
    Esto evita que pgbadger pierda tiempo o se cuelgue con consultas muy largas
    al insertar bytea, por ejemplo. El límite de 10Kb se puede controlar
    con el parámetro de línea de comandos --maxlength.
    La consulta se normaliza o se trunca al valor de maxlength solo después de
    este primer intento de limitar el tamaño.

Esta nueva versión rompe la compatibilidad con los archivos binarios o JSON
antiguos. Esto también significa que el modo incremental no podrá leer los
archivos binarios antiguos. Si quieres actualizar pgBadger y conservar tus informes antiguos,
asegúrate de actualizar al inicio de una semana nueva; de lo contrario, el informe semanal quedará
roto. pgBadger imprimirá una advertencia y simplemente omitirá el archivo binario
antiguo.
