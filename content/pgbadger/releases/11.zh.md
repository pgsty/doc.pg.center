## v11.2 · 2020-03-11 {#v11-2}

本版本修复了过去六个月用户报告的问题，并增加以下功能：

  * 支持并自动识别 AWS Redshift 日志格式。
  * 支持 PgBouncer 1.11 的新日志格式。
  * 支持 zstd 与 lz4 压缩格式。
  * 增量模式下可完全分离统计数据生成与 HTML 报告生成，生成报告时无需重新读取日志。例如，可以每小时运行：

        pgbadger -I -O "/out-dir/data" --noreport /var/log/postgresql*.log

    这只在 `/out-dir/data` 创建二进制数据文件。随后可每晚在独立目录 `/out-dir/reports` 生成当天的报告，供次日查看：

        pgbadger -I -l "/out-dir/data/LAST_PARSED" -H "/out-dir/reports" /out-dir/data/2020/02/19/*.bin

    需要指定最后解析状态的路径、HTML 输出目录，以及当天的二进制数据文件。

新增命令行选项：

  * 添加 `--explain-url`，覆盖图形化执行计划工具的 URL。当时的默认 URL 为：

        http://explain.depesz.com/?is_public=0&is_anon=0&plan=

    可用于本地安装的 PgExplain 或其他工具。pgBadger 将转义后的文本格式执行计划追加到 URL 末尾。

  * 添加 `--no-week`，增量模式下不生成周报，适合周报消耗过多时间和资源的情况。

  * 添加 `--command`，指定获取日志记录的命令。pgBadger 打开通向该命令的管道，并解析其输出的日志，例如：

      pgbadger -f stderr --command 'cat /var/log/postgresql.log'

    这与直接将日志文件作为参数传入等效。需要实时改写日志、从程序提取日志或从数据库生成日志时，此选项尤为有用。例如：

      pgbadger -f csv --command 'psql dbname -c "COPY jrn_log TO STDOUT (FORMAT CSV)"'

  * 添加 `--noexplain`，不解析或报告 auto_explain 扩展写入日志的执行计划。在 PostgreSQL < 9.0 中，日志包含执行计划时 pgBadger 会生成损坏的报告，此选项可避免该问题。

向后兼容性：

  - 默认将查询截断至 100000 字符；可通过 `--maxlength` 调整这个人为设定的值。此前默认不截断，可能造成过量资源消耗。限定默认长度更安全，且多数查询不会触及此限制。不过，超过 25000 字符的查询不会进行格式化。

## v11.0 · 2019-06-25 {#v11-0}

本版本加入重要新功能，并修复了过去四个月用户报告的问题。新增功能：

  - 将游标相关查询（DECLARE、CLOSE、FETCH、MOVE）归入新查询类型 CURSOR。
  - 添加生成最多临时文件的 bind 查询报告；需要启用连接与断开连接日志。
  - 添加 `--exclude-client`，排除指定客户端 IP 的日志记录，可多次指定。
  - 允许 `--begin` 与 `--end` 只使用时间。
  - 添加 `-H, --html-dir`，在增量模式下指定独立的 HTML 输出路径；二进制文件仍保存在 `-O, --outdir` 指定的目录。
  - 添加 `-E | --explode`，将主报告拆分为每个数据库一份；与数据库无关的全局信息放入 postgres 数据库报告。
  - 增量模式支持按数据库报告，每个数据库有独立子目录与增量报告。
  - 支持 Heroku PostgreSQL 的 logplex 格式，可这样解析：

      heroku logs -p postgres | pgbadger -f logplex -o heroku.html -

  - 查询超过 10Kb 时，先将所有常量字符串参数限制为 30 字符，再将查询截断为 10Kb，避免插入 bytea 等超长查询造成耗时过多或挂起。10Kb 限制可通过 `--maxlength` 控制；先尝试缩短参数，再归一化查询或按 maxlength 截断。

此版本与旧二进制或 JSON 文件不兼容，增量模式也无法读取旧二进制文件。若升级后仍需保留历史报告，请在新的一周开始时升级，否则周报会损坏。pgBadger 将打印警告并跳过旧二进制文件。
