## v10.3 · 2019-02-14 {#v10-3}

Dieses Wartungsrelease von pgBadger behebt einige Probleme bei der automatischen Erkennung des Logformats sowie ein weiteres, von Benutzern gemeldetes Problem beim Parsen von PgBouncer-Logs. Es enthält außerdem eine neue Funktion:

    Die Option -o | --outfile kann nun mehrfach verwendet werden, um
    Ausgaben mit einem einzigen Befehl in mehreren Formaten zu erzeugen. Beispiel:
        pgbadger -o out.html -o out.json /log/pgsql-11.log
    Dadurch entstehen zwei Berichte im HTML- und JSON-Format, die in den
    beiden entsprechenden Dateien gespeichert werden.

Darüber hinaus enthält das Release Fehlerkorrekturen und Funktionsverbesserungen.

  - Korrigiert Statistikberichte bei Verwendung eines Filters nach Datenbank, Benutzer, Client oder Anwendung; einige Abfragen fehlten in den Berichten.
  - Korrigiert die automatische Erkennung des standardmäßigen Logzeilenpräfixes für pg>=10.
  - Korrigiert die automatische Erkennung von Logdateien mit einem „nicht standardmäßigen“ Logzeilenpräfix. Wenn --prefix %t, %m, %n und %p oder %c angibt, wird stderr als Format verwendet. Dank an Alex Danvy für die Meldung.
  - Entfernt ein überflüssiges Leerzeichen am Zeilenende.
  - Fügt einen Minimaltest für den Syslog-Parser hinzu.
  - Korrigiert einen Aufruf von autodetect_format().
  - Kürzt Anweisungen bei Verwendung von maxlength. Dank an Thibaud Madelaine für den Patch.
  - Fügt einen Test für mehrere Ausgabeformate hinzu.
  - Die Option -o | --outfile kann nun mehrfach verwendet werden, um mit einem einzigen Befehl Ausgaben in mehreren Formaten zu erzeugen. Beispiel:
      pgbadger -o out.txt -o out.html -o - -x json /log/pgsql-11.log
    pgBadger erstellt dabei zwei Berichte im Text- und HTML-Format und speichert sie in den beiden entsprechenden Dateien. Zusätzlich gibt es einen JSON-Bericht auf der Standardausgabe aus. Dank an Nikolay für den Funktionswunsch.
  - Verschiebt die Erkennung des Ausgabeformats und die Festlegung des Ausgabedateinamens in die eigene Funktion set_output_extension().
  - Behebt ein weiteres Problem beim Parsen von PgBouncer-Logs. Dank an Douglas J. Hunley für die Meldung.

## v10.2 · 2018-12-27 {#v10-2}

Dieses Wartungsrelease von pgBadger behebt Probleme, die Benutzer in den vergangenen drei Monaten gemeldet haben. Es enthält außerdem einige neue Funktionen:

  * Unterstützt das Stats-Logformat von PgBouncer 1.8.
  * Passt die Zeitzone von JavaScript-Diagrammen automatisch an.

Hinzu kommen neue Befehlszeilenoptionen:

  * Fügt die Option --exclude-db hinzu, um einen Bericht über alles außer der angegebenen Datenbank zu erstellen.
  * Unterstützt das Herunterladen entfernter PostgreSQL-Logdateien über HTTP oder FTP. Die Logdatei wird während des Downloads mit dem Befehl curl geparst und nie auf der Festplatte gespeichert. Bei der entfernten Logauswertung über SSH lässt sich die PostgreSQL-Logdatei über eine URI als Befehlszeilenargument angeben.

            ssh://localhost/postgresql-10-main.log
            http://localhost/postgresql-10-main.log.gz
            ftp://localhost/postgresql-10-main.log
    
    Bei den Protokollen HTTP und FTP muss das Logdateiformat am Ende
    der URI angegeben werden:
    
            http://localhost/postgresql-10-main.log:stderr
    
    Für die zu parsenden Logdateien können mehrere URIs angegeben werden.
    Das ist praktisch, wenn sich eine PgBouncer-Logdatei auf einem entfernten
    Rechner und die PostgreSQL-Logs auf dem lokalen Rechner befinden.

    Beim Protokoll SSH lassen sich wie im Remote-Modus ebenfalls Platzhalter
    verwenden, beispielsweise: ssh://localhost/postgresql-10-main.log*
    
    Die alte Syntax zum Parsen entfernter Logdateien mit der Option -r
    funktioniert weiterhin, ist jedoch veraltet und könnte in künftigen Versionen entfallen.


Darüber hinaus enthält das Release Fehlerkorrekturen und Funktionsverbesserungen.

  - Passt das Ende der Fortschrittsanzeige bei Dateien mit geschätzter Größe an (bz2-komprimierte und komprimierte Dateien auf entfernten Rechnern).

  - Stellt sicher, dass die Fortschrittsanzeige nach dem Parsen einer komprimierten Datei auf einem entfernten Rechner 100% erreicht.
  - Extrahiert Informationen zu PL/pgSQL-Funktionsaufrufen aus Abfragen in Berichten zu temporären Dateien und ergänzt sie im Detailanzeigeblock.
  - Korrigiert die Fortschrittsanzeige für CSV-Dateien.
  - Korrigiert die Verarbeitung einer Binärdatei als Eingabedatei statt als Logdatei.
  - Kodiert die HTML-Ausgabe von Abfragen als UTF8, um die Meldung „Wide character in print“ zu vermeiden. Dank an Colin 't Hart für die Meldung.
  - Fügt das Schlüssel-Wert-Paar „Checkpoints distance“ für die Abstandsspitze hinzu.
  - Korrigiert das PgBouncer-Parsing und die Berichte zum Anfragedurchsatz. Dank an Levente Birta für die Meldung.
  - Korrigiert die Verwendung von csvlog statt csv als Eingabeformat.
  - Unterstützt das Stats-Logformat von PgBouncer 1.8. Dank an Levente Birta für die Meldung.
  - Fügt eine Warnung hinzu, dass die parallele Verarbeitung mit csvlog deaktiviert ist. Dank an cstdenis für die Meldung.
  - Ergänzt die Ausgabe der Nutzungshinweise um Informationen zum erzwungenen Einzelprozessbetrieb mit dem Format csvlog und den Optionen -j und -J. Dank an cstdenis für die Meldung.

## v10.0 · 2018-09-09 {#v10-0}

Dieses Major-Release von pgBadger führt neue Funktionen ein und behebt alle seit dem vorherigen Release von Benutzern gemeldeten Probleme.

  * Unterstützt das Syslog-Logdateiformat von PgBouncer.
  * Unterstützt alle auto_explain-Formate (text, xml, json und yaml).
  * Unterstützt den Platzhalter %q in log_line_prefix.
  * Unterstützt das jsonlog-Format der Erweiterung von Michael Paquier; mit -f jsonlog kann pgBadger das Log parsen.
  * Ersetzt den SQL-Codeformatierer durch v3.0 von pgFormatter.

Hinzu kommen neue Befehlszeilenoptionen:

  - Fügt die Befehlszeilenoption --prettify-json hinzu, um die JSON-Ausgabe leserfreundlich zu formatieren.
  - Fügt die Befehlszeilenoption --log-timezone  +/-XX hinzu. Sie gibt an, um wie viele Stunden die verwendete Zeitzone von GMT abweicht, damit Datum/Uhrzeit aus der Logdatei vor dem Parsen entsprechend angepasst werden. Wenn der Client eine andere Zeitzone verwendet, muss die Zeitzone der Diagramme möglicherweise weiterhin mit -Z angepasst werden.
  - Fügt die Option --include-time hinzu. Damit lassen sich die gewünschten Zeiträume auswählen, anstatt alle unerwünschten Zeiträume auszuschließen (--exclude-time).

Das pgBadger-Projekt und die Urheberrechte wurden von Dalibo auf den Autor und offiziellen Maintainer des Projekts übertragen. Bitte aktualisieren Sie Ihre Links:
