## v11.8 · 2022-04-08 {#v11-8}

Этот выпуск pgBadger исправляет проблемы, о которых пользователи сообщили
за предыдущие три месяца, и в особенности две ошибки обнаружения новых
записей журнала в инкрементальном режиме.

  * Исправлено обнаружение новых записей журнала по отметке времени, когда
    в log_line_prefix использовались миллисекунды (%m) или эпоха (%n).
  * Исправлено обнаружение новых записей в локальном файле без использования
    многопроцессной обработки.

Полный список изменений и благодарностей:

  - Полностью пересмотрено и упрощено обнаружение изменений файла журнала.
  - Сообщения "could not (receive|send) data (from|to) client" включены в отчёты
    Events. Спасибо Adrien Nayrat за сообщение.
  - Исправлена ошибка разбора, когда имя подготовленного запроса содержит
    символ ':'. Спасибо aleszeleny за сообщение.
  - Исправлено обнаружение новых записей журнала по отметке времени с
    миллисекундами (%m) или эпохой (%n). Спасибо aleszeleny за сообщение.
  - Исправлено обнаружение новых записей в локальном файле без многопроцессной
    обработки. Спасибо aleszeleny за сообщение.
  - Исправлено обнаружение новых записей в удалённых файлах по SSH. Спасибо
    Luca Ferrari за сообщение.
  - Устранён мусор в имени пользователя в отчёте "Connections per user".
    Спасибо caseyandgina за сообщение.
  - Исправлена команда SSH при использовании URI: ранее параметры SSH
    отсутствовали. Спасибо Luca Ferrari за сообщение.
  - Добавлена обработка заполнителя queryid %Q. Спасибо Adrien Nayrat за патч.
  - Исправлена опечатка в сообщении об ошибке. Спасибо Luca Ferrari за патч.
  - Сообщение "server process was terminated by signal" включено в отчёт
    Events. Спасибо Avi Vallarapu за сообщение.
  - В документации исправлено имя файла в команде еженедельного инкрементального
    отчёта. Спасибо Theophile Helleboid за патч.
  - В t/04_advanced.t исправлен тест syslog. Спасибо Christoph Berg за патч.

## v11.7 · 2022-01-23 {#v11-7}

Этот выпуск pgBadger исправляет проблемы, о которых пользователи сообщили
за предыдущие пять месяцев, и содержит ряд улучшений:

* Добавлен параметр --no-progressbar, скрывающий индикатор выполнения, но
  сохраняющий остальной вывод.
* Добавлен параметр --day-report для пересборки HTML-отчёта за указанный день.
  Он аналогичен --month-report, но работает только для одного дня. Требуются
  каталоги инкрементального вывода и все необходимые файлы двоичных данных.
  Значение — дата в формате YYYY-MM-DD.
* Улучшен разбор журналов Heroku logplex и cloudsql json.

Полный список изменений и благодарностей:

- Обновлены руководство для участников и Makefile.PL, что улучшает
  согласованность, ясность и зависимости. Спасибо diffuse за патч.
- Исправлено использование файла последнего разбора (--last-parsed) в двоичном
  режиме. Спасибо wibrt за сообщение.
- Добавлен регрессионный тест использования --last-parsed и исправлен тест
  отчёта только о временных файлах.
- Исправлен заголовок диаграммы сеансов по узлам. Спасибо Norbert Bede за сообщение.
- Исправлен номер недели при расчёте еженедельных отчётов с включёнными

  остальной вывод. Спасибо seidlmic за запрос функции.
- Ограничен чрезмерный вывод строк неизвестного формата в режиме отладки для
  многострочного jsonlog.
- Исправлен разбор однострочного журнала cloudsql json. Спасибо Thomas Leclaire
  за сообщение.
- Исправлена сводка временных файлов при одном лишь log_temp_files.
- Отладочное сообщение с -v теперь выводится даже при -q или --quiet.

- Исправлена нормализация идентификатора объекта: в некоторых случаях числа

- Исправлены неформатированные нормализованные запросы с комментарием в начале.
- Исправлена многострочность формата stderr при использовании --dbname.

## v11.6 · 2021-09-04 {#v11-6}

Этот выпуск pgBadger исправляет проблемы, о которых пользователи сообщили
за предыдущие семь месяцев, и содержит ряд улучшений:

  * Добавлено распознавание нового в PG14 Query Id из log_line_prefix. Спасибо
    Florent Jardin за сообщение.
  * Добавлены расширенные регрессионные тесты с исключением БД и функцией
    explode. Спасибо MigOps Inc за патч.
  * При использовании --explode создание отчётов выполняется несколькими
    процессами. Спасибо MigOps Inc за патч и Thomas Leclaire за запрос функции.
  * В инкрементальный режим добавлен --iso-week-number: календарные недели
    начинаются с понедельника и соответствуют нумерации ISO 8601 от 01 до 53,
    где неделя 1 — первая неделя, содержащая не менее 4 дней нового года.
    Спасибо Alex Muntada за запрос функции.
  * Добавлен параметр командной строки --keep-comments, сохраняющий комментарии
    в нормализованных запросах. Он полезен для различения одинаковых
    нормализованных запросов. Спасибо Stefan Corneliu Petrea за запрос функции.
  * Пропускаются строки INFO, добавленные в журнал PostgreSQL сторонним ПО.
    Спасибо David Piscitelli за сообщение.
  * Добавлена совместимость с журналом PostgresPro, где после длительности
    оператора указаны число строк и размер в байтах. Спасибо panatamann за сообщение.
  * Разбирается время с T, что позволяет использовать отметки времени journalctl.
    Спасибо Graham Christensen за патч.
  * Улучшен порт для Windows. Спасибо Bertrand Bourgier за патчи.

Важное примечание:

  * Ожидается, что в следующем основном выпуске --iso-week-number станет
    режимом по умолчанию, а --start-monday будет удалён, поскольку неделя всегда
    будет начинаться с понедельника. Ради упрощения кода будет удалена
    возможность начинать еженедельные отчёты с воскресенья.

## v11.5 · 2021-02-18 {#v11-5}

Этот выпуск pgBadger исправляет проблемы, о которых пользователи сообщили
за предыдущие три месяца, и содержит ряд улучшений:

  * Добавлен отчёт о времени простоя сеансов, рассчитанном по формуле:
        "(total sessions time - total queries time) / number of sessions"
    Для достоверного значения должны быть включены log_connections и
    log_disconnections, а log_min_duration_statement = 0, чтобы журналировались
    все запросы. Это помогает оценить потерянное время простоя и понять,
    полезен ли режим транзакций в пулере. Отчёт находится на вкладке "Sessions"
    раздела "Global Stats" и на вкладке "Sessions" почасовых отчётов
    "General Activity".
  * Добавлена анонимизация числовых значений с заменой на 4 случайные цифры.
  * Обновлён форматировщик SQL на базе pgFormatter 5.0.

Полный список изменений и благодарностей:

  - Исправлен разбор многострочного оператора cloudsql. Спасибо Jon Young за сообщение.
  - Добавлен регрессионный тест анонимизации.
  - Исправлена анонимизация, нарушенная усечением maxlength. Спасибо artl за сообщение.
  - Добавлена анонимизация параметров в отчётах о затратных prepare и bind.
    Спасибо arlt за сообщение.
  - Добавлена поддержка микросекунд в префиксе строки журнала logplex. Спасибо
    Ross Gardiner за сообщение.
  - Добавлен отчёт о времени простоя сеансов. Спасибо Guillaume Lelarge за запрос функции.
  - Завершён патч поддержки многострочности в формате jsonlog.

## v11.4 · 2020-11-24 {#v11-4}

за предыдущие четыре месяца, улучшает поддержку сведений журнала PostgreSQL 13
и добавляет новые возможности:

  * В отчёт "Vacuums per table" добавлены полные сведения autovacuum:

    оставшиеся кортежи, ещё не удаляемые кортежи и оставшиеся страницы. Эти
    сведения доступны только на вкладке "Table".
  * Добавлен новый отчёт о распределении причин запуска контрольных точек.
  * Добавлено определение имени приложения из трассировок разрешённого соединения.

Полный список изменений и благодарностей:

  - Исправлена опечатка в сообщении об ошибке. Спасибо Vidar Tyldum за патч.
  - Исправлена ошибка порта Windows "can not load incompatible binary data".
    Спасибо Eric Brawner за сообщение.
  - Исправлена опечатка в параметре --html-outdir в справке и документации
    pgbadger. Спасибо Vidar Tyldum за патч.
  - Исправлено автоматическое распознавание формата jsonlog/cloudsql. Спасибо
    Jon Young за сообщение.

    и Kaarel Moppel за патч.

    временных файлов. Спасибо Sebastien Lardiere за сообщение.
  - В режиме отладки добавлена запись версии pgbadger.

## v11.3 · 2020-07-26 {#v11-3}

Этот выпуск pgBadger исправляет несколько проблем, о которых пользователи
сообщили за предыдущие четыре месяца. Он также добавляет новые возможности
и параметры командной строки:

  * Добавлено автоматическое распознавание отметки времени UTC, чтобы не
    применять часовой пояс к диаграммам.
  * Добавлена поддержка формата журнала GCP CloudSQL json.
  * Добавлен параметр --dump-all-queries: pgBadger выводит все запросы в
    текстовый файл без создания отчёта — только полный список операторов,
    найденных в журнале PostgreSQL. Параметры привязки вставляются в запросы
    на соответствующие позиции.
  * Добавлен параметр -Q | --query-numbering для нумерации запросов в выводе
    при использовании --dump-all-queries или --normalized-only.
  * Добавлен параметр командной строки --tempdir для выбора каталога временных
    файлов. Он полезен в системах, где запись в /tmp запрещена.
  * Добавлен параметр командной строки --ssh-port для задания порта SSH,
    отличного от 22. В записи URI порт SSH указывается в форме:
        ssh://192.168.1.100:2222//var/log/postgresql-11.log

Полный список изменений и благодарностей:

  - Исправлены инкрементальные отчёты для формата журнала jsonlog/cloudsql.
    Спасибо Ryan DeShone за сообщение.
  - Добавлено автоматическое распознавание отметки времени UTC, чтобы не
    применять к диаграммам автоматически определённый часовой пояс. Для времени
    UTC JavaScript применит локальный часовой пояс. Спасибо Brett Stauner за сообщение.
  - Исправлен инкрементальный разбор журналов journalctl, который не работал со
    второго запуска. Спасибо Paweł Koziol за патч.
  - Исправлен путь к файлу ресурсов при использовании -X и -E. Спасибо Ryan
    DeShone за сообщение.
  - Исправлен отчёт General Activity о запросах чтения/записи. Спасибо
    alexandre-sk5 за сообщение.
  - Добавлено отладочное сообщение, когда параллельный режим не используется.
  - Исправлена логика elsif при определении размера файла и лишний пробел,
    добавлявшийся в команду journalctl с параметром --since. Спасибо Pawel
    Koziol за патч.
  - Исправлена ошибка "not a valid file descriptor". Спасибо Pawel Koziol за сообщение.
  - Исправлен инкрементальный режим с файлами RDS. Спасибо Ildefonso Camargo,

  - Добавлен параметр -Q | --query-numbering для нумерации запросов в выводе с

        pgbadger -I -l "/out-dir/data/LAST_PARSED" -H "/out-dir/reports" /out-dir/data/2020/02/19/*.bin

    Для этого нужно указать путь к сведениям о последнем разборе, путь для
    записи HTML-отчётов и файл двоичных данных за день.

Также добавлены новые параметры командной строки:

  * Добавлен параметр командной строки --explain-url для переопределения URL
    графического инструмента explain. URL по умолчанию:

    инструмент. pgBadger добавит экранированный план в текстовом формате в
    конец URL.

  * Добавлен параметр --no-week, запрещающий pgbadger строить еженедельные
    отчёты в инкрементальном режиме. Он полезен, если это занимает слишком
    много времени и ресурсов.

  * Добавлен параметр командной строки --command для задания команды, которую
    pgBadger выполнит, чтобы получить записи журнала через стандартный ввод.
    pgBadger откроет канал к команде и разберёт созданные ею записи журнала.

    Это равнозначно запуску pgbadger с непосредственной передачей файла журнала
