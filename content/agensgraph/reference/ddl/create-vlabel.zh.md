创建顶点标签，即一张继承图基础顶点标签的 `(id, properties)` 表；可选地把属性提升为类型列。

## Synopsis {#synopsis}

```text
CREATE [ UNLOGGED ] VLABEL [ IF NOT EXISTS ] label_name [ ( promoted_property [, ... ] ) ]    [ DISABLE INDEX ]    [ INHERITS ( parent_label [, ... ] ) ]    [ WITH ( storage_parameter [= value] [, ... ] ) ]    [ TABLESPACE tablespace_name ]CREATE [ UNLOGGED ] VLABEL ONLY label_name ( label_id ) [ option ... ]where promoted_property is one of:    column_name data_type GENERATED    column_name data_type GENERATED ( property_key )    column_name data_type GENERATED ALWAYS AS ( expression ) [ STORED ]
```

**记法**：大写为关键字，小写为占位符，`[ ]` 表示可选，`...` 表示可重复。参见[语法约定](/zh/agensgraph/reference/syntax/)。

## Description {#description}

顶点标签是一张表，包含 `graphid` 类型的 `id` 和 `jsonb` 类型的 `properties` 列。除非指定父标签，它继承图的 `ag_vertex`。创建标签还会创建为其编号的序列以及 `id` 上的主键。[图如何存储](/zh/agensgraph/concepts/graph-on-postgresql/)完整介绍该布局。

标签创建在 `graph_path` 指定的图中。

- **选项位置敏感。** 必须按所示顺序出现：先 `DISABLE INDEX`，再 `INHERITS`，再 `WITH`，最后 `TABLESPACE`。其他顺序都是语法错误。
- `INHERITS` 中指定的父标签必须在同一个图中，并且必须是顶点标签。
- `IF NOT EXISTS` 与 `ONLY` 属于不同形式，不能组合。
- Cypher 会按需创建标签：在没有 `film` 标签的图上执行 `CREATE (:film)` 会创建它。需要选项、提升列或父标签时使用 `CREATE VLABEL`。

### 提升属性 {#promoted-properties}

提升属性是位于 `properties` 包旁边的真实类型列，由该包计算并存储。读取这个属性时会访问列，而不是遍历 JSON 文档。三种形式的取值来源不同：

- `column_name data_type GENERATED` 镜像键名与列名相同的属性。
- `column_name data_type GENERATED ( property_key )` 镜像指定键，因此列可以使用其他名称。键是标识符，会按 Cypher 存储映射键的方式转为小写。
- `column_name data_type GENERATED ALWAYS AS ( expression ) STORED` 用基于标签自身列的 SQL 表达式计算该列。

列是否能响应某个属性取决于表达式，而不是书写时使用的形式。对包中单个键的普通读取，例如带或不带转换的 `properties ->> 'year'`，会记录在 `ag_label_property` 中。Cypher 属性读取查询的就是这个目录。如果把读取包在任何其他表达式中，该列就是普通生成列：SQL 能读取它，而 `n.<key>` 看不到它。[把属性提升为列](/zh/agensgraph/querying/typed-columns/)说明了何时值得提升。

提升属性不能是以下四种情况：

- **非生成列。** 裸 `column_name data_type` 会以 `a non-generated promoted column is not supported yet` 被拒绝。
- **`VIRTUAL`。** 提升列必须物化才能承载索引，因此 `VIRTUAL` 会以 `promoted generated properties must be STORED` 被拒绝。`STORED` 是默认值，可以省略。
- **`GENERATED BY DEFAULT`。** 只接受 `GENERATED ALWAYS`。
- **名为 `id`、`properties`、`start` 或 `end`。** 这些是图元素的结构列，名称会作为保留名被拒绝。

数据类型的文本输入函数必须是 immutable 的，且不能固定长度。`date`、`timestamp`、`timestamptz` 和数组类型会以 `generation expression is not immutable` 被拒绝。`varchar(n)` 和 `char(n)` 被拒绝，因为把值适配到固定长度可能让列和属性持有不同的值。接受 `smallint`、`int`、`bigint`、`numeric`、`real`、`double precision`、`text`、`boolean`、`uuid` 和 `jsonb`。

## Parameters {#parameters}

UNLOGGED
: 将标签表创建为 unlogged 表：其内容不写入预写日志，崩溃后会丢失。

IF NOT EXISTS
: 同名标签已存在时发出通知而不是错误。不会创建任何内容；既有标签的选项也不会改变。

label_name
: 要创建的标签名，位于 `graph_path` 指定的图中。

promoted_property
: 按上述三种形式之一，把属性镜像为类型列。列按书写顺序添加在 `properties` 之后。

DISABLE INDEX
: 创建标签的索引但保持无效，使加载行时不必维护它们。读写仍然可用；规划器会忽略无效索引。用 [`REINDEX VLABEL`](/zh/agensgraph/reference/ddl/reindex/) 重建。没有 `ENABLE INDEX`。

INHERITS ( parent_label [, ...] )
: 父标签，替换默认父标签 `ag_vertex`。每个父标签都必须是同一个图中的顶点标签。参见[标签继承](/zh/agensgraph/concepts/label-inheritance/)。

WITH ( storage_parameter [= value] [, ...] )
: 标签表的存储参数，与 `CREATE TABLE` 相同。

TABLESPACE tablespace_name
: 标签表的表空间。省略时由 `default_tablespace` 决定。

ONLY label_name ( label_id )
: 以给定标签 ID 创建标签，不创建默认父标签、ID 默认值或主键。标签 ID 是该标签发出的每个 `graphid` 的高 16 位。`pg_dump` 输出的就是这个形式，以便恢复时保留转储图中的 ID。在补回这些对象之前，这样创建的标签不能从 Cypher 使用，因此仅在复现转储时使用。

## Examples {#examples}

这些示例创建自己的图 `filmstore`，不使用[示例数据集](/zh/agensgraph/get-started/example-dataset/)，并在最后删除它。

### 创建顶点标签 {#create-a-vertex-label}

```cypher
CREATE GRAPH filmstore;
SET graph_path = filmstore;
CREATE VLABEL film;
```

```
CREATE VLABEL
```

```psql
\d filmstore.film
```

```
                                                          Table "filmstore.film"
   Column   |  Type   | Collation | Nullable |                                           Default                                           
------------+---------+-----------+----------+---------------------------------------------------------------------------------------------
 id         | graphid |           | not null | graphid(graph_labid('filmstore.film'::cstring), nextval('filmstore.film_id_seq'::regclass))
 properties | jsonb   |           | not null | jsonb_build_object()
Indexes:
    "film_pkey" PRIMARY KEY, btree (id)
Inherits: filmstore.ag_vertex
```

### 仅在标签不存在时创建 {#create-a-label-only-if-it-is-not-there}

```cypher
CREATE VLABEL IF NOT EXISTS film;
```

```
NOTICE:  label "film" already exists, skipping
CREATE VLABEL
```

### 在父标签下创建标签 {#create-a-label-under-a-parent}

```cypher
CREATE VLABEL work;
CREATE VLABEL documentary INHERITS (work);
```

```psql
\dGv filmstore.documentary
```

```
              List of labels
   Graph   |    Name     |  Type  | Owner
-----------+-------------+--------+-------

(1 row)

--

```

`documentary` 继承 `work` 而不是 `ag_vertex`，因此 `MATCH (n:work)` 也匹配纪录片。[标签继承](/zh/agensgraph/concepts/label-inheritance/)介绍其余内容。

### 先加载标签再构建索引 {#load-a-label-before-building-its-indexes}

```cypher
CREATE VLABEL bulk DISABLE INDEX;
```


### 将两个属性提升为类型列 {#promote-two-properties-to-typed-columns}

```cypher
CREATE VLABEL title (year int GENERATED, name text GENERATED);
```

```psql
\d filmstore.title
```

```
                                                           Table "filmstore.title"
   Column   |  Type   | Collation | Nullable |                                            Default                                            
------------+---------+-----------+----------+-----------------------------------------------------------------------------------------------
 id         | graphid |           | not null | graphid(graph_labid('filmstore.title'::cstring), nextval('filmstore.title_id_seq'::regclass))
 properties | jsonb   |           | not null | jsonb_build_object()
 year       | integer |           |          | generated always as (ag_property_text(properties, 'year'::text, 'n'::"char")::integer) stored
 name       | text    |           |          | generated always as (ag_property_text(properties, 'name'::text, 's'::"char")) stored
Indexes:
    "title_pkey" PRIMARY KEY, btree (id)
Inherits: filmstore.ag_vertex
```

写入方式不变。属性仍进入包，列随之生成：

```cypher
CREATE (:title {name: 'Arrival', year: 2016});
MATCH (t:title) RETURN t.name AS name, t.year AS year;
```

```
  name   | year 
---------+------
 Arrival | 2016
(1 row)
```

相同值也在列中，SQL 可以访问：

```sql
SELECT name, year FROM filmstore.title;
```

```
  name   | year 
---------+------
 Arrival | 2016
(1 row)
```

值与列类型不匹配的属性会在写入时被拒绝，并指出双方：

```cypher
CREATE (:title {name: 42, year: 2016});
```

```
ERROR:  property "name" holds a number
DETAIL:  A column promoting this property holds strings.
CONTEXT:  while computing the promoted typed columns of graph label "title"
```

### 提升键名不同于列名的属性 {#promote-a-property-whose-key-differs-from-the-column-name}

```cypher
CREATE VLABEL review (released text GENERATED (releaseDate));
```

```psql
\d filmstore.review
```

```
                                                           Table "filmstore.review"
   Column   |  Type   | Collation | Nullable |                                             Default                                             
------------+---------+-----------+----------+-------------------------------------------------------------------------------------------------
 id         | graphid |           | not null | graphid(graph_labid('filmstore.review'::cstring), nextval('filmstore.review_id_seq'::regclass))
 properties | jsonb   |           | not null | jsonb_build_object()
 released   | text    |           |          | generated always as (ag_property_text(properties, 'releasedate'::text, 's'::"char")) stored
Indexes:
    "review_pkey" PRIMARY KEY, btree (id)
Inherits: filmstore.ag_vertex
```

键写作 `releaseDate`，但存储为 `releasedate`，因为属性键在这里是标识符，而标识符会转为小写。Cypher 以 `n.releasedate` 读取该属性；SQL 以 `released` 读取列。

### 从属性包计算列 {#compute-a-column-from-the-property-bag}

长形式接受基于标签自身列的 SQL 表达式，而不是属性键：

```cypher
CREATE VLABEL slug (handle text GENERATED ALWAYS AS (lower(properties ->> 'name')) STORED);
```

```psql
\d filmstore.slug
```

```
                                                          Table "filmstore.slug"
   Column   |  Type   | Collation | Nullable |                                           Default                                           
------------+---------+-----------+----------+---------------------------------------------------------------------------------------------
 id         | graphid |           | not null | graphid(graph_labid('filmstore.slug'::cstring), nextval('filmstore.slug_id_seq'::regclass))
 properties | jsonb   |           | not null | jsonb_build_object()
 handle     | text    |           |          | generated always as (lower(properties ->> 'name'::text)) stored
Indexes:
    "slug_pkey" PRIMARY KEY, btree (id)
Inherits: filmstore.ag_vertex
```

```cypher
CREATE (:slug {name: 'Arrival'});
```

```
UPDATE 1
```

无论写入是什么，Cypher 写入都用 `UPDATE` 标签报告行数；该列会被计算并存储：

```sql
SELECT handle FROM filmstore.slug;
```

```
 handle  
---------
 arrival
(1 row)
```

但它不响应任何属性键，因此 Cypher 看不到它：

```cypher
MATCH (s:slug) RETURN s.handle AS handle;
```

```
 handle 
--------
 
(1 row)
```

`s.handle` 读取包中的 `handle` 键，而这个键从未写入。

如果长形式的表达式*就是*对单个键的普通读取，它会像简写形式一样记录，Cypher 也能看到：

```cypher
CREATE VLABEL runtime (minutes int GENERATED ALWAYS AS ((properties ->> 'minutes')::int) STORED);
CREATE (:runtime {minutes: 116});
MATCH (r:runtime) RETURN r.minutes AS minutes;
```

```
 minutes 
---------
     116
(1 row)
```

因此，当列应响应该属性时，直接读取该键；当列只供 SQL 使用时，再基于它计算。

### 值得识别的拒绝情况 {#refusals-worth-recognizing}

以下每种都会直接被拒绝：

```cypher
CREATE VLABEL bad1 (name varchar(40) GENERATED);
```

```
ERROR:  a promoted property cannot have a length-limited string type
DETAIL:  Type character varying fits a value to its length by truncating or padding it.
HINT:  Use text, which stores the property as it is.
```

```cypher
CREATE VLABEL bad2 (name text);
```

```
ERROR:  a non-generated promoted column is not supported yet
HINT:  Use GENERATED to mirror the property from the jsonb bag.
```

```cypher
CREATE VLABEL bad3 (released date GENERATED);
```

```
ERROR:  generation expression is not immutable
```

```cypher
CREATE VLABEL bad4 (id int GENERATED);
```

```
ERROR:  promoted property name "id" is reserved
```

```cypher
CREATE VLABEL bad5 (name text GENERATED ALWAYS AS (properties ->> 'name') VIRTUAL);
```

```
ERROR:  promoted generated properties must be STORED
LINE 1: ...e text GENERATED ALWAYS AS (properties ->> 'name') VIRTUAL);
                                                              ^
HINT:  A VIRTUAL generated column cannot carry an index.
```

一个属性键在整条继承链中只能指向一个列。因此，除非列名相同，父标签已提升的键再次提升会被拒绝：

```cypher
CREATE VLABEL feature (year int GENERATED) INHERITS (work);
CREATE VLABEL short (released int GENERATED (year)) INHERITS (feature);
```

```
ERROR:  property "year" is already promoted on graph label "feature"
DETAIL:  It answers from column "year" there and would answer from column "released" here.
HINT:  Promote it to the same column name, or leave it to the label that has it.
```

镜像情况也会被拒绝：把不同键提升到祖先已使用的列名，会让两个键读取同一个继承列。

### 用给定标签 ID 重建标签 {#recreate-a-label-with-a-given-label-id}

标签 ID 按创建顺序来自图的 `ag_label_seq`。`ONLY` 显式设置一个 ID，恢复就是这样复现转储捕获的 ID：

```cypher
CREATE VLABEL ONLY restored (300);
```

```sql
SELECT l.labname, l.labid FROM pg_catalog.ag_label l
  JOIN pg_catalog.ag_graph g ON g.oid = l.graphid
 WHERE g.graphname = 'filmstore' ORDER BY l.labid;
```

```
   labname   | labid 
-------------+-------
 ag_vertex   |     1
 ag_edge     |     2
 film        |     3
 work        |     4
 documentary |     5
 bulk        |     6
 staging     |     7
 title       |     8
 review      |     9
 slug        |    10
 runtime     |    11
 feature     |    12
 restored    |   300
(13 rows)
```

该标签没有父标签、没有 `id` 默认值，也没有主键。因此它当前不能从 Cypher 使用：

```psql
\d filmstore.restored
```

```
              Table "filmstore.restored"
   Column   |  Type   | Collation | Nullable | Default 
------------+---------+-----------+----------+---------
 id         | graphid |           | not null | 
 properties | jsonb   |           | not null | 
```

复用图已发出的 ID 会在 `(graphid, labid)` 的唯一索引上失败。

最后删除示例创建的图：

```cypher
DROP GRAPH filmstore CASCADE;
```

## Notes {#notes}

标签名不能带限定名。`CREATE VLABEL filmstore.film` 是语法错误，图始终来自 `graph_path`。未设置时，语句以 `graph_path is NULL` 停止。

`\dGv` 列出顶点标签并描述每个匹配项；`\dGl` 列出两种标签但不给详情。

> [!NOTE]
> `enable_property_promotion` 决定 Cypher 属性读取是否从提升列响应。它默认开启；关闭它可能改变结果和计划：列用自身类型的规则比较和排序值，而 `jsonb` 包使用 `jsonb` 排序。

## Compatibility {#compatibility}

### ISO/IEC 39075 (GQL) {#isoiec-39075-gql}

GQL 没有标签 DDL。它的模式机制是*图类型*，即 `<create graph type statement>`（§12.6）。图类型一次性声明整张图的节点类型和边类型，并约束引用它的图。AgensGraph 逐个声明标签，且图是开放图：标签不限制其顶点可以携带哪些属性。图类型在 [GQL 一致性矩阵](/zh/agensgraph/appendix/gql-conformance/)中记录为规划项。

### PostgreSQL {#postgresql}

`CREATE VLABEL` 对应 `CREATE TABLE`。`UNLOGGED`、`IF NOT EXISTS`、`INHERITS`、`WITH` 和 `TABLESPACE` 的含义与 PostgreSQL 相同，提升属性形式是 `GENERATED ALWAYS AS ... STORED` 生成列。`CREATE TABLE` 没有其余部分：不可选择的固定列清单、在 `ag_label` 和 `ag_label_property` 中的注册、自动父标签，以及位置敏感的选项顺序。反过来说，除非开启 `enable_graph_ddl`，标签表不能用 `ALTER TABLE` 重塑。参见[`ALTER VLABEL` 与 `ALTER ELABEL`](/zh/agensgraph/reference/ddl/alter-label/)。
