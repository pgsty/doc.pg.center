这一版 AgensGraph 带来重要增强和缺陷修复，包括兼容 PostgreSQL 17.10、改进 Cypher 查询支持，以及更新构建基础设施。

## 上游变化 {#upstream-changes}

* **上游合并：** AgensGraph 现在兼容到 17.10 版的 [PostgreSQL 17](https://www.postgresql.org/docs/release/17.0/)，纳入了最新的 PostgreSQL 改进和安全补丁。
* **增量备份：** `pg_basebackup` 现在可以创建增量备份，之后与 `pg_combinebackup` 合并，从而减少例行基础备份的大小和时间。
* **`MERGE` 增强：** `MERGE` 现在支持 `RETURNING` 子句（配合 `merge_action()` 函数）和 `WHEN NOT MATCHED BY SOURCE` 动作。
* **SQL/JSON `JSON_TABLE`：** 新增 `JSON_TABLE()`，以及符合标准的 SQL/JSON 查询函数 `JSON_EXISTS()`、`JSON_QUERY()` 和 `JSON_VALUE()`。
* **VACUUM 内存与性能：** 新的存储死元组 ID 的内部数据结构大幅降低 VACUUM 内存使用，并改善大表性能。
* **查询性能：** 大量规划器和执行器改进，包括更好的 `IS [NOT] NULL` 处理，以及顺序扫描的流式 I/O。

## 增强 {#enhancements}

* **优化 DELETE / DETACH DELETE 性能——最高约快 30 倍（#781）：**
  * 删除顶点不再逐个顺序扫描每个边标签；在内部测试中，高度连接顶点的删除约快 **30 倍**。
* **新的 `enable_graph_dml` 配置参数（#786）：**
  * 新增 `enable_graph_dml` GUC，允许直接对图对象（底层顶点表和边表）执行 SQL DML 语句（`INSERT` / `UPDATE` / `DELETE`）。它默认为 `off`，且仅超级用户可设置，因为对图存储发出原始 SQL DML 可能破坏图数据。
* **图属性上的 pgvector 与表达式属性索引（#804）：**
  * `CREATE PROPERTY INDEX` 现在可以在图属性的 `::vector(n)` 转换上构建并使用 pgvector HNSW 索引，也可以在 `to_tsvector(...)` 上构建 GIN 索引。这是 Cypher 内向量、全文和混合搜索的基础（见新的向量 / 全文 / 混合搜索指南）。

## 缺陷修复 {#bug-fixes}

* **列表推导中不能使用图实体（#788）**
  * 图实体以及作用于它们的函数——例如 `nodes()`、`relationships()`、`startNode()`、`type()` 和 `label()`——现在可以在列表推导中使用，例如 `[n IN nodes(p) | n]` 或 `[r IN relationships(p) WHERE type(r) = 'knows']`。此前它们返回错误结果，因为图对象被收集进未类型化的 JSONB 数组；现在会收集进正确类型的数组。
* **`IN` 运算符中的 `CypherList is expected` 错误（#789）**
  * 修复当 `IN` 运算符右侧是表达式生成的列表时出现的虚假 `CypherList is expected` 错误，例如 `x IN split(s, ',')` 或 `x IN ['1', '2']`。
* **`SET +=` 运算符遇到 NULL 时断言失败（#791）**
  * 在 `SET +=`（映射合并）运算符中使用 `NULL` 不再触发断言失败；NULL 情况现在通过 `COALESCE` 回退安全处理。
* **`ORDER BY` 不能引用 `RETURN` 之外的变量（#805）**
  * Cypher `RETURN` 后按未投影列排序，例如 `MATCH (p:person) RETURN p.name ORDER BY p.age`，现在可以工作，而不是失败。
