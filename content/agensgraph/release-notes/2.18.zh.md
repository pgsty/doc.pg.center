## 2.18.6.1 {#21861}

2.18.6.1 不改变查询、目录或存储行为。它和 2.18.6.0 一样基于 PostgreSQL 18.6，并按原样启动 2.18.6.0 的数据目录。

* `agens --help` 和 `ag_ctl --help` 现在把错误报告发送到 <inquiry@skaiworldwide.com>，并把 <https://skaiworldwide.com/> 列为主页。2.18.6.0 列出的是公司不再持有的 `bitnine.net`。

## 2.18.6.0 {#21860}

2.18.6.0 把 AgensGraph 移到 PostgreSQL 18，并加入 ISO/IEC 39075（GQL）标准的相当一部分。它还带来类型化列属性提升，让高频 `jsonb` 属性可以变成真实的可索引列，而不改变查询写法。

若干变化会破坏在 2.17 上工作的应用。升级前先阅读下文[迁移到 2.18](#migrating-to-218)，并按[升级到 2.18](/zh/agensgraph/release-notes/upgrade-to-2.18/)的流程执行——2.17 数据目录不能由 2.18 二进制启动。

## 概览 {#overview}

* **PostgreSQL 18 基础。** 2.17 基于 PostgreSQL 17.10；2.18.6.0 基于 18.6，因此 PostgreSQL 18 的所有新能力随之而来。
* **GQL。** 新语句 `LET`、`NEXT`、`FILTER`、`FINISH`、`INSERT` 和 `FOR`；`CALL { }` 子查询与 `CALL … YIELD`；`OPTIONAL CALL`；子查询值表达式 `EXISTS { }`、`COUNT { }`、`COLLECT { }`、`ARRAY { }`、`VALUE { }` 和 `x IN { }`；独立 `ORDER BY`、`SKIP`、`OFFSET` 与 `LIMIT`；`XOR` 运算符；以及 `CURRENT_GRAPH` / `CURRENT_PROPERTY_GRAPH`。参见 [GQL 一致性](/zh/agensgraph/appendix/gql-conformance/)。
* **类型化列属性提升。** `ALTER VLABEL movie ADD COLUMN year int GENERATED` 为属性提供一个声明类型的真实可索引列，Cypher 属性读取会解析到它，查询无需修改。参见[把属性提升为列](/zh/agensgraph/querying/typed-columns/)。
* **图元素进入原生数组。** 对顶点、边或路径执行 `collect()` 现在构造 `vertex[]`、`edge[]` 或 `graphpath[]`，而不是 jsonb 快照，收集到的元素保持可用。
* **遍历规划工作**，包括由 `ag_graphmeta` 驱动的扫描裁剪、省略未使用的模式端点，以及更好的可变长度边估算。
* **修复十五类崩溃**，其中若干只需读权限即可触达。

## 新特性 {#new-features}

### GQL 语句 {#gql-statements}

| 语句 | 作用 |
| --- | --- |
| [`LET`](/zh/agensgraph/reference/clauses/let/) | 向当前行添加计算值，不丢弃作用域中的任何内容。 |
| [`NEXT`](/zh/agensgraph/reference/clauses/next/) | 把一个查询链接到另一个查询的结果上。 |
| [`FILTER`](/zh/agensgraph/reference/clauses/filter/) | 过滤行；有 `FILTER` 和 `FILTER WHERE` 两种形式。 |
| [`FINISH`](/zh/agensgraph/reference/clauses/finish/) | 结束一个不投影任何结果的查询。 |
| [`INSERT`](/zh/agensgraph/reference/clauses/insert/) | 创建元素；是 `CREATE` 的 GQL 写法。 |
| [`FOR`](/zh/agensgraph/reference/clauses/for/) | 迭代列表，`WITH OFFSET` 提供索引。 |
| [`CALL { }`](/zh/agensgraph/reference/clauses/call-subquery/) | 子查询，带显式变量导入列表。 |
| [`CALL … YIELD`](/zh/agensgraph/reference/clauses/call-yield/) | 调用函数并命名输出列。 |
| [`OPTIONAL CALL`](/zh/agensgraph/reference/clauses/optional-call/) | 与 `CALL` 相同，但调用没有产出时仍产生一行。 |
| [子查询表达式](/zh/agensgraph/reference/clauses/subquery-expressions/) | 子查询上的 `EXISTS { }` 与 `VALUE { }`。`COUNT { }`、`COLLECT { }`、`ARRAY { }` 和 `x IN { }` 完成同样工作，但它们是 AgensGraph 扩展，不属于 GQL。 |

独立 `ORDER BY`、`SKIP`、`OFFSET` 和 `LIMIT` 成为自己的子句，不再只是 `RETURN` 与 `WITH` 的一部分，因此可以放在管道的任意位置。它们不能结束查询：语句仍必须以 `RETURN`、`FINISH` 或写入子句结束。

其他新增包括：`XOR` 运算符、`NULLIF`、`IS [NOT] UNKNOWN`、`RETURN ALL` / `WITH ALL`、`exists(property)`、`size(value)`、`cardinality()`、`toInteger()`、`toFloat()`，以及 Cypher 内的 SQL 值函数。

类型转换现在可以命名关键字类型：`::int`、`::numeric`、`::varchar`、`::bit`、`::interval`、`::boolean`、`::date`、`::timestamptz` 等。此前其中若干完全没有可用写法。`::timestamp` 和 `::time` 在 Cypher 中仍不可写；请把表达式包在 SQL 中处理。

### 类型化列属性提升 {#typed-column-property-promotion}

属性保存在每个元素自己的 `jsonb` 文档中。这意味着读取要遍历 JSON 文档，也不能按值本身的类型使用索引。提升为一个属性生成一个声明类型的已存储生成列：

```cypher
ALTER VLABEL movie ADD COLUMN year int GENERATED;
CREATE PROPERTY INDEX ON movie (year);
```

查询不变——`MATCH (m:movie) WHERE m.year > 2010` 现在把 `m.year` 解析到列并可以使用索引。提升也可以在创建时进行，列还可以从不同名称的属性取值：

```cypher
CREATE VLABEL doc (words int GENERATED (word_count), score numeric GENERATED);
```

列承载括号中命名的属性，因此解析到 `words` 的读取是 `d.word_count`——属性键，不是列名。

扩展类型也适用，而这是检索场景的关键：安装 `pgvector` 后，`CREATE VLABEL doc (emb vector(1024) GENERATED)` 会为 embedding 提供真实可索引列，而不是每次读取都从 `jsonb` 数组转换。

提升后的键不再无模式：值不符合列类型的写入会中止。[把属性提升为列](/zh/agensgraph/querying/typed-columns/)覆盖了这些取舍。

### 其他新增 {#other-additions}

* `ALTER VLABEL … ADD COLUMN` / `DROP COLUMN`。
* 新目录 `ag_label_property` 记录哪一列承载哪个属性；新列 `ag_graph.graphmeta_valid` 控制扫描裁剪。参见[系统目录](/zh/agensgraph/system-catalogs/catalogs/)。
* 三个新设置：`enable_graph_ddl`、`enable_property_promotion` 和 `enable_graph_endpoint_elision`。参见[服务器设置](/zh/agensgraph/reference/guc/)。
* `log_statement = mod` 现在记录 Cypher 写入。此前，要求记录数据修改语句的服务端一条也不记录——旁边的 SQL `INSERT` 被记录，Cypher `CREATE` 却没有。

## 迁移到 2.18 {#migrating-to-218}

这些是最容易破坏现有工作的变化。[升级到 2.18](/zh/agensgraph/release-notes/upgrade-to-2.18/)有完整清单和流程。

### 新保留字 {#new-reserved-words}

`xor`、`current_graph` 和 `current_property_graph` 现在是保留字。使用这些名称的标识符、标签、变量或别名需要引用；这里的引用是**双引号**，Cypher 与 SQL 相同——`MATCH (n:"xor")`。反引号不是这里的引用字符，`` `xor` `` 是语法错误。

`insert`、`finish` 和 `let` 也是保留字，但两个在 2.16 和 2.17 上可用的用法被有意恢复：`insert` 作为变量，以及 `insert` 或 `finish` 作为*模式中*的标签。创建这样的标签仍需引用——`CREATE VLABEL insert;` 是语法错误，`CREATE VLABEL "insert";` 可以工作，随后未引用的模式写法能找到它。在每个位置都必须引用的是：`let` 或 `finish` 作为*变量*名、`let` 作为标签，以及按名为 `let` 或 `finish` 的别名排序。

[关键字](/zh/agensgraph/appendix/keywords/)给出哪个词在哪个位置失败的完整矩阵。

`CALL` 保持未保留，因此 `call` 仍可用作列、表、别名、标签、属性键和变量。只有两种写法改变含义并需要引用：`call(...)`——调用一个字面名为 `call` 的函数——以及 `(call { ... })`，一个变量名为 `call`、带属性映射且没有标签的点模式。

参见[关键字](/zh/agensgraph/appendix/keywords/)。

### 条件只接受布尔值 {#a-condition-takes-only-a-boolean}

`WHERE n.count` 和 `FILTER n.name` 过去会按非零或非空读取属性并选择行。现在它们抛出转换错误：

```
ERROR:  cannot cast "Jack" (jsonb type string) to boolean
```

这适用于 `WHERE`、`FILTER`、`AND`、`OR`、`NOT`、`XOR`、`CASE WHEN` 和 `dijkstra()` 的限定条件。显式 `::boolean` 仍可转换；真正的布尔值、jsonb null 和缺失键不受影响。这个变化是刻意的：ISO/IEC 39075 把搜索条件定义为布尔值表达式。

### 变化的结果类型 {#changed-result-types}

* **对顶点、边或路径执行 `collect()`** 返回 `vertex[]`、`edge[]` 或 `graphpath[]`，而不是 jsonb 快照数组。现在可以读取收集元素的属性；过去它会静默返回空。对*属性*执行 `collect` 仍返回 jsonb 列表，存储数据保持形状。
* **对顶点或边执行 `min()` 和 `max()` 现在是错误**：

  ```
  ERROR:  function min(vertex) is not unique
  ```

  PostgreSQL 18 新增 `min(record)` 和 `max(record)`，它们通过隐式 `vertex → jsonb` 转换与 `min(jsonb)`/`max(jsonb)` 竞争。请显式转换——`min(v::jsonb)`——或聚合身份 `min(id(v))`。
* **`range()`** 返回 jsonb 数组，而不是整数数组。
* **`toStringList`、`toIntegerList` 和 `toFloatList`** 被重写。每个现在有两种重载：在 SQL 中作用于真实数组时返回 `text[]`、`bigint[]` 和 `double precision[]`；作用于 Cypher 列表（`jsonb`）时返回 `jsonb`。旧版本会产生多个静默错误答案：bigint 丢失高位，非数字字符串转换为 0，单元素列表返回空，超过 64 字符的元素越过固定缓冲区。

### 变化的结果集 {#changed-result-sets}

**`WITH … WHERE` 与 `SKIP` 或 `LIMIT` 现在在过滤之后分页。** 过去分页先发生，因此 `WITH x WHERE x > 1 ORDER BY x LIMIT 2` 可能返回一行。现在顺序是 `WHERE`、`ORDER BY`、`SKIP`/`LIMIT`。这会改变结果集。

**`RETURN <expr> AS d ORDER BY d` 按值排序，不按 jsonb 形式排序。** 除非有限浮点数外，行和排序不变；非有限浮点数过去混在字符串之间。收益是索引可以服务排序。

**写入子句的修改对同一条语句中的后续读取可见。** `MATCH (p) SET p.age = 99 WITH p MATCH (q) RETURN q.age` 过去返回写入前的值；`CREATE (:Q) WITH 1 MATCH (x:Q) RETURN count(x)` 返回 0，同时静默丢弃创建。

**`ALL`、`ANY`、`NONE` 和 `SINGLE` 遵循三值逻辑。** `any([null] WHERE p)` 现在是 null，不是 false。空列表保持其空虚结果。

### 更严格的校验 {#stricter-validation}

这些操作过去会成功，而且多数情况下给出错误答案：

* `ALTER TABLE` 不再重塑图标签——添加或删除列、修改继承、重命名标签列都不允许。标签 DDL 完成同样工作，`enable_graph_ddl` 可以解除限制。即便如此，修改 `id`、`start`、`end` 或 `properties` 的类型仍被拒绝。
* 对标签执行 SQL `MERGE` 现在需要 `enable_graph_dml`，与 `INSERT`、`UPDATE` 和 `DELETE` 一致。
* **行级安全现在真正作用于图写入。** `UPDATE` 或 `DELETE` 策略的 `USING` 子句过去挂在一个永远不会被扫描的范围表项上，因此什么都没有过滤——完全没有 `DELETE` 策略的角色也能删除行。`INSERT` 策略检查的是错误的行，边创建从未检查，因此启用行安全的边标签接受每次插入。如果依赖图上的 RLS，请在 2.18 重新测试：过去能通过的写入现在会被拒绝。
* `WITH` 不得携带同一名称两次；`ORDER BY` 键不得包含易变计算；模式变量不得命名已在作用域中的列；图写入不得用标量替换属性映射；`CALL` 子查询不得返回已在外部绑定的名称。

### 诊断 {#diagnostics}

图元素上的 `count()`、属性读取和可变长度遍历节点的 `EXPLAIN` 输出发生变化；后者现在会命名它走过的边标签。刷新比较计划文本的回归基线。

## 修复 {#fixes}

修复了十五类崩溃。其中若干只需读权限的用户即可触达，并使实例上的每个会话停止：

* `head('{}'::text[])` 在*规划*阶段使服务端崩溃。
* `RETURN cardinality(['a','b'])` 在解析阶段崩溃。
* `MATCH ()-[r:e*1..2 = 5]->()`——可变长度边上的非映射约束。
* `CREATE PROPERTY INDEX ON doc (tags[0])`。
* 列表推导中的聚合。
* 超过 64 字符的列表元素越过固定缓冲区。

另有四个修复，过去给出的是错误答案而不是错误。2.17.0 中顶点排序和边相等性是错的，因此顶点上的 `<`、`<=`、`>`、`>=` 和边上的 `=` 并不表示字面含义。`min(jsonb)` 和 `max(jsonb)` 返回任意元素。`DELETE` 对被删除元素返回空值，并清空绑定到它的其他变量。图元素上的 `x IN <list>` 比较完整序列化，而不是身份。

本版还修复了内部的一个 PostgreSQL 18 回归：属性读取上的 `DISTINCT`、`GROUP BY`、`ORDER BY`、`min()` 和 `max()` 曾因 “could not determine which collation to use” 失败。这样的键现在采用数据库默认排序规则，与 jsonb 自身使用的相同，因此结果不变。

## 本版不包含 {#not-in-this-release}

明确说明如下，因为这些内容曾被询问：

* **`CALL { }` 内的写入子句。** 解析器拒绝在子查询体中使用 `CREATE`、`SET` 及其他写入子句。`CALL { } IN TRANSACTIONS` 不存在。
* **GQL 的会话与模式**——`SESSION_SET`、`USE`——以及类型化图 / 图类型。
* **`CREATE OR REPLACE CONSTRAINT`**——能解析，但随后被拒绝。
* **非存储且非生成的提升列。** 提升列必须是 `GENERATED … STORED`。
