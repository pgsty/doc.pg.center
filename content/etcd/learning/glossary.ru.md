Этот документ определяет различные термины, используемые в документации, командной строке и исходном коде etcd.

## Аварийный сигнал {#alarm}

Сервер etcd подаёт аварийный сигнал, когда для сохранения надёжности кластера требуется вмешательство оператора.

## Аутентификация {#authentication}

Аутентификация управляет правами доступа пользователей к ресурсам etcd.

## Клиент {#client}

Клиент подключается к кластеру etcd и отправляет служебные запросы: получает пары «ключ — значение», записывает данные или наблюдает за обновлениями.

## Кластер {#cluster}

Кластер состоит из нескольких участников.

Узел каждого участника следует протоколу консенсуса Raft для репликации журналов. Кластер получает предложения от участников, фиксирует их и применяет к локальному хранилищу.

## Компактизация {#compaction}

Компактизация удаляет всю историю событий etcd и замещённые ключи до заданной ревизии. Она освобождает место в базе данных бэкенда etcd.

## Выборы {#election}

В рамках протокола консенсуса Raft кластер etcd проводит выборы лидера среди своих участников.

## Конечная точка {#endpoint}

URL, указывающий на службу или ресурс etcd.

## Ключ {#key}

Определяемый пользователем идентификатор для хранения и получения пользовательских значений в etcd.

## Диапазон ключей {#key-range}

Набор ключей, содержащий отдельный ключ, лексический интервал всех x, для которых a <= x < b, либо все ключи больше заданного ключа.

## Пространство ключей {#keyspace}

Множество всех ключей в кластере etcd.

## Аренда {#lease}

Краткосрочный возобновляемый договор, который по истечении срока удаляет связанные с ним ключи.

## Участник {#member}

Логический сервер etcd, участвующий в обслуживании кластера etcd.

## Ревизия изменения {#modification-revision}

Первая ревизия, содержащая последнюю запись заданного ключа.

## Одноранговый узел {#peer}

Одноранговый узел — другой участник того же кластера.

## Предложение {#proposal}

Предложение — это запрос, например на запись или изменение конфигурации, который должен пройти через протокол Raft.

## Кворум {#quorum}

Количество активных участников, необходимое для достижения консенсуса при изменении состояния кластера. Для кворума etcd требуется большинство участников.

## Ревизия {#revision}

Общий для кластера 64-битный счётчик, который начинается с 1 и увеличивается при каждом изменении пространства ключей.

## Роль {#role}

Набор прав для диапазонов ключей, который можно предоставить группе пользователей в целях контроля доступа.

## Снимок {#snapshot}

Резервная копия состояния кластера etcd на определённый момент времени.

## Хранилище {#store}

Физическое хранилище, лежащее в основе пространства ключей кластера.

## Срок полномочий {#term}

Срок полномочий — монотонно возрастающее целое число, связанное с каждыми выборами лидера в алгоритме Raft.
В течение одного срока может быть выбран только один лидер; при смене лидера срок увеличивается.

## Транзакция {#transaction}

Атомарно выполняемый набор операций. Все изменённые в транзакции ключи имеют одну и ту же ревизию изменения.

## Версия ключа {#key-version}

Количество записей ключа с момента его создания, начиная с 1. Версия несуществующего или удалённого ключа равна 0.

## Наблюдатель {#watcher}

Клиент открывает наблюдателя, чтобы отслеживать обновления в заданном диапазоне ключей.
