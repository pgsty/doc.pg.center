يستهلك مكونان من تخزين etcd الذاكرة الفعلية. تخصص عملية etcd *فهرسًا في الذاكرة* لتسريع البحث عن المفاتيح. وتخزن *ذاكرة التخزين المؤقت للصفحات* الخاصة بالعملية، التي يديرها نظام التشغيل، البيانات التي تم الوصول إليها حديثًا من القرص لإعادة استخدامها بسرعة.

يحتفظ الفهرس في الذاكرة بجميع المفاتيح في بنية بيانات [شجرة B][btree]، إلى جانب مؤشرات تشير إلى البيانات الموجودة على القرص (القيم). قد يحتوي كل مفتاح في شجرة B على مؤشرات متعددة تشير إلى إصدارات مختلفة من قيمه. لذلك يمكن تقريب الاستهلاك النظري للذاكرة للفهرس في الذاكرة بالصيغة:

`N * (c1 + avg_key_size) + N * (avg_versions_of_key) * (c2 + size_of_pointer)`

حيث يمثل `c1` الحمل الزائد للبيانات الوصفية للمفتاح ويمثل `c2` الحمل الزائد للبيانات الوصفية للإصدار.

يوضح الرسم البياني البنية التفصيلية لشجرة B الخاصة بالفهرس في الذاكرة.

```


                                In mem index

                               +------------+
                               | key || ... |
  +--------------+             |     ||     |
  |              |             +------------+
  |              |             | v1  || ... |
  |   disk    <----------------|     ||     | Tree Node
  |              |             +------------+
  |              |             | v2  || ... |
  |           <----------------+     ||     |
  |              |             +------------+
  +--------------+       +-----+    |   |   |
                         |     |    |   |   |
                         |     +------------+
                         |
                         |
                         ^
                      ------+
                      | ... |
                      |     |
                      +-----+
                      | ... | Tree Node
                      |     |
                      +-----+
                      | ... |
                      |     |
                      ------+
```

ذاكرة [التخزين المؤقت للصفحات][pagecache] يديرها نظام التشغيل ولا يتم تناولها بالتفصيل في هذا المستند.

## استخدام ذاكرة الفهرس في الذاكرة {#in-memory-index-memory-usage}

في هذا الاختبار، نقيس استخدام الذاكرة للفهرس في الذاكرة فقط. الهدف هو إيجاد `c1` و`c2` المذكورين أعلاه وفهم الحد الأقصى الصارم لاستهلاك الذاكرة في التخزين.

نحسب استهلاك الذاكرة عبر Go runtime.ReadMemStats. نحسب فرق إجمالي البايتات المخصصة قبل إنشاء الفهرس وبعده. لا يمكن لذلك أن يعكس استخدام الذاكرة للفهرس في الذاكرة نفسه بشكل مثالي، لكنه يوضح نمط الاستهلاك التقريبي.

| N    | الإصدارات | حجم المفتاح | استخدام الذاكرة |
|------|----------|----------|--------------|
| 100K | 1        | 64bytes  | 22MB         |
| 100K | 5        | 64bytes  | 39MB         |
| 1M   | 1        | 64bytes  | 218MB        |
| 1M   | 5        | 64bytes  | 432MB        |
| 100K | 1        | 256bytes | 41MB         |
| 100K | 5        | 256bytes | 65MB         |
| 1M   | 1        | 256bytes | 409MB        |
| 1M   | 5        | 256bytes | 506MB        |


بناءً على النتيجة، يمكننا حساب `c1=120bytes` و`c2=30bytes`. نحتاج فقط إلى مجموعتي بيانات لحساب `c1` و`c2`، لأنهما المتغيران المجهولان الوحيدان في الصيغة. إن قيمتي `c1=120bytes` و`c2=30bytes` هما المتوسط لمجموعات `c1` و`c2` الأربع التي حسبناها. لا يزال الحمل الزائد للبيانات الوصفية للمفتاح كبيرًا نسبيًا (50%) لأزواج المفاتيح والقيم الصغيرة. ومع ذلك، فهذا تحسن كبير مقارنة بالمخزن القديم الذي كان لديه حمل زائد لا يقل عن 1000%.

## إجمالي استخدام الذاكرة {#overall-memory-usage}

يوضح إجمالي استخدام الذاكرة مقدار RSS الذي يستهلكه etcd مع التخزين. ينبغي أن يكون لحجم القيمة تأثير ضئيل جدًا على إجمالي استخدام الذاكرة لـ etcd، لأننا نحتفظ بالقيم على القرص ولا نُبقي في الذاكرة إلا القيم الساخنة، التي تديرها ذاكرة التخزين المؤقت للصفحات في نظام التشغيل.

| N    | الإصدارات | حجم المفتاح | حجم القيمة | استخدام الذاكرة |
|------|----------|----------|------------|--------------|
| 100K | 1        | 64bytes  | 256bytes   | 40MB         |
| 100K | 5        | 64bytes  | 256bytes   | 89MB         |
| 1M   | 1        | 64bytes  | 256bytes   | 470MB        |
| 1M   | 5        | 64bytes  | 256bytes   | 880MB        |
| 100K | 1        | 64bytes  | 1KB        | 102MB        |
| 100K | 5        | 64bytes  | 1KB        | 164MB        |
| 1M   | 1        | 64bytes  | 1KB        | 587MB        |
| 1M   | 5        | 64bytes  | 1KB        | 836MB        |

بناءً على النتيجة، نعرف أن حجم القيمة لا يؤثر بشكل كبير في استهلاك الذاكرة. هناك زيادة طفيفة بسبب زيادة البيانات المحتفظ بها في ذاكرة التخزين المؤقت للصفحات في نظام التشغيل.
