## 物理マシン {#physical-machine}

GCEのn1-highcpu-2マシンタイプ

- /var/lib/etcdにマウントした専用ローカルSSD：1台
- OS用の専用低速ディスク：1台
- メモリー：1.8 GB
- CPU：2基

## etcdクラスター {#etcd-cluster}

etcd 2.2.0-rcメンバー3つを、それぞれ別のマシンで実行します。

バージョンの詳細：

```
etcd Version: 2.2.0-alpha.1+git
Git SHA: 59a5a7e
Go Version: go1.4.2
Go OS/Arch: linux/amd64
```

比較の基準となる性能を測るため、alpha段階のetcd 2.1.0メンバー3つでもクラスターを構成します。etcdのコミットは[c7146bd5][c7146bd5]で、[etcd 2.1のベンチマーク][etcd-2.1-benchmark]で使用したものと同じです。

## テスト {#testing}

別のマシンを起動し、[hey HTTPベンチマークツール][hey]を使って各etcdメンバーにリクエストを送信します。詳しい手順は[ベンチマーク開発ガイド][hack-benchmark]を参照してください。

### 性能変化の説明 {#performance-changes-explanation}

- ほとんどのシナリオで、読み取りQPSが5～8%低下しています。これは、etcdがストア操作ごとにストアのメトリクスを記録するためです。メトリクスは監視やデバッグに重要なため、この低下は許容できると考えています。

- リーダーに対する書き込みQPSが20～30%増加しています。raftのメインループとエントリー適用ループを分離し、互いの処理をブロックしないようにしたためです。

- 全サーバーに対する書き込みQPSが30～80%増加しています。フォロワーが最新のコミットインデックスをより早く受信し、提案をより速くコミットできるようになったためです。
