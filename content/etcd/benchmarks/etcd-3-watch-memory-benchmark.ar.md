> [!NOTE]
> ميزات المراقبة (watch) قيد التطوير النشط، وقد يتغير استخدامها للذاكرة مع تقدم هذا التطوير. لا نتوقع أن يتجاوز استخدام الذاكرة الأرقام المذكورة أدناه بشكل كبير.

من الأهداف الرئيسية لـ etcd دعم عدد كبير جدًا من المراقبين (watchers) يقومون بكم هائل من عمليات المراقبة. يستهدف etcd دعم O(10k) عميل، وO(100K) من تدفقات المراقبة (O(10) تدفقات لكل عميل)، وO(10M) من إجمالي عمليات المراقبة (O(100) عملية مراقبة لكل تدفق). تمثل الذاكرة التي تستهلكها كل عملية مراقبة فردية الجزء الأكبر من الاستخدام الكلي لـ etcd، ولذلك فهي محور التحسينات الحالية والمستقبلية.


تستهلك ثلاثة مكونات مرتبطة بمراقبة etcd الذاكرة الفعلية: كل `grpc.Conn`، وكل تدفق مراقبة، وكل مثيل من نشاط المراقبة. يحافظ `grpc.Conn` على اتصال TCP الفعلي وحالات اتصال gRPC الأخرى. يستهلك كل `grpc.Conn` ذاكرة بمقدار O(10kb)، وقد تكون به عدة تدفقات مراقبة مرتبطة.

كل تدفق مراقبة هو اتصال HTTP2 مستقل يستهلك قدرًا إضافيًا من الذاكرة بمقدار O(10kb).
قد تتشارك عدة عمليات مراقبة في تدفق مراقبة واحد.

المراقبة (watching) هي البنية الفعلية التي تتعقب التغييرات على مخزن المفاتيح والقيم. ينبغي أن تستهلك كل عملية مراقبة < O(1kb) فقط.

```
                                          +-------+
                                          | watch |
                              +---------> | foo   |
                              |           +-------+
                       +------+-----+
                       |   stream   |
      +--------------> |            |
      |                +------+-----+     +-------+
      |                       |           | watch |
      |                       +---------> | bar   |
+-----+------+                            +-------+
|            |         +------------+
|   conn     +-------> |   stream   |
|            |         |            |
+-----+------+         +------------+
      |
      |
      |
      |                +------------+
      +--------------> |   stream   |
                       |            |
                       +------------+
```

يمكن تقريب الاستهلاك النظري للذاكرة بواسطة المراقبة بالصيغة التالية:
`memory = c1 * number_of_conn + c2 * avg_number_of_stream_per_conn + c3 * avg_number_of_watch_stream`

## إجمالي استخدام الذاكرة {#overall-memory-usage}

يوضح إجمالي استخدام الذاكرة مقدار [RSS][rss] الذي يستهلكه etcd مع مراقبي العملاء. ومع أن النتيجة قد تختلف بنسبة تصل إلى 10%، فإنها لا تزال ذات دلالة، لأن الهدف هو التعرف على الاستخدام التقريبي للذاكرة ونمط التخصيصات.

باستخدام نتيجة قياس الأداء، يمكننا تقدير أن `c1 = 17kb` و`c2 = 18kb` و`c3 = 350bytes` تقريبًا. وهكذا يستهلك كل اتصال عميل إضافي 17kb من الذاكرة، ويستهلك كل تدفق إضافي 18kb من الذاكرة، بينما لا تستهلك كل عملية مراقبة إضافية سوى 350bytes. يمكن لخادم etcd واحد أن يحافظ على ملايين عمليات المراقبة ببضعة GB من الذاكرة في الحالة الطبيعية.
