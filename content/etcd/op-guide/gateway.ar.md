## ما هي بوابة etcd {#what-is-etcd-gateway}

بوابة etcd هي وسيط TCP بسيط يعيد توجيه بيانات الشبكة إلى عنقود etcd. البوابة عديمة الحالة وشفافة؛ فهي لا تفحص طلبات العملاء ولا تتدخل في استجابات العنقود. وهي لا تنهي اتصالات TLS، ولا تجري مصافحات TLS نيابةً عن عملائها، ولا تتحقق مما إذا كان الاتصال مؤمَّنًا.

تدعم البوابة نقاط نهاية متعددة لخوادم etcd وتعمل وفق سياسة تناوب دوري (round-robin) بسيطة. وهي لا توجّه الطلبات إلا إلى نقاط النهاية المتاحة وتحجب الأعطال عن عملائها. وقد تُدعم سياسات إعادة محاولة أخرى، مثل التناوب الدوري الموزون، مستقبلًا.

## متى تستخدم بوابة etcd {#when-to-use-etcd-gateway}

يجب أن يمتلك كل تطبيق يصل إلى etcd أولًا عنوان نقطة نهاية عميل لعنقود etcd. وإذا كانت تطبيقات متعددة على الخادم نفسه تصل إلى عنقود etcd نفسه، فسيظل كل تطبيق بحاجة إلى معرفة نقاط نهاية العميل المُعلَنة لعنقود etcd. وإذا أُعيد إعداد عنقود etcd ليستخدم نقاط نهاية مختلفة، فقد يحتاج كل تطبيق أيضًا إلى تحديث قائمة نقاط النهاية الخاصة به. وهذا النطاق الواسع من إعادة الإعداد ممل ومعرّض للأخطاء في آن واحد.

تحل بوابة etcd هذه المشكلة عبر العمل كنقطة نهاية محلية مستقرة. في الإعداد النموذجي لبوابة etcd، تعمل على كل آلة بوابة تستمع على عنوان محلي، ويتصل كل تطبيق etcd ببوابته المحلية. والنتيجة أن البوابة وحدها هي التي تحتاج إلى تحديث نقاط نهايتها بدلًا من تحديث كل تطبيق على حدة.

خلاصة القول، ولكي تُنشر تلقائيًا تغييرات نقاط نهاية العنقود، تعمل بوابة etcd على كل آلة تخدم تطبيقات متعددة تصل إلى عنقود etcd نفسه.

## متى لا تستخدم بوابة etcd {#when-not-to-use-etcd-gateway}

- تحسين الأداء

لم تُصمَّم البوابة لتحسين أداء عنقود etcd. فهي لا توفر التخزين المؤقت ولا دمج عمليات المراقبة (watch) ولا التجميع على دفعات. ويعمل فريق etcd حاليًا على تطوير وسيط تخزين مؤقت مصمم لتحسين قابلية توسّع العنقود.

- التشغيل على نظام إدارة عناقيد

تدعم أنظمة إدارة العناقيد المتقدمة مثل Kubernetes اكتشاف الخدمات بصورة أصلية. يمكن للتطبيقات الوصول إلى عنقود etcd باستخدام اسم DNS أو عنوان IP افتراضي يديره النظام. مثلًا، kube-proxy مكافئ لبوابة etcd.

## بدء بوابة etcd {#start-etcd-gateway}

تخيّل عنقود etcd بنقاط النهاية الثابتة التالية:

|الاسم|العنوان|اسم المضيف|المنفذ|
|------|---------|------------------|----|
|infra0|10.0.1.10|infra0.example.com|2379|
|infra1|10.0.1.11|infra1.example.com|2379|
|infra2|10.0.1.12|infra2.example.com|2379|

ابدأ بوابة etcd لتستخدم نقاط النهاية الثابتة هذه بالأمر التالي:

```bash
$ etcd gateway start --endpoints=infra0.example.com:2379,infra1.example.com:2379,infra2.example.com:2379
2016-08-16 11:21:18.867350 I | tcpproxy: ready to proxy client requests to [...]
```

وبدلًا من ذلك، إذا كنت تستخدم DNS لاكتشاف الخدمات، فخذ بعين الاعتبار سجلات DNS SRV التالية:

```bash
$ dig +noall +answer SRV _etcd-client._tcp.example.com
_etcd-client._tcp.example.com. 300 IN SRV 0 0 2379 infra0.example.com.
_etcd-client._tcp.example.com. 300 IN SRV 0 0 2379 infra1.example.com.
_etcd-client._tcp.example.com. 300 IN SRV 0 0 2379 infra2.example.com.
```

```bash
$ dig +noall +answer infra0.example.com infra1.example.com infra2.example.com
infra0.example.com.  300  IN  A  10.0.1.10
infra1.example.com.  300  IN  A  10.0.1.11
infra2.example.com.  300  IN  A  10.0.1.12
```

ابدأ بوابة etcd لجلب نقاط النهاية من سجلات DNS SRV بالأمر التالي:

```bash
$ etcd gateway start --discovery-srv=example.com
2016-08-16 11:21:18.867350 I | tcpproxy: ready to proxy client requests to [...]
```

## أعلام الإعداد {#configuration-flags}

### عنقود etcd {#etcd-cluster}

#### --endpoints {#endpoints}

 * قائمة مفصولة بفواصل لأهداف خوادم etcd التي تُوجَّه إليها اتصالات العملاء.
 * القيمة الافتراضية: `127.0.0.1:2379`
 * يجب تضمين المنفذ.
 * مثال غير صالح: `https://127.0.0.1:2379` (البوابة لا تنهي اتصالات TLS). لاحظ أن البوابة لا تتحقق من مخطط HTTP ولا تفحص الطلبات، بل تكتفي بإعادة توجيه الطلبات إلى نقاط النهاية المعطاة.

#### --discovery-srv {#discovery-srv}

 * نطاق DNS المستخدم لتهيئة نقاط نهاية العنقود مبدئيًا عبر سجلات SRV.
 * الافتراضي: (غير محدد)

### الشبكة {#network}

#### --listen-addr {#listen-addr}

 * الواجهة والمنفذ اللذان يجري الربط عليهما لقبول طلبات العملاء.
 * القيمة الافتراضية: `127.0.0.1:23790`

#### --retry-delay {#retry-delay}

 * مدة التأخير قبل إعادة محاولة الاتصال بنقاط النهاية المتعطلة.
 * الافتراضي: 1m0s
 * مثال غير صالح: "123" (يُتوقع إدخال وحدة زمنية بالتنسيق الصحيح)

### الأمان {#security}

#### --insecure-discovery {#insecure-discovery}

 * قبول سجلات SRV غير المؤمَّنة أو القابلة لهجمات الرجل في المنتصف (man-in-the-middle).
 * القيمة الافتراضية: `false`

#### --trusted-ca-file {#trusted-ca-file}

 * المسار إلى ملف CA الخاص بـ TLS للعميل لعنقود etcd للتحقق من نقاط النهاية التي تعيدها عملية الاكتشاف عبر SRV. لاحظ أنه يُستخدم فقط لمصادقة نقاط النهاية المكتشفة وليس لإنشاء اتصالات لنقل البيانات. ولا تنهي البوابة اتصالات TLS أبدًا ولا تنشئ اتصالات TLS نيابةً عن عملائها.
 * الافتراضي: (غير محدد)
